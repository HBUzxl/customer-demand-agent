# 慧鉴(CodeInsight)离线部署安装使用说明

本文档适用于客户拿到 慧鉴 离线部署包后的安装、升级、停止、重启和卸载操作。

## 1 部署包目录结构

解压交付包后，目录通常类似：
```bash
corax-<版本号>/
install.sh
common.sh
docker-compose.yml
.env
conf/
scripts/
docker/
corax-<版本号>.tar.gz
```


关键文件说明：

| **文件或目录** | **说明** |
| --- | --- |
| install.sh | 安装、升级、停止、重启、卸载的统一入口 |
| docker-compose.yml | 服务编排文件 |
| .env | 服务运行环境变量 |
| conf/ | 持久化配置和数据目录，包含 Redis、MySQL、MinIO 等数据 |
| docker/ | Docker 和 Docker Compose 离线安装二进制 |
| corax-<版本号>.tar.gz | CodeInsight 运行所需 Docker 镜像包 |

## 2 部署前要求

**推荐机器规格：**

| **项目** | **最低要求（只能用于****POC****）** | **推荐要求** |
| --- | --- | --- |
| CPU | 8 核及以上 | 16核及以上 |
| 内存 | 16 GB 及以上 | 32GB及以上 |
| 磁盘 | 安装目录所在磁盘可用空间500 GB SSD以上 | 安装目录所在磁盘可用空间500G SSD以上 |

安装脚本会自动检查机器规格。如果不满足要求，默认会停止安装。确认继续安装时，可使用 “\-f”强制执行。

脚本还会检查 Docker 和 Docker Compose：

•   如果机器已安装并正常运行 Docker / Docker Compose，会直接使用现有环境。

•   如果未安装，脚本会尝试使用部署包 “**docker/**” 目录下的离线二进制自动安装。

•   自动安装 Docker 需要 root 权限。

## 3 端口规则

平台 Web 服务默认使用宿主机“80”端口。

安装时脚本会自动检测：

1. 如果“80”端口可用，使用“80”；

2. 如果“80”被占用，自动切换到“10080”；

3. 如果“80”和“10080”都被占用，脚本会提示手动输入可用端口；

最终端口会写入安装目录下的 “.env”：

```bash
CORAX_HTTP_PORT=<实际端口>
```


## 4 默认安装


```bash
#进入解压后的部署包目录：
cd corax-<版本号>
#执行默认安装：
./install.sh start
#默认安装目录就是当前目录。
#如果机器规格不满足推荐要求，但确认继续安装：
./install.sh start -f
#安装完成后，根据脚本输出的端口访问系统：
http://<服务器IP>:<端口>
```

## 5 安装到指定目录

如果希望把服务安装到指定目录，例如“/data/codeinsight”：

```bash
./install.sh start -d /data/codeinsight
#如果机器规格不满足推荐要求，但确认继续安装：
./install.sh start -d /data/codeinsight -f

```


**说明：**

- 脚本会把部署包中的安装文件复制到指定目录。

- 如果指定目录不存在，脚本会自动创建。

- 如果指定目录非空且不是 CodeInsight 安装目录，脚本会停止，避免覆盖客户已有文件。

- 首次安装成功后控制台会打印密码：

查看首次部署的密码可在con目录下查看**“initial-admin-password.txt”**内容即可。

## 6 停止服务

```bash
#在安装目录执行：
./install.sh stop
#或从任意部署包目录指定安装目录：
./install.sh stop -d /data/codeinsight
```


**说明：**

- 该命令只停止容器。

- 不删除镜像。

- 不删除 “conf/”、“.env”、“docker-compose.yml” 等数据和配置。

## 7 重启服务

```bash
#在安装目录执行：
./install.sh restart
#或指定安装目录：
./install.sh restart -d /data/codeinsight
#如果机器规格不满足推荐要求，但确认继续启动：
./install.sh restart -d /data/codeinsight -f
```

## 8 升级服务

### 8.1   升级流程：

1. 解压新版本部署包。

2. 进入新版本部署包目录。

3. 执行升级命令。

4. 按提示输入旧版本服务运行目录。

5. 脚本停止旧服务。

6. 脚本询问是否备份，默认备份。

7. 脚本迁移旧服务数据到新安装目录。

8. 脚本启动新版本服务。

**示例：**

```bash
cd corax-<新版本号>
./install.sh upgrade -d /data/codeinsight-new -o /data/old-codeinsight
```


如果机器规格不满足推荐要求，但确认继续升级：

```bash
./install.sh upgrade -d /data/codeinsight-new -o /data/old-codeinsight -f
```


脚本会提示：

请输入当前旧服务运行目录:

输入旧版本安装目录，例如：

| /data/codeinsight |
| --- |

**备份说明：**

- 脚本会询问是否备份，默认 `Y`。

- 备份目录位于旧安装目录下的 `backups/backup-<时间戳\>/`。

- 备份内容包括：

  - `conf/`

  - `.env`

  - `docker-compose.yml`

**数据迁移说明：**

- `conf/` 会从旧目录复制到新目录。

- `.env/` 会迁移客户运行配置。

- 新版本镜像相关变量会保留新包中的值，避免升级后仍使用旧镜像。

升级完成后，新的服务运行目录是 `-d` 指定的新目录。

## 9 卸载服务

```bash
#卸载命令：
./install.sh autoremove
#或指定安装目录：
./install.sh autoremove -d /data/codeinsight
```


**卸载会执行：**

- 停止容器。

- 删除 compose 中使用的镜像。

- 删除安装目录。

**重要提示：**

- 该操作会删除安装目录下的 \`conf/\`，包括 Redis、MySQL、MinIO 等持久化数据。

- 脚本会二次确认。

- 默认答案是 \`N\`，直接回车不会卸载。

## 10 常用命令速查

| **场景** | **命令** |
| --- | --- |
| 默认安装 | ./install.sh start |
| 默认安装并强制跳过规格限制 | ./install.sh start -f |
| 安装到指定目录 | ./install.sh start -d /data/codeinsight |
| 指定目录并强制安装 | ./install.sh start -d /data/codeinsight -f |
| 停止服务 | ./install.sh stop -d /data/codeinsight |
| 重启服务 | ./install.sh restart -d /data/codeinsight |
| 升级服务 | ./install.sh upgrade -d /data/codeinsight-new |
| 卸载服务 | ./install.sh autoremove -d /data/codeinsight |
| 查看帮助 | ./install.sh --help |

## 11 故障处理

### 11.1 机器规格不满足要求

报错示例：

机器不满足推荐部署标准。如确认继续安装，请加 -f 强制执行。

确认继续安装时加 `-f`：
```bash
./install.sh start -f
```



### 11.2 80 端口被占用

脚本会自动切换到 `10080`。如果 `10080` 也被占用，按提示输入其他可用端口。

### 11.3 Docker 未安装

脚本会尝试使用部署包中的 `docker/` 离线二进制自动安装。请使用 root 用户或 sudo 执行安装命令。

### 11.4 升级时旧目录不符合要求

旧服务目录必须包含：
```bash
docker-compose.yml .env conf/
```


如果不满足，脚本会提示重新输入。

### 11.5 查看容器状态

```bash
#进入安装目录：
cd /data/codeinsight
#查看状态：
docker compose ps
#如果系统只支持老版本命令：
docker-compose ps
```

# 码力（CodeForce）智能开发与安全一体化平台操作手册

## 一、码力产品介绍

### 1.1 背景介绍

随着 AI 编程、大模型智能体和自动化安全检测技术的发展，企业软件研发正在从“人工主导、工具辅助”逐步走向“人机协同、流程自动化”的新阶段。AI 不再只是提供代码补全，而是开始参与需求理解、代码生成、问题修复、测试辅助和安全审计等研发环节。
但在企业场景中，AI 能力要真正落地，还需要解决项目上下文不足、生成结果不可控、任务过程难追踪、安全风险难治理等问题。码力（CodeForce）正是面向这些需求研发，帮助企业把 AI 研发能力纳入统一管理、安全审计和工程化交付体系中。

### 1.2 产品简介

码力（CodeForce）是一款企业级 AI 代码生成与安全审计平台，面向研发团队、安全团队和平台管理者，提供 AI 辅助编码、AI 任务执行、代码安全扫描、依赖风险分析、项目管理和审计追踪等能力。
平台通过 Web 管理端、IDE 插件、AI Worker 和安全扫描引擎，将 AI 研发提效与代码安全治理结合起来，帮助企业在提升研发效率的同时，保障代码质量、安全合规和过程可控，适用于私有化部署和企业内部研发场景。

## 二、产品初始化

### 2.1 平台登录

平台登录用于管理员或研发成员进入码力平台，后续执行项目管理、智能开发、安全审计、知识集管理等操作。

**操作步骤如下：**

1. 打开平台登录页 > 在登录页选择「管理员」身份页签。

![平台登录步骤1](../assets/step-login-01.png)



2. 输入用户名和密码，然后点击「登录」。

![平台登录步骤2](../assets/step-login-02.png)

3. 成功登录后，可以看到仪表盘首页。

![平台登录步骤3](../assets/step-login-03.png)


**注意事项**

- 登录失败时，请检查账号、密码和当前选择的身份页签是否匹配。

### 2.2 模型配置

模型配置用于接入和维护对话模型、代码补全模型、智能体模型和 Workflow 智能体模型，同时设置默认模型、模型池和模型分组，支撑平台对话、补全、AI 员工、审计和工作流等能力稳定调用。

**操作步骤如下：**

1. 登录系统 > 在左侧菜单展开「通用设置」> 点击「模型管理」，进入模型管理页面。

![模型配置步骤1](../assets/step-model-config-01.png)



2. 查看顶部 Token 使用量统计，并在「模型选择」区域确认对话模型、代码补全模型、Workflow 智能体模型、智能体主模型、备用模型和 AI CLI 执行工具的当前配置。

![模型配置步骤2](../assets/step-model-config-02.png)



3. 向下滚动到「模型列表」区域 > 点击「添加模型」，系统打开添加模型弹窗。

![模型配置步骤3](../assets/step-model-config-03.png)



4. 在添加模型弹窗中选择或填写模型供应商、API 地址、API Key、模型名称、模型备注、协议类型、上下文窗口和最大输出 Token 等信息；保存前可先执行模型检测，演示时不要点击最终保存。

![模型配置步骤4](../assets/step-model-config-04.png)



5. 如需控制成员可见范围，在「模型分组」区域点击「创建模型分组」，填写分组名称并选择已启用模型；进入分组后可点击「添加成员」选择可使用该分组模型的成员。

![模型配置步骤5](../assets/step-model-config-05.png)




**注意事项**

- 添加或编辑模型会影响平台真实调用链路，演示时只打开配置入口和填写示例，不执行最终保存。
- API Key、API 地址和模型供应商账号属于敏感配置，正式截图发布前应确认没有泄露真实密钥。
- 代码补全、对话、智能体和审计任务依赖不同模型场景，默认模型和模型池调整前应确认业务影响。

### 2.3 license导入

License 导入用于维护平台授权文件、查看授权有效期、机器码、增值模块开关和扩展授权配额，确保平台功能在授权范围内可用。

**操作步骤如下：**

1. 登录系统 > 在左侧菜单展开「通用设置」> 点击「系统管理」> 滚动到「License 授权管理」区域。

![License 授权管理步骤1](../assets/step-license-import-01.png)

2. 查看授权有效期、机器码、增值模块配置和扩展授权配置，确认当前授权范围和配额。

![License 授权管理步骤2](../assets/step-license-import-02.png)

3. 如需更新授权，点击「更新 license」打开文件选择入口，按页面提示选择授权文件；演示时不上传真实授权文件。

![License 授权管理步骤3](../assets/step-license-import-03.png)




**注意事项**

- License 文件属于授权凭据，演示时不要上传真实授权文件。
- 机器码和授权文件应妥善保管，避免通过非授权渠道传播。
- 更新 License 会影响平台可用模块和配额，正式操作前应确认授权文件来源与适用环境。

## 三、AI赋能研发

### 3.1 CLI环境研发

CLI 环境研发用于下载和配置 CLI 工具、CLI Skill 和 MCP Server，帮助研发人员在本地命令行中调用平台模型与安全能力。

**操作步骤如下：**

1. 使用管理员账号登录系统 > 点击页面右上角「下载中心」，进入「插件与CLI工具」页面。

![插件与 CLI 工具步骤1](../assets/step-cli-development-01.png)



2. 在「CLI 工具」区域选择「OpenCode」页签，按本机系统选择「Windows」或「macOS 与 Linux」，复制页面提供的一键安装命令；以 Windows 为例，命令格式为在 PowerShell 中请求平台安装脚本后执行。

![插件与 CLI 工具步骤2](../assets/step-cli-development-02.png)

3. 在本地电脑打开 cmd.exe，粘贴并执行页面复制的 OpenCode 安装命令；安装脚本会先下载依赖和 CLI 文件，然后写入 CodeForce 管理的 opencode.cmd 启动脚本。

![插件与 CLI 工具步骤3](../assets/step-cli-development-03.png)

4. 当安装器提示开始认证时，按提示进入浏览器认证流程；该步骤由 codeforce_tool.exe 拉起或输出认证地址，不需要手工编写 OpenCode 配置。

![插件与 CLI 工具步骤4](../assets/step-cli-development-04.png)



5. 由管理员在「用户管理」中邀请或注册研发成员测试用户；CLI 安装认证页的「管理员」身份不可用于该流程，应使用研发成员测试用户完成浏览器认证。

![插件与 CLI 工具步骤5](../assets/step-cli-development-05.png)

6. 执行安装器中的 codeforce_tool.exe 配置流程后，浏览器会打开「登录以完成 CLI 安装」页面；在页面中输入研发成员测试用户的用户名和密码，点击「登录以完成 CLI 安装」。

![插件与 CLI 工具步骤6](../assets/step-cli-development-06.png)



7. 浏览器跳转到本地回调页并提示认证成功后，回到 cmd.exe 等待安装器继续执行。

![插件与 CLI 工具步骤7](../assets/step-cli-development-07.png)

8. codeforce_tool.exe 会把平台默认模型、OpenCode 凭据和模型配置写入本地；终端提示配置已完成或显示已生效模型后，说明默认模型配置已经完成，不需要客户手动在多个模型中选择。

![插件与 CLI 工具步骤8](../assets/step-cli-development-08.png)

9. 继续在本地 cmd.exe 中执行「where opencode」和「opencode --version」做命令验证；确认命令来源和版本号正常后，再交给研发人员使用。

![插件与 CLI 工具步骤9](../assets/step-cli-development-09.png)

10. 向下滚动到「CLI Skill」区域，复制 codeforce-skill 安装命令，按页面提示安装用于本地漏洞扫描、代码安全审计和 MR/PR 审计的 Skill。

![插件与 CLI 工具步骤10](../assets/step-cli-development-10.png)

11. 继续查看「MCP Server」区域，根据目标系统下载资源包或复制 npm 安装命令，安装完成后执行页面提示的验证命令。

![插件与 CLI 工具步骤11](../assets/step-cli-development-11.png)




**注意事项**

- 推荐选择一个代表性 CLI 完整测试安装链路，本手册以 OpenCode 为例；其他 CLI 的安装方式同页签切换后按页面命令执行。
- 管理员账号只用于平台认证、进入下载中心和获取安装命令；手册截图不得展示管理员密码、访问令牌或 API Key。
- 页面中的一键安装命令包含当前平台服务配置，请不要把命令中的服务地址或凭据复制到公开材料中。
- 安装后必须在本地 cmd.exe 中完成浏览器认证、默认模型配置写入和版本检查，不能只检查命令文件是否存在。
- CLI 安装认证属于研发成员授权链路，管理员账号只用于进入下载中心和准备测试用户；不要把管理员账号写成 OpenCode 授权账号。








### 3.2 AI研发工程师

AI 研发工程师是项目级 AI 员工能力，用于在具体项目接入测试仓库或正式仓库后，监听 Issue 创建、Issue 评论中被 @、Merge/Pull Request 评论中被 @ 等研发类事件，并把需求分析、代码修改和交付辅助流程沉淀为可配置的自动化能力。

**操作步骤如下：**

1. 如尚未准备测试数据，先参见「5.2 用户管理」邀请或创建测试用户，并参见「5.5 仓库管理」完成测试仓库接入；本章节不重复展开仓库创建流程。

![AI 研发工程师步骤1](../assets/step-ai-dev-engineer-01.png)

2. 登录系统 > 点击左侧「项目管理」> 在项目卡片中点击「进入项目」，进入项目控制台，并确认项目已绑定测试仓库且测试用户已加入项目成员。

![AI 研发工程师步骤2](../assets/step-ai-dev-engineer-02.png)



3. 在项目控制台切换到「AI 员工」页签，查看项目内 AI 员工列表，确认当前页面是项目级员工管理，而不是左侧全局「AI 员工」菜单下的统计或管理页。

![AI 研发工程师步骤3](../assets/step-ai-dev-engineer-03.png)



4. 点击「新建 AI 员工」> 选择「研发工程师」，填写员工名称，按需选择模型策略，并勾选 Issue 创建、Issue 评论中被 @、Merge/Pull Request 评论中被 @ 等工作触发条件。

![AI 研发工程师步骤4](../assets/step-ai-dev-engineer-04.png)

5. 确认 AI 研发工程师创建在当前项目内，并在员工卡片中查看启用状态、工作状态和 Webhook 同步状态；仓库地址和访问令牌在「5.5 仓库管理」维护，不在本弹窗中重复配置。

![AI 研发工程师步骤5](../assets/step-ai-dev-engineer-05.png)



6. 进入测试仓库的 Gitee Issue 页面，新建或打开需求 Issue，在评论中输入「@AI研发工程师 请在当前仓库创建 hello world 示例」，提交后等待平台机器人回复或生成关联研发任务。

![AI 研发工程师步骤6](../assets/step-ai-dev-engineer-06.png)



7. 在 Gitee 仓库中查看 AI 研发工程师提交的 hello world 文件、工作分支和 Pull Request，确认变更来自测试仓库且只包含本次演示文件。

![AI 研发工程师步骤7](../assets/step-ai-dev-engineer-07.png)



8. 回到项目控制台「AI 智能开发」页签，查看由 Issue 或评论触发生成的研发任务，核对任务名称、触发来源、仓库和分支信息。

![AI 研发工程师步骤8](../assets/step-ai-dev-engineer-08.png)




**注意事项**

- AI 研发工程师与 AI 安全工程师一样属于项目级 AI 员工创建流程，操作和截图均应以项目控制台「AI 员工」页签为准。
- 研发工程师需要至少关联一个测试仓库或正式仓库配置，并至少启用一个工作触发条件。
- 使用测试用户和已接入的测试仓库验证触发流程，避免在生产仓库或真实业务用户上直接试验。
- Gitee/GitLab/GitHub 访问令牌需要具备读取仓库、读取 Issue/MR/PR 和按需评论或创建 Webhook 的权限。
- Issue 创建和 Issue 评论中被 @ 的研发触发流程应归入「三、AI赋能研发」章节；后续 PR/MR 审计和合并流程归入「四、AI赋能安全」章节。

## 四、AI赋能安全

### 4.1 AI安全审计

#### 4.1.1 MR自动审计

MR 自动审计用于在项目接入代码仓库后，通过项目级 AI 安全工程师监听 Git 平台 Webhook 事件。当仓库产生 Merge/Pull Request 创建、更新或评论中被 @ 等事件时，平台会自动触发安全审计任务，并在项目控制台中跟踪审计状态、风险统计和模板使用情况。

**操作步骤如下：**

1. 如项目尚未绑定测试仓库，先参见「5.5 仓库管理」完成仓库接入；如需模拟触发，可在已接入的 Gitee、GitLab 或 GitHub 测试仓库中准备一个 Merge/Pull Request。

![MR 自动审计步骤1](../assets/step-mr-auto-audit-01.png)

2. 登录系统 > 点击左侧「项目管理」> 在项目卡片中点击「进入项目」，进入项目控制台并确认项目已绑定目标测试仓库。

![MR 自动审计步骤2](../assets/step-mr-auto-audit-02.png)



3. 在项目控制台切换到「AI 员工」页签，查看项目内 AI 员工列表，并关注「安全工程师」员工的启用状态、工作状态和 Webhook 同步状态。

![MR 自动审计步骤3](../assets/step-mr-auto-audit-03.png)



4. 点击「新建 AI 员工」或编辑已有「AI安全工程师」，确认员工类型为「安全工程师」，工作触发条件已勾选「Merge/Pull Request 创建」或「Merge/Pull Request 评论中被 @」，并在「审计模板」区域选择模板。

![MR 自动审计步骤4](../assets/step-mr-auto-audit-04.png)



5. 保存安全工程师配置后查看 Webhook 同步结果，确认页面展示 Webhook 地址、Webhook 密钥和同步成功仓库；对外材料中应隐藏地址和密钥的具体值。

![MR 自动审计步骤5](../assets/step-mr-auto-audit-05.png)



6. 在测试仓库中打开由 AI 研发工程师提交的 Pull Request，核对 PR 关联 Issue、源分支、目标分支以及审查和测试状态。

![MR 自动审计步骤6](../assets/step-mr-auto-audit-06.png)

7. 在 Pull Request 评论区输入「@AI安全工程师 请审计本次 hello world 变更」，提交评论；如果已启用 PR 创建触发，也可以直接等待 PR 创建事件自动进入审计流程。

![MR 自动审计步骤7](../assets/step-mr-auto-audit-07.png)



8. 回到项目控制台「AI 智能审计」页签，查看自动生成的审计任务、风险统计、任务状态、审计模板和 PR/MR 链接。

![MR 自动审计步骤8](../assets/step-mr-auto-audit-08.png)



9. 审计和人工确认完成后，回到 Gitee Pull Request 页面，按仓库规则完成审查通过、测试通过和合并操作，确认页面状态显示为已合并。

![MR 自动审计步骤9](../assets/step-mr-auto-audit-09.png)




**注意事项**

- MR 自动审计不通过全局「AI智能审计」页面的「创建任务」按钮发起；该按钮属于手动审计流程。
- 如果 Webhook 自动同步失败，应按页面给出的 Webhook 地址和密钥到代码托管平台手动配置。
- Gitee/GitLab/GitHub Token 或仓库账号需要具备读取代码变更、读取 MR/PR 与评论、创建 Webhook 的权限。
- 只有 Webhook 同步结果提示需要手动绑定时，才进入 Gitee、GitLab 或 GitHub 仓库的 Webhook 管理页面新增配置；若页面显示同步成功仓库，则无需重复创建 Webhook。
- 首次验证建议使用测试用户和测试仓库模拟 MR/PR，不要直接在生产仓库上触发自动审计。
- Webhook 地址和密钥属于敏感配置，正式文档和截图对外发布前应确认没有泄露真实密钥。
- PR/MR 创建和 PR/MR 评论中被 @ 的安全触发流程应归入「四、AI赋能安全」章节，并与 Issue 研发触发流程分开说明。


#### 4.1.2 手动上传审计

手动上传审计用于在未接入 MR 自动触发、需要临时检查指定仓库版本或需要人工发起专项审计时创建 AI 审计任务。若审计对象是本地代码包，先在代码管理中上传 ZIP 形成代码版本，再到 AI 智能审计中选择代码仓库版本创建任务。

**操作步骤如下：**

1. 若审计对象是 Git 仓库，先参见「5.5 仓库管理」完成仓库接入；若审计对象是本地代码包，先进入「AI 员工 > 代码管理」，点击「增加代码仓库」，填写代码仓库名称、版本说明并选择 ZIP 文件。

![手动上传审计步骤1](../assets/step-manual-upload-audit-01.png)



2. 登录系统 > 在左侧菜单展开「智能安全」> 点击「AI智能审计」，切换到「人工手动审计」页签，进入全局人工审计任务列表页面。

![手动上传审计步骤2](../assets/step-manual-upload-audit-02.png)



3. 查看审计统计和任务列表，可通过任务 ID、仓库名、状态、仓库或创建人等条件筛选已有人工审计任务。

![手动上传审计步骤3](../assets/step-manual-upload-audit-03.png)



4. 点击「创建任务」打开人工审计任务创建窗口，选择 AI 原生审计或 AI 增强审计。

![手动上传审计步骤4](../assets/step-manual-upload-audit-04.png)



5. 在任务配置页选择 Git 仓库或代码仓库、目标分支/版本和审计模板；演示时只展示配置页，不点击最终创建。

#### 4.1.3 审计模板创建

审计模板用于定义 AI 审计时关注的规则、缺陷类型、排除范围和结果明细要求，便于在 MR 自动审计、手动上传审计等场景中复用统一审计标准。

**操作步骤如下：**

![审计模板步骤1](../assets/step-audit-template-01.png)

3. 点击「创建模板」打开模板窗口，先填写基础信息：模板名称示例为「高危安全漏洞审计模板」，模板类型选择「安全漏洞」，模板描述填写「面向 MR/PR 变更的高危安全漏洞审计，重点发现凭证泄露、注入、越权、SSRF、反序列化和不安全文件操作」。

![审计模板步骤3](../assets/step-audit-template-03.png)



4. 在「审计规则」中填写可执行的检查要求，示例为「仅审计本次变更引入或暴露的高危或阻断安全问题；重点关注硬编码 Token、Password、AccessKey、SecretKey、Cookie、Authorization、私钥、连接串，SQL/命令/模板/路径注入，危险反序列化，SSRF，任意文件读写，认证、授权、租户隔离和越权访问缺失，不安全加密、弱随机数、敏感日志明文输出；每个问题必须给出 diff 行范围内的触发点、攻击路径、受影响资产和可执行修复建议」。

![审计模板步骤4](../assets/step-audit-template-04.png)

5. 在「排除规则」中填写降噪范围，示例为「排除纯格式调整、注释修改、测试夹具、mock 数据、自动生成文件、构建产物、第三方依赖目录；仅当示例凭据明确位于测试数据且不会进入运行时配置时，可降级不报」。

![审计模板步骤5](../assets/step-audit-template-05.png)

6. 在「Detail」中填写结果明细要求；选择「安全漏洞」类型时可使用系统预设「包含漏洞名称、攻击路径或利用方式、受影响资产、破坏后果；必须包含问题点代码片段，并标注文件路径与行号」。确认「启用」开关打开后，演示时不点击最终保存。

![审计模板步骤6](../assets/step-audit-template-06.png)

7. 模板保存后，可在 MR 自动审计创建 AI 安全工程师或手动上传审计创建任务时选择该模板，用同一套规则审计测试仓库或正式仓库。

![审计模板步骤7](../assets/step-audit-template-07.png)


**注意事项**

- 新建模板的必填项包括模板名称、模板类型、审计规则和 Detail；模板描述、排除规则和启用状态应按团队审计策略补充。
- 模板类型包含软件BUG、安全漏洞、编码规范、合规审计、业务缺陷、基础组件和其他；不同类型会带出不同 Detail 预设。
- Detail 只约束审计结果中的问题明细字段，不等同于修复建议；修复建议仍应在审计规则中明确要求输出。
- 内置模板在管理页面会隐藏完整规则内容，不能按自定义模板一样查看或复制；需要自定义规则时应新建团队模板。
- 启用、禁用、删除模板会影响后续审计策略，演示过程中不执行最终保存。

知识集管理用于维护平台知识集、共享范围、文件数和知识集大小，为对话、智能体和检索增强能力提供知识来源。

**操作步骤如下：**

1. 登录系统 > 点击左侧菜单「知识集管理」，进入知识集列表页面。 知识集管理用于维护平台知识集、共享范围、文件数和知识集大小，为对话、智能体和检索增强能力提供知识来源。

![知识集管理步骤1](../assets/step-knowledge-management-01.png)



2. 使用「知识集名称」和「所有者」筛选知识集，查看知识集名称、共享范围、知识集大小、文件数、创建人、创建时间、更新时间和可用操作。

![知识集管理步骤2](../assets/step-knowledge-management-02.png)

3. 点击「编辑」打开知识集配置窗口，查看名称、描述和共享范围等字段；页面字段名称以实际显示为准，演示后关闭窗口。

![知识集管理步骤3](../assets/step-knowledge-management-03.png)




**注意事项**

- 删除知识集会影响依赖该知识集的能力，演示时不执行。
- 上传和更新知识文件前，应确认知识内容的授权和适用范围。

### 5.7 能力市场

能力市场用于统一维护平台可被 IDE、CLI 和智能体调用的能力资产，包括 MCP、IDE 智能体、SKILLS 和 CLI 智能体。通过能力市场可以把工具、规则包和智能体定义沉淀成可复用配置，并控制共享范围与插件可见性。

**操作步骤如下：**

1. 登录系统 > 在左侧菜单展开「通用设置」> 点击「能力市场」，进入能力市场页面。

![能力市场步骤1](../assets/step-capability-market-01.png)



2. 通过 MCP、IDE 智能体、SKILLS、CLI 智能体等页签筛选能力，查看标识、名称、描述、标签、类型、共享范围、创建人、更新时间和可用操作。

![能力市场步骤2](../assets/step-capability-market-02.png)



3. 创建能力前先确认共享范围：选择「全局」表示具备权限的成员可见，选择「私有」表示仅当前维护人或指定范围可用；演示示例只展示填写方式，不点击最终保存。

![能力市场步骤3](../assets/step-capability-market-03.png)


**注意事项**

- 新增或编辑能力会影响平台可调用工具和智能体能力，演示时不执行最终保存。
- 启用能力前应确认来源、权限和运行风险。
- 示例 ID、slug 和名称仅用于说明填写方式，正式创建时应使用团队约定的命名规范。

#### 5.7.1 创建 MCP

MCP 用于把本地命令、远程服务或工具集合注册为可被 IDE 智能体、CLI 智能体和其他 AI 能力调用的工具能力。

**操作步骤如下：**

1. 进入「能力市场」> 切换到「MCP」页签 > 点击「创建 MCP」，打开 MCP 创建窗口。

![能力市场 MCP步骤1](../assets/step-4-7-1-mcp-01.png)



2. 填写基础信息，示例为 ID「code-review-mcp」、名称「代码审计辅助 MCP」、描述「提供代码审计所需的本地命令能力」，服务地址填写企业内部 MCP 服务地址占位值，标签填写「安全审计」，共享范围按团队策略选择全局或私有。

![能力市场 MCP步骤2](../assets/step-4-7-1-mcp-02.png)

3. 在工具配置中选择单工具或多工具模式；单工具示例可填写运行要求「Node.js 18+，具备访问目标仓库的本地权限」，命令「npx」，参数 JSON「["-y","code-review-mcp"]」，环境变量 JSON「{"CODEFORCE_TOKEN":"{{CODEFORCE_TOKEN}}"}」。

![能力市场 MCP步骤3](../assets/step-4-7-1-mcp-03.png)

4. 查看窗口中的配置预览，确认生成的 mcpServers 配置包含正确的命令、参数和环境变量占位符；演示时不点击最终保存。

![能力市场 MCP步骤4](../assets/step-4-7-1-mcp-04.png)

5. 正式启用前在隔离环境执行一次命令验证，确认工具来源可信、不会读取未授权目录，也不会把 Token、源码或审计结果上传到未授权服务。

![能力市场 MCP步骤5](../assets/step-4-7-1-mcp-05.png)


**注意事项**

- MCP 的 command、args 和 env 会进入实际运行配置，参数必须使用合法 JSON。
- 环境变量示例中的 {{CODEFORCE_TOKEN}} 是占位符，正式环境应通过安全配置注入，不要在文档或截图中写入真实 Token。
- 远程 MCP 或第三方 npm 包应先做来源审查和版本固定，再开放给 IDE 或 CLI 智能体调用。

#### 5.7.2 创建 IDE 智能体

IDE 智能体用于定义在编辑器插件中可被研发人员选择的角色、调用时机、上下文权限和执行规则。

**操作步骤如下：**

1. 进入「能力市场」> 切换到「IDE 智能体」页签 > 点击「创建智能体」，打开 IDE 智能体创建窗口。

![能力市场 IDE 智能体步骤1](../assets/step-ide-agent-01.png)



2. 填写基础信息，示例为 ID「secure-reviewer」、名称「安全评审智能体」、描述「在编辑器中对当前变更进行安全评审」，调用时机填写「当研发人员需要检查当前文件、暂存区或 MR 变更是否存在高危安全问题时使用」。

![能力市场 IDE 智能体步骤2](../assets/step-ide-agent-02.png)

3. 填写角色定义「你是代码安全审计专家，关注凭证泄露、注入、越权、SSRF、反序列化和敏感日志」，自定义功能描述填写「输出问题位置、风险原因、攻击路径和最小修复建议；不确定时说明需要补充的上下文」。

![能力市场 IDE 智能体步骤3](../assets/step-ide-agent-03.png)

4. 按能力边界勾选权限组：只读场景可选择 read、command、mcp；需要自动修改代码时再添加 edit 权限，并用文件匹配规则限制为「.*\.(go|ts|tsx|py|java)$」等团队允许的代码文件。

![能力市场 IDE 智能体步骤4](../assets/step-ide-agent-04.png)

5. 确认共享范围、启用状态和插件可见性后，演示时只展示表单填写方式，不点击最终保存或发布。

![能力市场 IDE 智能体步骤5](../assets/step-ide-agent-05.png)

6. 正式发布后，研发人员应在已验证可用的编辑器插件中刷新能力列表，再选择「安全评审智能体 secure-reviewer」处理当前文件、选中代码、变更或仓库上下文；插件端验证不在本章节展开。

![能力市场 IDE 智能体步骤6](../assets/step-ide-agent-06.png)


**注意事项**

- IDE 智能体的权限越大，运行风险越高；默认先开放读取和 MCP 调用，确认稳定后再开放编辑权限。
- 编辑器插件端是否可见、是否可调用，应以实际插件登录环境和能力刷新结果为准。
- 如果后续需要补充具体编辑器插件使用流程，应单独成节并使用真实插件截图，不与 CLI 环境研发混写。

#### 5.7.3 创建 Skill

Skill 用于把一组面向特定任务的说明、脚本和参考资料打包上传，使 IDE、CLI 智能体或手动调用流程可以复用同一套能力说明。

**操作步骤如下：**

1. 先准备示例包「secure-code-review.zip」：包内可包含 SKILL.md、scripts、references 等文件，SKILL.md 写明适用场景、输入要求、执行步骤和输出格式。

![能力市场 Skill步骤1](../assets/step-4-7-3-skill-01.png)

2. 进入「能力市场」> 切换到「SKILLS」页签 > 点击「创建Skills」，选择准备好的压缩包上传。

![能力市场 Skill步骤2](../assets/step-4-7-3-skill-02.png)



3. 等待平台预览包元数据，确认 Skill 标识、名称、描述、标签和启用状态；示例 slug 可使用「secure-code-review」，名称为「安全代码评审 Skill」，描述为「用于本地变更和 MR/PR 的安全审计工作流」。

![能力市场 Skill步骤3](../assets/step-4-7-3-skill-03.png)

4. 如果需要手动维护 slug，必须使用小写字母开头，并且只包含小写字母、数字和短横线；共享范围选择全局或私有后，演示时不点击最终创建。

![能力市场 Skill步骤4](../assets/step-4-7-3-skill-04.png)

5. 创建完成后，可在 IDE 智能体、CLI 智能体或下载中心的 CLI Skill 安装流程中选择该 Skill，使编辑器插件和 OpenCode 等客户端复用同一套安全审计步骤。

![能力市场 Skill步骤5](../assets/step-4-7-3-skill-05.png)


**注意事项**

- SKILL 创建依赖合法压缩包，包内元数据解析失败时应先修复包结构再上传。
- Skill 内容可能包含脚本和工具调用说明，正式发布前应检查是否会执行高风险命令或泄露内部路径。
- 面向 IDE 插件或 CLI 的 Skill 应写清楚触发条件、需要读取的上下文和输出格式，避免研发人员不知道何时使用。

#### 5.7.4 创建 CLI 智能体并在 CLI 使用

CLI 智能体用于把用途说明、智能体定义、可用 Skill 和 MCP 组合成命令行客户端可安装或可选择的智能体能力，适合 OpenCode、Codex、Claude Code 等本地 CLI 场景。

**操作步骤如下：**

1. 进入「能力市场」> 切换到「CLI 智能体」页签 > 点击「创建CLI智能体」，打开 CLI 智能体创建窗口。

![能力市场 CLI 智能体步骤1](../assets/step-4-7-4-cli-cli-01.png)



2. 填写基础信息，示例为名称「security-reviewer」、用途说明「根据仓库变更进行安全评审」、智能体定义「先读取变更摘要和 diff，再调用 codeforce-skill 或已绑定 MCP 分析高危安全风险，最后输出问题清单和修复建议」。

![能力市场 CLI 智能体步骤2](../assets/step-4-7-4-cli-cli-02.png)

3. 在可用能力中选择刚创建的 Skill「secure-code-review」和 MCP「code-review-mcp」，按团队策略设置共享范围，并确认启用状态；演示时不点击最终创建。

![能力市场 CLI 智能体步骤3](../assets/step-4-7-4-cli-cli-03.png)

4. 创建后在详情或生成物区域查看 Codex、Claude Code、OpenCode 等客户端对应的 artifacts，按页面提示安装到目标 CLI 环境或通过下载中心同步。

![能力市场 CLI 智能体步骤4](../assets/step-4-7-4-cli-cli-04.png)

5. 研发人员按照生成物提示完成 CLI 智能体安装或同步后，在本地执行「opencode」进入 OpenCode；在底部 agents 或 commands 入口查看并选择对应智能体，发起安全评审、修复建议或 MR/PR 审计请求。

![能力市场 CLI 智能体步骤5](../assets/step-4-7-4-cli-cli-05.png)


**注意事项**

- CLI 智能体的名称、用途和定义会直接影响客户端里展示给研发人员的能力说明，应写成能判断何时使用的短句。
- 绑定的 Skill 和 MCP 必须先在能力市场中启用，否则客户端生成物可能缺少可调用能力。
- OpenCode 使用前应先完成「3.1 CLI环境研发」的认证、默认模型配置和命令验证，否则智能体无法稳定调用平台模型。

### 5.8 OpenAPI文档

OpenAPI 文档用于查询平台开放接口、接口路径、请求方式、认证要求和下载接口文档。

**操作步骤如下：**

1. 登录系统 > 在左侧菜单展开「通用设置」> 点击「OpenAPI文档」，进入 OpenAPI 文档页面。

![OpenAPI 文档步骤1](../assets/step-openapi-docs-01.png)



2. 在页面顶部查看接口数量，并使用「管理员」「普通用户」「全部」切换接口受众范围。

![OpenAPI 文档步骤2](../assets/step-openapi-docs-02.png)

3. 在「X-API-Key」输入框中输入授权 Key，使用搜索框按接口名称、路径或方法查询接口，并查看方法、路径、接口名称、认证、受众、标签和可用操作。

![OpenAPI 文档步骤3](../assets/step-openapi-docs-03.png)

4. 如需离线查看接口说明，点击「下载 JSON」或「下载 Markdown」下载文档。

![OpenAPI 文档步骤4](../assets/step-openapi-docs-04.png)


**注意事项**

- OpenAPI 调用应使用授权的 API Key，并妥善保管密钥。
- 下载接口文档不会修改业务数据，但接口调用可能产生业务影响，应按接口说明谨慎执行。

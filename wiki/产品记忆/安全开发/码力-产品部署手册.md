# 码力(CodeForce)产品部署手册

## 1部署包目录结构

| **目录或文件** | **说明** |
| --- | --- |
| codeforce.sh | 安装、更新、启停和卸载入口脚本。 |
| images/ | 码力服务所需 Docker 镜像 tar 包。 |
| docker/ | Docker 与 Docker Compose 离线安装文件。 |
| configs/ | docker-compose.yml 和 Nginx 配置模板。 |
| env/.env | 环境变量模板。 |
| common/ | 安装脚本依赖的公共脚本。 |
| knowledge-base/ | 码力知识库配置和初始数据。 |

## 2部署前要求

| **项目** | **要求** | **备注** |
| --- | --- | --- |
| **硬件环境** | CPU：16C |  |
| **硬件环境** | 内存：32GB |  |
| **硬件环境** | 磁盘：500GB SSD |  |
| **基础平台** | ubuntu 20.04 centos 7.6 以上 x86 |  |
| **基础平台** | docker版本 ＞ 27.5 |  |
| **基础平台** | docker-compose版本 ＞ 2.39.2 |  |
| **网络环境** | 默认使用 HTTP 80；如 80 被占用会尝试 10080，用于访问平台 |  |
| **网络环境** | 默认情况下，需要开通服务器的22，用于安装运维 |  |

**注：** 如果目标机器未安装 Docker 或 Docker Compose，脚本会尝试使用离线包内置的安装文件自动安装。该能力依赖 systemd 环境，并需要 root 权限。

## 3端口规则

安装预检查会检测 80 和 10080。若 80 被占用且 10080 可用，脚本会自动将 NGINX_PORT 设置为 10080。

安装完成后访问地址以终端输出为准，也可查看：

```bash
grep '^NGINX_PORT='<安装目录>/.env
```

## 4默认安装

将 CodeForce-software-installer-26.xx.xx_xxx.zip 上传到目标服务器，例如 /opt/codeforce-offline/<version>

```bash
/opt/codeforce-offline/<version>
#解压加密包
unzip -P "xxxx(密码)"  CodeForce-software-installer-26.xx.xx_xxx.zip
tar -xzf codeforce-all-in-one-<version>.tar.gz   #解压实际离线安装包：
cd offline-package    #进入离线安装目录
```

### 4.1执行安装

```bash
./codeforce.sh install   #默认安装， 会安装到/data/codeforce：
./codeforce.sh install -m full -d <安装目录>     #指定目录安装
```

如果不指定 -d，且 /data/codeforce 不存在，脚本会默认使用 /data/codeforce。

安装脚本会执行以下操作：

1. 检查系统环境、端口、磁盘、Docker 和 Docker Compose。

1. 创建安装目录。

1. 配置 .env、docker-compose.yml 和 Nginx 配置。

1. 为首次安装生成随机 admin 初始密码，并写入安装目录 .env。

1. 加载离线 Docker 镜像。

1. 初始化码力知识库。

1. 创建 shared-network Docker 网络。

1. 启动码力知识库和码力服务。

1. **输出访问地址和 admin 初始密码**。

### 4.2强制安装

如需强制安装，可使用 -f参数：

```bash
sudo ./codeforce.sh install -m full -d /data/codeforce -f
```

不建议在生产环境使用强制安装。预检查失败通常表示磁盘、端口、权限或 Docker 环境存在明确问题，应优先修复后再安装。

### 4.3登录信息

安装完成后，终端会输出访问地址，例如：

HTTP 访问地址: http://<server-ip>

管理员账号：

| **项目** | **值** |
| --- | --- |
| 用户名 | admin |
| 初始密码 | 首次安装时终端输出的随机密码，也可在 /data/codeforce/.env 的 ADMIN_PASSWORD 中查看。 |

**注：**首次登录后建议立即修改管理员密码。

## 5服务启停

进入离线包目录后，可通过 codeforce.sh execute 管理已安装服务。

```bash
sudo ./codeforce.sh execute up -d /data/codeforce    #启动服务
sudo ./codeforce.sh execute down -d /data/codeforce    #停止服务
sudo ./codeforce.sh execute restart -d /data/codeforce    #重启服务
```

**注：**服务启动时会优先启动码力知识库，再启动码力主服务；停止时会先停止码力主服务，再停止码力知识库。

## 6升级服务

### 6.1更新前准备

更新前请先获取新版本离线包，并解压到一个新的临时目录，不要覆盖之前的目录。例如：

```bash
cd /opt/codeforce-offline/<version>
unzip -P "$(cat password.txt)" artifacts.zip
tar -xzf codeforce-all-in-one-<new-version>.tar.gz
cd offline-package
```

确认当前安装目录，例如：

```bash
ls /data/codeforce
```

生产环境更新前建议确认：

- 当前业务无重要任务正在执行，或任务可以中断。

- 已预留维护窗口。

- 已确认新版本变更范围。

- 已准备数据库和对象存储备份策略。

### 6.2执行更新

执行更新命令：

```bash
sudo ./codeforce.sh install -m update_env -d /data/codeforce
```

也可以指定备份目录：

```bash
sudo ./codeforce.sh install -m update_env -d /data/codeforce -b /data/codeforce-backup/backup-$(date +%Y%m%d_%H%M%S)
```

更新脚本会执行以下操作：

1. 停止当前码力服务和码力知识库服务。

1. 询问是否进行备份；如果指定了 -b，则直接备份。

1. 备份 PostgreSQL 数据目录和关键配置文件。

1. 对比并提示是否更新 .env、docker-compose.yml 和 Nginx 配置。

1. 重新执行环境检查。

1. 加载新版本离线镜像。

1. 更新码力知识库配置；如果已有知识库数据目录，会保留数据。

1. 启动码力知识库和码力服务。

### 6.3配置对比注意事项

更新过程中，脚本会逐个对比以下文件：

| **文件** | **说明** |
| --- | --- |
| .env | 环境变量配置。 |
| docker-compose.yml | 服务编排配置。 |
| nginx.conf | Web 入口 Nginx 配置。 |
| nginx-sca.conf | SCA 相关 Nginx 配置。 |
| nginx-pandawiki.conf | 知识库相关 Nginx 配置。 |
| nginx-inner.conf | 内部访问 Nginx 配置。 |

脚本提示是否应用新文件时，默认值为 y。生产环境不要直接一路回车，应重点核对 .env 中的数据库密码、Redis 密码、MinIO 配置、模型配置、代理配置和 ADMIN_PASSWORD 等本地配置，避免被新包模板覆盖。

如果选择不应用某个配置文件，脚本会保留当前安装目录中的原文件。

### 6.4更新后验证

更新完成后建议执行：

```bash
cd /data/codeforce
sudo docker compose ps
sudo docker compose logs -f --tail=200 server
sudo docker compose logs -f --tail=200 codeforce-server
```

**验证项目：**

- Web 页面可正常访问。

- 管理员可正常登录。

- 核心服务、兼容后端、前端、数据库、Redis、MinIO、Worker 和扫描器处于运行状态。

- 历史项目、任务和报告数据仍可访问。

- 可创建一次小规模测试任务。

## 7卸载服务

### 7.1保留镜像卸载

执行：

```bash
sudo ./codeforce.sh uninstall -d /data/codeforce
```

脚本会提示确认。确认后会：

1. 停止并删除码力服务容器、网络和 Compose 卷。

1. 停止并删除码力知识库服务容器、网络和 Compose 卷。

1. 删除安装目录 /data/codeforce。

1. 如果 shared-network 未被其他容器使用，则删除该网络。

该操作会删除安装目录下的数据和配置，请在卸载前完成备份。

### 7.2跳过确认卸载

自动化场景可使用 -f 跳过确认：

```bash
sudo ./codeforce.sh uninstall -d /data/codeforce -f
```

### 7.3同时删除镜像

如需额外删除当前安装涉及的 Docker 镜像：

```bash
sudo ./codeforce.sh uninstall -d /data/codeforce -f --purge-images
```

--purge-images 会根据安装目录中的 Compose 配置收集镜像并执行删除。如果镜像仍被其他容器使用，删除可能失败，脚本会给出警告并继续卸载流程。

## 9故障处理

### 9.1安装目录已存在

首次安装 -m full 要求安装目录为空。若目录已存在且包含内容，脚本会提示使用更新模式。

新安装请更换空目录或清理旧目录；已有环境升级请使用：

```bash
sudo ./codeforce.sh install -m update_env -d /data/codeforce
```

### 9.2忘记初始管理员密码

首次安装生成的随机密码会写入安装目录 .env：

```bash
grep '^ADMIN_PASSWORD=' /data/codeforce/.env
```

注意：管理员用户创建后，后续修改 .env 中的 ADMIN_PASSWORD 不会自动重置数据库中已有管理员密码。

### 9.3Docker 未安装

脚本会尝试使用离线包内置的 Docker 和 Docker Compose 安装文件自动安装。若自动安装失败，请检查：

- 是否使用 root 权限执行。

- 当前系统是否使用 systemd。

- iptables 等基础依赖是否可用。

- /usr/local/bin 和 systemd 服务目录是否可写。

### 9.4更新后配置异常

优先检查更新前备份目录。更新脚本会备份配置到：

```
<backup-dir>/config/
```

可按需恢复 .env、docker-compose.yml 或 Nginx 配置，然后重启服务：

```bash
sudo ./codeforce.sh execute restart -d /data/codeforce
```

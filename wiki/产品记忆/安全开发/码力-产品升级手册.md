# 码力（CodeForce）产品升级手册

## 1. 升级概述

码力采用多服务容器化部署，升级通常包含镜像版本更新、配置变更、数据库迁移、前端资源更新和 worker 重启。升级前应完成数据备份，并在测试环境完成验证后再进入生产环境。

## 2. 升级前准备

### 2.1 确认升级范围

升级前应确认：

- 目标版本号或镜像标签。
- 是否包含数据库迁移。
- 是否包含 `.env` 新增或废弃配置。
- 是否包含 Nginx 配置变更。
- 是否包含 worker、scanner 或模型代理变更。
- 是否需要同步更新子模块或 patch 文件。

### 2.2 备份数据

升级前建议备份：

- PostgreSQL 数据库。
- MinIO 对象存储。
- `.env` 文件。
- Nginx 配置文件。
- 当前 `docker-compose.yml`。
- 关键业务报告和任务工件。

示例：

```bash
mkdir -p backups/$(date +%Y%m%d)
cp .env docker-compose.yml nginx*.conf backups/$(date +%Y%m%d)/
```

数据库和对象存储应使用企业标准备份工具或运维平台执行。

### 2.3 记录当前状态

```bash
docker compose ps
docker compose images
git status --short
```

如需回滚，应记录当前镜像标签和配置版本。

## 3. 标准升级流程

### 3.1 拉取最新代码

```bash
git fetch --all
git checkout <target-branch-or-tag>
git submodule update --init --recursive
```

### 3.2 合并配置变更

对比新旧 `.env.template`、`docker-compose.yml` 和 Nginx 配置，确认新增变量并补齐本地 `.env`。

重点检查：

- 镜像版本 `IMAGE_TAG`。
- 数据库连接配置。
- Redis 密码。
- MinIO 配置。
- 模型服务配置。
- worker 副本数。
- 安全扫描服务配置。
- 文档转换和报告服务配置。

### 3.3 更新镜像

```bash
docker compose pull
```

如使用本地构建镜像，应先执行对应组件构建命令。

### 3.4 重启服务

```bash
docker compose up -d
```

服务启动后查看状态：

```bash
docker compose ps
docker compose logs -f codeforce-server
```

数据库迁移通常由服务启动流程自动执行。升级期间应关注核心服务日志，确认迁移成功且无重复错误。

## 4. 本地构建升级流程

如需基于当前代码构建服务：

```bash
# 构建后端
cd codeforce
make ent wire
make bin
make image

# 构建 worker
cd ../infinitemonkey
make bin
make image

# 构建前端
cd ../ui
pnpm install
pnpm run build
make image
```

构建完成后更新镜像标签或 Compose 配置，再执行：

```bash
docker compose up -d
```

## 5. 升级后验证

升级完成后建议执行以下检查：

| 验证项 | 验证方式 |
| --- | --- |
| 页面访问 | 打开 Web 控制台并登录。 |
| 服务状态 | 执行 `docker compose ps`。 |
| 核心日志 | 查看 `codeforce-server`、`worker`、`frontend` 日志。 |
| 数据库连接 | 检查核心服务是否启动成功并完成迁移。 |
| AI 任务 | 创建测试 AI 编码任务并观察执行结果。 |
| 安全扫描 | 发起一次小规模 SAST 或 SCA 扫描。 |
| 报告生成 | 生成测试报告并下载。 |
| 模型调用 | 确认模型配置和模型代理可用。 |

## 6. 回滚流程

如升级失败，可按以下方式回滚：

1. 停止当前服务。
2. 恢复升级前的 `.env`、`docker-compose.yml` 和 Nginx 配置。
3. 将 `IMAGE_TAG` 改回升级前版本。
4. 恢复数据库和对象存储备份。
5. 启动服务并验证。

示例：

```bash
docker compose down
cp backups/<backup-dir>/.env .
cp backups/<backup-dir>/docker-compose.yml .
cp backups/<backup-dir>/nginx*.conf .
docker compose up -d
```

如果新版本已经执行了不可逆数据库迁移，应优先通过数据库备份恢复，而不是仅回退镜像。

## 7. 升级注意事项

- 生产环境升级前必须完成备份。
- 不建议在业务高峰期升级。
- 涉及数据库迁移时，应预留更长维护窗口。
- 涉及 worker 或扫描服务变更时，应等待运行中的任务完成或确认可中断。
- 涉及模型配置变更时，应提前验证模型服务可达。
- 涉及 Nginx 配置变更时，应检查 API、插件和静态资源路由。

## 8. 常见问题

### 8.1 升级后页面打不开

- 检查 `frontend` 是否正常运行。
- 检查 Nginx 配置是否被正确复制到根目录。
- 检查端口是否冲突。
- 检查浏览器缓存或前端资源版本。

### 8.2 升级后任务无法执行

- 检查 worker 是否启动。
- 检查 Redis 连接是否正常。
- 检查 Docker socket 是否挂载。
- 检查模型配置是否变更。

### 8.3 升级后扫描失败

- 检查扫描器镜像是否更新成功。
- 检查数据库和对象存储连接。
- 检查扫描服务资源限制。
- 检查外部扫描服务或代理是否可达。

### 8.4 数据库迁移失败

- 保留日志。
- 停止业务写入。
- 根据错误信息确认是否为配置、权限、版本或重复迁移问题。
- 必要时恢复升级前数据库备份。

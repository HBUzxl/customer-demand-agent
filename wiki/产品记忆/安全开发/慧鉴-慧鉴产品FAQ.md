# 慧鉴(CodeInsight)产品FAQ

本文档面向首次了解、试用、交付和日常使用慧鉴的用户，汇总产品能力、部署方式、扫描流程、结果处置和常见配置问题。具体操作步骤可结合《慧鉴(CodeInsight)产品使用手册》和《慧鉴(CodeInsight)离线部署安装使用说明》查看。

## 1. 产品定位

### Q1：慧鉴(CodeInsight)主要解决什么问题？

慧鉴是一套面向企业研发安全、代码质量治理和合规审查场景的代码安全审计平台。它通过静态代码分析、规则体系、AI 智能分析、告警降噪、报告输出和漏洞闭环管理，帮助企业在研发和交付过程中发现、研判、修复和追踪代码风险。

### Q2：慧鉴和传统静态代码扫描工具有什么区别？

慧鉴不仅提供静态代码安全检测，还将任务管理、规则管理、缺陷审计、报告输出、AI 审计、AI 告警降噪、流水线集成和权限管理整合到统一平台中。它更适合持续化的代码安全治理，而不是只做单次扫描报告输出。

### Q3：慧鉴适合哪些组织或使用场景？

慧鉴适用于金融、政务、能源、通信、汽车、医疗、工业软件、互联网软件企业、第三方测评机构和代码审计机构等场景。常见用途包括上线前安全检查、研发过程安全门禁、专项代码审计、供应链代码检测、合规留痕和多团队漏洞闭环治理。

## 2. 扫描方式

### Q4：慧鉴支持哪些扫描方式？

慧鉴支持在线分析和离线分析两种方式：

- 在线分析：通过平台上传源码包或远程拉取仓库代码进行分析，适合轻量接入和快速验证。
- 离线分析：将分析探针下载到代码所在环境执行扫描，扫描完成后将结果上传至平台，适合源码不便离开客户环境、需要接入 CI/CD 或需要使用增强引擎的场景。

### Q5：什么时候推荐使用离线分析？

以下场景通常推荐使用离线分析：

- 代码或编译环境必须保留在客户内网或指定服务器中。
- C/C++ 或 Java 项目需要结合真实编译环境进行增强分析。
- 需要在 CI/CD 流水线中自动触发扫描。
- 在线分析资源压力较大，或希望由独立 Worker、探针环境承担扫描任务。

### Q6：在线分析是否支持所有增强引擎能力？

不完全支持。根据当前使用手册，在线分析不支持 C/C++ 增强引擎。需要使用 C/C++ 增强引擎时，应选择离线分析，并在代码实际编译环境中执行平台生成的扫描命令。

### Q7：C/C++、Java 和极速引擎的扫描命令有什么差异？

不同引擎生成的扫描命令需要按项目实际情况调整：

- C/C++ 增强引擎通常需要将命令中的 `BUILD_COMMAND` 替换为项目的清理和编译命令，例如 `make clean && make`，并且必须执行编译清理。
- Java 增强引擎通常需要将 `PROJECT_ROOT` 替换为待分析项目根目录，部分项目需要先完成编译打包。
- 极速引擎的离线扫描命令通常可以直接执行，不需要替换编译命令。

### Q8：慧鉴是否支持 VBScript、JScript、TypeScript、ASP 和 Node.js 扫描？

慧鉴当前支持 JavaScript、TypeScript 和 Node.js 应用的源代码安全扫描。

#### 当前支持情况

- **TypeScript**：支持 `.ts`、`.tsx` 文件，当前统一使用 JavaScript 语言及相关规则集进行扫描。
- **Node.js**：支持 Node.js 源代码扫描，可检测通用安全问题，并覆盖 Express、Koa、Hapi、NestJS、Sequelize、TypeORM 等常见框架和组件的部分安全规则。
- **ASP.NET**：支持 C# 编写的 ASP.NET、ASP.NET MVC 和 ASP.NET Core 后端源码，并提供部分框架专项规则。独立的 C# 源码及代码后置文件可以扫描，`.aspx`、`.cshtml` 页面中的内嵌代码暂不保证完整覆盖。

#### 当前暂不支持的范围

- VBScript。
- VB.NET。
- JScript、WSH、ActiveX 等微软特有的脚本技术。
- 经典 ASP（`.asp`）及其中内嵌的 VBScript、JScript。
- npm 第三方依赖及已知 CVE 扫描。

普通 JScript 如果采用标准 JavaScript 语法并保存为 `.js` 文件，可能被作为 JavaScript 代码扫描，但不属于慧鉴正式支持范围。

#### 后续优化计划

慧鉴正在持续优化静态分析引擎，重点提升以下能力：

- **TypeScript**：增强类型理解、跨函数及跨文件数据流分析，扩展 `.mts`、`.cts` 等文件类型支持。
- **Node.js**：增强服务端安全分析，以及对 Express、Fastify、Hapi、Koa、NestJS、Restify 等常见框架的安全建模和漏洞检测能力。
- **ASP.NET**：增强对 C# ASP.NET、ASP.NET Core、MVC、Razor 模板及 Entity Framework 等技术栈的深度分析能力。

相关优化预计于 **2026 年 8 月底前**完成并逐步上线。本阶段优化不包含 VBScript、JScript、经典 ASP、VB.NET 和 SCA 组件漏洞扫描。

## 3. 部署与交付

### Q9：慧鉴支持私有化或离线部署吗？

支持。慧鉴提供离线部署包，可在客户环境中安装、升级、停止、重启和卸载。部署包中包含服务编排文件、配置目录、离线 Docker 组件和运行所需镜像包，适合内网和私有化交付场景。

### Q10：部署慧鉴对机器规格有什么要求？

部署手册中给出的最低规格为 8 核 CPU、16 GB 内存和 500 GB 以上 SSD 可用空间，最低规格仅建议用于 POC；推荐规格为 16 核 CPU、32 GB 内存和 500 GB 以上 SSD 可用空间。安装脚本会检查机器规格，不满足要求时默认停止安装，确认继续时可使用强制参数。

### Q11：安装时 80 端口被占用怎么办？

平台 Web 服务默认使用宿主机 80 端口。安装脚本会自动检测端口占用情况：如果 80 端口可用则使用 80；如果 80 被占用，会自动切换到 10080；如果 80 和 10080 都被占用，脚本会提示手动输入可用端口。最终端口会写入安装目录下的 `.env` 文件。

### Q12：首次部署后如何获取管理员密码？

首次安装成功后，安装脚本会在控制台打印初始密码。也可以在安装目录的 `conf` 目录下查看 `initial-admin-password.txt` 文件获取首次部署密码。

## 4. 规则、结果和报告

### Q13：慧鉴支持哪些类型的检测？

慧鉴支持质量与安全检测、敏感信息检测、IaC 检测等扫描类型。质量与安全检测用于代码质量与安全分析；敏感信息检测用于发现 API 密钥、用户名、密码、令牌、URL 等敏感内容；IaC 检测用于扫描 Terraform、CloudFormation、Kubernetes、Helm、Azure Resource Manager、Docker 等基础设施配置中的风险。

### Q14：如果不确定应该选择哪个扫描标准怎么办？

创建任务时可以根据语言、行业和合规要求选择扫描标准。若暂时无法确认标准类型，可优先选择“推荐”标准，再根据后续扫描结果、企业规范和审计要求调整规则集。

### Q15：慧鉴是否支持自定义规则和规则配置？

支持。慧鉴提供规则库、规则集和部分引擎规则配置能力。C/C++ 增强引擎和 Java 增强引擎支持部分规则自定义配置，例如污点分析模型、动态内存分配函数、IO 流函数、函数摘要、source 规则、sink 规则和 summary 规则等。

### Q16：扫描结果可以如何处置和流转？

扫描完成后，用户可以在平台中查看任务结果和缺陷详情，并根据风险等级、缺陷类型、代码位置和审计结论进行确认、分派、修复、复测和归档。平台支持缺陷结果导出、报告输出、第三方平台同步和临时链接分享，便于安全、研发、测试和管理角色协同处理。

### Q17：慧鉴可以导出哪些报告？

慧鉴支持报告导出能力，可用于项目验收、整改跟踪和合规留痕。具体可导出的格式和模板以当前版本平台页面和使用手册说明为准。

## 5. AI 能力与研发流程集成

### Q18：慧鉴的 AI 智能分析主要做什么？

慧鉴的 AI 智能分析用于结合扫描结果和代码上下文进行进一步研判，帮助区分真实风险、误报和待确认问题，并提供原因说明、修复建议和处置优先级参考，从而降低人工筛选告警的成本。

### Q19：慧鉴 AI 降噪为什么分为“快速降噪”和“深度降噪”两条技术路线？

慧鉴 AI 降噪采用分层技术架构，核心目标是在不同算力条件、模型规模和精度要求之间取得最优平衡。对于算力资源有限、模型参数量相对较小的客户环境，慧鉴提供快速降噪路线，以较低资源成本完成告警二次判定和误报辅助识别；对于具备优质算力资源、可承载更大模型和更长上下文推理链路的客户环境，慧鉴提供深度降噪路线，通过更充分的仓库级上下文检索与智能推理提升复杂漏洞场景下的判断精度。

这种分级设计使慧鉴既能适配私有化、内网化和资源受限的交付环境，也能在高规格算力环境下释放大模型与智能体的深度分析能力，避免用单一技术形态强行覆盖所有客户场景。

### Q20：快速降噪适用于哪些场景，核心原理是什么？

快速降噪主要面向算力资源有限、模型参数量较小的客户场景，通常适合使用 100B 以下模型或对响应成本、部署复杂度、处理吞吐有明确约束的环境。

其核心思路是“引擎线索采集 + 平台流程化推理”。在代码扫描和分析过程中，慧鉴引擎会围绕告警点收集关键上下文与线索信息，并将缺陷名称、文件位置、行号、漏洞类别、严重等级及相关分析材料传输至平台。平台侧再由流式智能体（Streaming Agent）调用大模型能力，按照产品预设的专业分析流程，对漏洞触发条件、数据流路径、安全防护措施、攻击可达性和误报依据进行逐步推理。

快速降噪不是简单让模型“读一条告警后给结论”，而是将静态分析引擎沉淀出的结构化证据与大模型的语义研判能力结合起来。该过程支持多轮对话交互，可在固定流程内持续补充解释、修正判断和收敛结论，使降噪结果更稳定、更可控，也更适合在企业级环境中规模化落地。

### Q21：深度降噪适用于哪些场景，核心原理是什么？

深度降噪适用于算力资源充足、模型能力较强、对降噪精度和复杂漏洞识别要求极高的客户环境，尤其适合大型代码仓库、复杂业务系统、跨文件调用链、框架封装较深或传统规则难以准确判定的场景。

深度降噪采用“智能规划型 Agent”模式。与依赖预设上下文的快速降噪不同，深度降噪会挂载完整代码仓库和扫描产物，由智能体围绕目标告警自主制定分析计划：先理解告警位置和风险类型，再在仓库全局范围内动态寻找调用链、数据来源、配置约束、框架处理逻辑、鉴权校验、过滤函数、业务边界和运行条件等深层证据，最后基于完整证据链输出漏洞、误报或未知结论。

这种模式的关键价值在于上下文不再局限于扫描阶段预先抽取的信息，而是由智能体根据当前漏洞的真实分析需求主动检索、验证和补全。对于需要跨模块推理、跨层追踪或结合业务语义判断的告警，深度降噪能够获得更接近人工资深安全审计的分析过程。

### Q22：深度降噪相比快速降噪的技术优势是什么？

深度降噪的优势主要体现在两个方面。

第一，适应范围更广。深度降噪不依赖单一告警点附近的固定上下文，而是在完整仓库范围内构建漏洞相关证据链，因此更适合处理复杂框架、间接调用、跨文件数据流、配置影响、业务前置校验和运行时约束等复杂场景。

第二，识别精度更高。快速降噪以产品预设流程和引擎采集线索为基础，强调低成本、高效率和稳定输出；深度降噪则由智能体按需动态采集信息，能够根据漏洞类型和代码结构实时调整分析路径，减少“上下文不足导致无法判断”或“证据片段不完整导致误判”的情况，从而实现更精准的漏洞真实性识别。

对于高价值系统、重点版本、关键业务模块和高危告警复核场景，深度降噪可以作为更高精度的 AI 安全审计能力，帮助安全团队把有限的人力集中在真正需要处置的风险上。

### Q23：客户应如何选择快速降噪或深度降噪？

客户可以根据算力条件、模型规模、代码复杂度和精度要求选择降噪路线：

- 如果客户环境算力有限、模型规模较小、需要快速完成大批量告警初筛，建议优先选择快速降噪。
- 如果客户具备较好的 GPU/推理算力，能够承载更大模型和更长上下文分析，并且对重点系统的误报识别精度要求极高，建议选择深度降噪。
- 如果客户既有规模化降噪需求，又有重点告警深度复核需求，可采用组合策略：先用快速降噪完成批量告警筛选，再对高危、疑难或业务关键告警启用深度降噪。

通过这种分层组合，慧鉴可以同时覆盖“广覆盖、低成本”的日常治理场景和“高精度、深推理”的专项审计场景，让 AI 降噪能力与客户实际算力投入和安全治理成熟度保持一致。

### Q24：慧鉴是否支持对 AI 生成代码进行安全治理？

支持。对于已经引入 AI 编程工具的研发组织，慧鉴可用于识别 AI 生成代码中的安全问题、规范偏差和潜在风险，帮助企业在研发提效的同时保持代码安全审查能力。

### Q25：慧鉴可以接入 CI/CD 或研发流程吗？

可以。慧鉴可通过探针、CLI、Jenkins 插件、IDE 插件、开放接口等方式接入企业研发流程，并与代码仓库、CI/CD 流水线和缺陷管理平台协同。企业可以在研发过程中自动触发扫描和安全门禁，使风险代码更早被发现和处置。

### Q26：代码门禁可以按什么条件配置？

慧鉴代码门禁用于对代码质量和安全风险进行整体把控。当前使用手册中提到的门禁配置条件包括漏洞总数、严重程度等级、缺陷名称、代码度量指标数、克隆检测重复率等。

## 6. 常见使用问题

### Q27：扫描任务执行完成后，如何确认结果已经上传？

离线扫描执行完成后，终端输出中出现类似 `Upload...100%` 的上传完成信息，并返回任务结果访问地址时，通常表示扫描结果已经上传到平台。用户可登录平台或访问输出的 Task URL 查看任务结果。

### Q28：访问令牌过期会有什么影响？

访问令牌主要用于扫描时的鉴权。如果访问令牌失效或过期，扫描操作可能无法正常执行。遇到令牌相关错误时，应在平台中重新创建或更新访问令牌，并使用新的令牌重新执行扫描。

### Q29：扫描时是否可以排除不需要分析的文件或函数？

可以。慧鉴支持扫描黑白名单能力，可在分析过程中排除扫描文件、排除指定源码文件中的某些函数，或增加需要扫描的源码文件。具体配置方式以当前版本平台页面和使用手册说明为准。

### Q30：扫描时间较长时，应该优先检查哪些因素？

可以优先检查项目规模、扫描引擎类型、扫描策略、编译命令是否完整、分析环境资源是否充足，以及是否选择了适合当前项目的扫描方式。对于大型项目或需要高精度分析的项目，扫描耗时会相对更长；如果资源不足，可能出现排队或执行缓慢。

### Q31：产品资料中找不到的问题应该如何反馈？

如果 FAQ、使用手册、部署手册或 OpenAPI 文档中没有覆盖相关问题，可通过项目约定的需求提交入口或 Bug 反馈入口提交问题，并附上产品版本、部署方式、任务类型、扫描语言、关键错误信息和复现步骤，便于定位和处理。

### Q32：慧鉴普通用户无法使用创建代码托管平台的新建配置

是的，若客户想要新建的用户有这个权限的话，可以创建自定义角色，赋予权限就可以了

### Q33：创建的角色，查看的内容是隔离的吗？比如A用户只查看A部门的代码扫描结果；B用户只查看B部门扫描结果

是的，每个用户的任务都是隔离的，除了管理员其他不可看，除非将授权给其他用户

### Q34：离线分析结果包上传对结果包的限制是多少？

/openapi/v1/probe/upload-file，这条接口所在的扫描服务默认配置是单文件 16000MB、总请求 32000MB

在docker-compose文件里，去掉minio的镜像后缀"-cpuv1"，然后docker-compose down，docker-compose up -d重启服务即可


### Q36：代码托管平台是直接git clone拉取到慧鉴服务器本地的吗？扫描完代码后会继续保存在磁盘吗

是，Git工作副本扫描后通常会删除，但平台还会保留带有风险的源码压缩归档。

### Q38：任务列表-每一个任务显示的修复漏洞数据是什么意思
这里是本次任务对比上一次任务少的漏洞，如果一个项目里每次分析的任务不是一套代码和规则集，这里的数据没有参考价值，后续优化这一块逻辑

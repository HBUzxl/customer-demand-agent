# 全悉（T-Answer）产品快速开始

> 适用对象：首次使用全悉的安全运营人员、管理员和实施人员  
> 参考文档：《全悉（T-Answer）用户手册》  
> 适用产品版本：全悉标准版 25.10.x

---

## 1. 快速开始路径

全悉（T-Answer）高级威胁分析预警系统是一款面向网络流量检测与响应的 NDR 产品。首次使用时，建议按以下路径完成基础配置和日常运营闭环：

1. 登录系统并完成账号安全配置
2. 查看威胁仪表，确认整体威胁态势
3. 进入威胁告警，筛选和研判高优先级告警
4. 使用告警详情完成溯源、标记、白名单或阻断处置
5. 配置资产、检测策略、响应策略和通知方式
6. 建立日常巡检与报告输出流程

---

## 2. 登录系统

### 2.1 访问管理平台

1. 打开浏览器，访问全悉管理平台地址，例如 `https://<设备IP>`。
2. 输入用户名和密码。
3. 点击「登录」进入系统。

![登录页面整体](./images/图2.1-1_登录页面整体.png)

### 2.2 首次登录处理

首次登录或密码过期时，系统会要求修改密码：

1. 输入旧密码。
2. 输入符合密码策略的新密码。
3. 再次确认新密码。
4. 点击「提交」完成修改。

![密码修改页面](./images/图2.2-1_密码修改页面.png)

如果系统启用了 MFA 多因素认证，需要使用 TOTP 认证器扫描二维码，并输入 6 位验证码完成绑定。

### 2.3 认识主界面

登录后进入主界面，左侧为功能菜单，顶部为当前模块导航，右上角包含消息中心、任务中心和个人中心入口。

![主界面整体](./images/图2.4-1_主界面整体.png)

常用入口如下：

| 目标 | 菜单路径 |
|------|----------|
| 查看安全态势 | 威胁视图 → 威胁仪表 |
| 处理威胁告警 | 威胁事件 → 威胁告警 |
| 查看聚合攻击趋势 | 威胁事件 → 告警聚合 |
| 检索原始流量 | 流量元数据 → 数据检索 |
| 管理资产 | 企业资产 → 资产配置 |
| 配置检测策略 | 安全策略 |
| 配置阻断与响应 | 响应处置 |
| 管理用户和系统状态 | 系统管理 |

## 3. 查看威胁态势

进入「威胁视图 → 威胁仪表」，先确认当前网络的整体威胁情况。

![威胁仪表整体页面](./images/图3.1-1_威胁仪表-整体页面.png)

建议优先关注以下指标：

| 指标 | 关注点 |
|------|--------|
| 威胁告警总数 | 判断当前告警规模和环比变化 |
| 告警等级分布 | 优先查看超危、高危告警 |
| 攻击结果统计 | 优先处理失陷、成功结果 |
| 攻击 IP Top10 | 定位高频攻击来源 |
| 受害 IP Top10 | 定位重点受害资产 |
| 攻击链路 | 判断攻击处于侦查、入侵、控制、横向移动等阶段 |
| 阻断统计 | 确认响应策略是否已经生效 |

如果需要值守大屏或汇报展示，可进入「威胁视图 → 威胁大屏」查看实时攻击态势。

---

## 4. 研判威胁告警

### 4.1 进入告警列表

进入「威胁事件 → 威胁告警」，查看检测引擎产生的告警。

![威胁告警整体页面](./images/图4.1-1_威胁告警-整体页面.png)

首次处理告警时，建议使用以下筛选组合：

| 筛选项 | 建议值 |
|--------|--------|
| 时间 | 今天或最近 24 小时 |
| 忽略状态 | 未忽略 |
| 已读状态 | 未读 |
| 威胁等级 | 超危、高危 |
| 攻击结果 | 失陷、成功 |

### 4.2 使用快速筛选

快速筛选适合常规运营场景，可按攻击 IP、受害 IP、威胁等级、攻击阶段、攻击结果、资产组等条件缩小范围。

常用操作：

1. 设置时间范围。
2. 选择威胁等级和攻击结果。
3. 输入攻击 IP 或受害 IP。
4. 点击「确定」查看结果。
5. 将常用筛选条件保存为筛选场景，便于下次复用。

### 4.3 使用高级筛选

高级筛选适合精确查询。格式为：

```text
字段名 运算符 值 逻辑连接符 字段名 运算符 值
```

示例：

```text
severity in (1, 2) AND result in ('control', 'success') AND attacker = '192.168.0.1'
```

常用字段：

| 字段 | 含义 |
|------|------|
| `attacker` | 攻击 IP |
| `victim` | 受害 IP |
| `severity` | 威胁等级，1 为超危，2 为高危，3 为中危，4 为低危 |
| `result` | 攻击结果，`control` 为失陷，`success` 为成功，`failed` 为失败，`unknown` 为企图 |
| `phase` | 攻击阶段 |
| `app_proto` | 应用层协议 |
| `appbrief.url` | URL 路径 |

![高级筛选页面](./images/图4.1.2-1_威胁告警-高级筛选Tab整体页面.png)

### 4.4 查看告警详情

点击告警列表中的「详情」，打开告警详情侧边面板。

![告警详情侧边面板](./images/图4.1.2-12_告警详情-Drawer整体页面.png)

建议按以下顺序研判：

1. 查看五元组信息，确认攻击 IP、受害 IP、端口和协议。
2. 查看威胁等级、攻击阶段、攻击结果和威胁类型。
3. 阅读攻击描述、原始报文、载荷解码、攻击危害与修复建议。
4. 如需进一步确认，查看数据包解码、原始数据或下载 PCAP。
5. 如需溯源，点击「元数据溯源」跳转到流量元数据检索。

## 5. 完成告警处置

告警研判完成后，根据结果选择处置方式。

| 场景 | 推荐操作 |
|------|----------|
| 确认为高风险攻击 | 加入阻断名单或创建旁路阻断策略 |
| 需要联动防火墙/WAF | 使用第三方协同阻断 |
| 告警需后续跟进 | 标记为重点告警、待紧急处置或待确认排查 |
| 确认为误报或合法流量 | 加入检测白名单 |
| 不希望自动阻断某些 IP | 加入响应白名单 |
| 需要自动化处置 | 设置自动响应策略 |

### 5.1 加入阻断名单

在告警列表或告警详情中选择「加入阻断名单」：

1. 选择阻断对象，支持 IP 或四元组。
2. 选择阻断方式，可选择旁路阻断和第三方协同阻断。
3. 配置策略名称、阻断时长或失效时间。
4. 确认提交。
5. 如需要自动化，继续创建自动响应策略。

### 5.2 查看阻断策略和记录

进入「响应处置 → 旁路阻断策略」管理阻断规则。

![旁路阻断策略整体页面](./images/图7.2-1_旁路阻断策略-整体页面.png)

进入「响应处置 → 旁路阻断记录」确认阻断是否执行。

![旁路阻断记录整体页面](./images/图7.1-1_旁路阻断记录-整体页面.png)

旁路阻断注意事项：

- 旁路阻断依赖阻断网口到访问者网络连通可达。
- 旁路阻断使用 TCP RESET 技术，仅对 TCP 报文有效。
- 建议先确认响应白名单，避免误阻断关键业务 IP。

## 6. 完成基础配置

### 6.1 配置企业资产

进入「企业资产 → 资产配置」，维护企业资产信息。

![资产配置整体页面](./images/图8.1-1_资产配置-整体页面.png)

建议配置内容：

| 配置项 | 用途 |
|--------|------|
| 资产名称和 IP | 让告警能够关联真实业务资产 |
| 负责人 | 便于告警流转和通知 |
| 资产重要性等级 | 用于告警优先级判断 |
| 资产类型和位置 | 便于筛选和统计 |
| 资产分组 | 用于告警筛选和自动响应条件 |

可以手动添加资产，也可以通过 CSV 批量导入。

### 6.2 配置检测策略

进入「安全策略」，按需配置检测能力。

![安全策略整体页面](./images/图6.-1_安全策略-整体页面.png)

常用配置如下：

| 标签页 | 使用场景 |
|--------|----------|
| 内置规则 | 查看和启停内置检测规则 |
| 自定义规则 | 使用 Suricata 兼容语法添加检测规则 |
| 自定义情报 | 导入 IP、域名、URL、文件哈希等 IOC |
| 检测白名单 | 排除合法流量，减少误报 |
| 登录安全 | 配置弱口令字典和暴力破解检测策略 |
| SSL 检测 | 上传 SSL 私钥，启用 HTTPS 解密检测 |
| 蜜罐联动 | 配置蜜罐系统联动告警 |

上线初期建议先配置检测白名单和自定义情报，再逐步调整内置规则和自定义规则。

### 6.3 配置自动响应

进入「响应处置 → 自动响应策略」，创建自动化处置策略。

![自动响应策略整体页面](./images/图7.3-1_自动响应策略-整体页面.png)

自动响应支持两种模式：

| 模式 | 说明 |
|------|------|
| 暂存处置 | 命中策略后进入待处置名单，由人工审核后下发 |
| 直接下发 | 命中策略后立即执行阻断 |

建议上线初期使用「暂存处置」模式，确认策略准确后再切换为「直接下发」。

### 6.4 配置响应白名单

进入「响应处置 → 响应白名单」，添加不应被阻断的合法 IP 或网段。

![响应白名单整体页面](./images/图7.4-1_响应白名单-整体页面.png)

响应白名单只影响阻断和自动响应，不影响检测白名单。

### 6.5 配置联动设备

进入「响应处置 → 联动设备配置」，配置防火墙、WAF、主机安全等第三方设备联动。

![联动设备配置整体页面](./images/图7.5-1_联动设备配置-整体页面.png)

配置步骤：

1. 选择设备类型。
2. 输入设备 IP、端口和认证信息。
3. 点击「连接测试」。
4. 测试成功后保存。

### 6.6 配置通知

进入「系统管理 → 数据配置」，配置 Syslog、Kafka、IM、Email、SNMP 等外部通知方式。

![数据配置整体页面](./images/图6.6-1_配置通知-数据配置整体页面.png)

建议至少配置一种告警通知方式，例如钉钉、飞书、企业微信或 Email，确保超危和高危告警能及时触达。

## 7. 使用流量元数据溯源

进入「流量元数据 → 数据检索」，可基于源 IP、目的 IP、端口、协议和时间范围查询原始流量记录。

![数据检索整体页面](./images/图9.1-1_数据检索-整体页面.png)

典型使用场景：

| 场景 | 操作 |
|------|------|
| 告警溯源 | 从告警详情点击「元数据溯源」 |
| 横向排查 | 使用受害 IP 查询同时间段关联通信 |
| 协议分析 | 展开 HTTP、DNS、TLS、邮件等协议详情 |
| 取证留存 | 查看或下载 JSON、PCAP 数据 |

## 8. 生成报告

进入「威胁视图 → 威胁报表」，可以查看分析报告或创建定时报告任务。

常用报告方式：

| 方式 | 用途 |
|------|------|
| 即时报告 | 对指定时间范围生成一次性报告 |
| 定时报告任务 | 按日报、周报、月报周期生成报告 |
| 自定义时间范围 | 用于事件复盘、审计或汇报 |

如需要通过邮件发送报告，请先在「系统管理 → 数据配置 → Email 配置」中完成 SMTP 配置。

## 9. 日常巡检建议

### 9.1 每日巡检

1. 进入「威胁视图 → 威胁仪表」，查看告警总数、等级分布、攻击结果变化。
2. 进入「威胁事件 → 威胁告警」，筛选超危、高危、失陷、成功告警。
3. 查看告警详情，完成研判、标记、白名单或阻断处置。
4. 进入「响应处置 → 旁路阻断记录」，确认阻断策略是否生效。
5. 查看「消息中心」和「任务中心」，确认通知和后台任务状态。

### 9.2 每周巡检

1. 查看「威胁事件 → 告警聚合」，按攻击 IP、受害 IP、威胁类型聚合分析趋势。
2. 检查「企业资产 → 资产配置」，补充资产负责人、重要性等级和分组。
3. 检查检测白名单和响应白名单，清理过期或不再适用的规则。
4. 查看威胁报表，输出周报并归档。

### 9.3 新设备上线检查

| 步骤 | 操作路径 |
|------|----------|
| 导入或补充资产 | 企业资产 → 资产配置 |
| 导入已知威胁情报 | 安全策略 → 自定义情报 |
| 配置合法流量白名单 | 安全策略 → 检测白名单 |
| 配置响应白名单 | 响应处置 → 响应白名单 |
| 创建自动响应策略 | 响应处置 → 自动响应策略 |
| 配置第三方联动 | 响应处置 → 联动设备配置 |
| 配置通知方式 | 系统管理 → 数据配置 |
| 检查设备健康 | 系统管理 → 设备自检 |

## 10. 常见问题

### 10.1 为什么没有看到告警？

可以按以下方向排查：

1. 确认镜像流量是否接入全悉采集口。
2. 查看「系统管理 → 系统设置 → 运行状态」中的网口流量曲线。
3. 检查内置规则、自定义规则是否启用。
4. 检查检测白名单是否误放行了目标流量。
5. 使用「流量元数据 → 数据检索」确认是否有相关协议流量入库。

### 10.2 为什么旁路阻断没有生效？

可以按以下方向排查：

1. 确认阻断网口到访问者网络连通可达。
2. 确认被阻断流量是 TCP 流量。
3. 检查目标 IP 是否在响应白名单中。
4. 查看「响应处置 → 旁路阻断记录」是否生成记录。
5. 检查阻断策略是否已启用且未过期。

### 10.3 如何减少误报？

建议按以下顺序处理：

1. 在告警详情中确认攻击描述、原始报文和载荷解码。
2. 对确认为合法业务的流量加入检测白名单。
3. 对不应被阻断的关键 IP 加入响应白名单。
4. 对频繁误报的规则，评估后调整规则启停或自定义等级。

## 11. 推荐操作闭环

```text
看态势 → 筛告警 → 查详情 → 做溯源 → 处置阻断/白名单 → 验证结果 → 生成报告
```

首次上线建议优先建立以下闭环：

1. 资产分组和重要性等级配置完整。
2. 超危、高危、失陷、成功告警有固定筛选场景。
3. 告警处置前先确认响应白名单。
4. 自动响应先使用暂存处置模式。
5. 每日输出告警处置结果，每周复盘聚合趋势和策略效果。

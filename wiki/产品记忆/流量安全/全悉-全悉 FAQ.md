## 全悉开局调优

**相似问题**：全悉降噪、提高告警准确性、资产配置

为了提高检测的准确性，我们的规则和攻击方向紧密相关，比如挖矿通信检测，我们对于矿池扫描和外连矿池检测两种类型攻击事件检测的payload实际上是一样的，但是如果攻击方向不一样，对应的攻击类型就不一样，定义资产实际上就是标识出真正的内网地址，从而确定攻击方向；因此我们建议是系统上线之后为了保证告警检出率和准确性，最好是把真正的内网资产录入到系统，因为有一些用户内部使用的地址就是公网地址，默认情况下就会认为这种攻击是外对外的攻击，但实际上可能是内对内，这种情况下我们的规则就不会去匹配，所以就会出现漏报。全悉资产配置对检测的影响举例：比如一段矿池通讯流量，可能是攻击者的公网服务器扫描，也可能是客户内网主机被植入挖矿木马后的外联行为。需要通过资产配置来区分 "外对内" 与 "内对外" 这两种情况。其余一些Web漏洞攻击、C2工具通信也是类似的。我们只想要检测某一个方向的攻击流量，所以需要提前配置资产

## 全悉告警存包数量

告警存包多少个：TCP会话存触发告警之前的所有包，触发告警之后存100个包；UDP会话存触发告警之后的100个包。

## 全悉告警没有pcap问题

告警没有pcap包问题：由于统计类、分析类、事件类告警存在跨会话、时间窗口长的特点，对存储空间消耗较大，存包逻辑复杂，所以目前不会存包，如账号爆破、弱口令、扫描、Kerberos相关告警等等这部分告警目前不会存包

## 弱口令检测逻辑

弱口令判断【解码相关操作：url、base64】1、弱口令字典：包含明文弱口令、明文弱口令的md5、sha1、sha256   2、密码复杂度计算，关联用户名计算进行密码复杂度，复杂度计算数据源：字典、日期等。目前支持FTP, SMTP, TELNET, POP3, IMAP, HTTP, HTTPS, MQTT, MYSQL, PGSQL, VNC, REDIS弱口令检测

## 告警结果研判逻辑

全悉结果判定逻辑：
【企图】：无法根据请求、响应及相关日志判断攻击结果的情况
【成功】：根据请求、响应及相关日志判定攻击结果。同事务流：1、看payload中的命令，以及响应中是否存在对应结果返回  2、某些漏洞利用后的特定返回，如报错，特定字符传等   3、某些攻击的返回     跨事务跨流：1、受害主机是否请求payload中的地址
【失陷】导致主机失陷的攻击成功行为，如webshell、c2等
【失败】：根据响应判断攻击失败，如页面不存在，状态码404等

## 加密流量检测方案支持情况

**相似问题**：加密流量解密方案、恶意加密流量检测方案、全悉旁路解密能力

1. 针对于业务自身加密，目前TLS/SSL加密主流使用RSA和ECDHE两种密钥协商算法，我们提供三种解决方案可基本实现所有业务加密流量的解密：
- 针对RSA算法：可在全悉设备直接导入加密私钥，可对TLS1.2 及之前版本协商方式为 RSA 的加密流量进行解密检测。
- 针对ECDHE密钥交换算法：
- 通过长亭waf，代理模式下卸载HTTPS证书，可实现TLS1.3全协议以及TLS1.2(或更早版本)中使用DH算法的加密流量进行解密，并将卸载后的明文流量发送给全悉设备，达到增强旁路安全设备检测能力的效果。
- 通过在终端主机部署agent，获取加密密钥，可实现TLS1.3全协议以及TLS1.2(或更早版本)中使用DH算法的加密流量进行解密（windows环境当前无技术方案支持）
- 全悉agent方案针对ECDHE算法加密流量解密大致原理：在主机侧部署agent，通过hook到服务端openssl库，获取到每一笔会话协商后的密钥字符串发送给全悉检测平台，然后依据每笔会话的密钥字符串实现对应会话解密。
2. 针对于攻击流量加密：
- 全悉通过对加密流量的指纹特征、网络行为、证书交互、包大小特征、包时序特征、载荷字符特征、攻击工具特征以及人际交互行为特征等关键要素建立特征集合，利用人工智能算法构建智能分析判别模型，同时关联异常事件，能够在加密流量不解密的场景下，实现对恶意加密流量进行检测。
- 当前支持恶意加密流量如下：
- 加密反弹shell（reverseshell）检测：
- 在某客户流量环境中统计的reverseshell攻击检测，误报率0.011%（3/28021）、0.047%（30/645160），漏报率0.64%（3/470）、0.20%（1/499）
- 隐匿隧道检测：
- 支持icmptunnel、ptunnel、icmpsh、Nishang、Allin等ICMP隐匿隧道的检测
- 支持CobaltStrikeDNS上线、dns2tcp、iodine、dnscapy、dnsteal、DnsShell、OzymanDNS等DNS隐匿隧道的检测
- 支持ABPTTS、reGeorg、reDuh、Neo-reGeorg、Chisel等http隐蔽隧道检测
- 黑客工具的恶意加密通信检测：
- CobaltStrike、Matesploit、Antsowrd、Behinder...
- CobaltStrikeRSA加密上线检测
- msfmeterpreterHTTP、TCP通信检测，msf/vipermeterpreterrc4、uuid等加密HTTP、TCP通信检测
- Empireaes/rc4加密上线检测
- Behinder（V1.0-4.0）xor/xor_base64/aes/json/image加密webshell命令执行
3. 常用的密钥算法
  a. 密钥交换算法 ：RSA、DH、DHE、ECDHE
  b. 非对称加密算法 ：RSA、DSA、ECDSA
  c. 对称加密算法：DES、3DEC、AES_128_GCM、AES_128_CCB、AES_256_GCM、AES_256_CBC
  d. 哈希算法：MD5、SHA1、SHA256、SHA384

## 全悉产品组成说明

**相似问题**：全悉产品介绍

1、Agent流量采集探针：
功能：云上ECS主机网卡流量采集，并将流量转发给全悉检测平台
部署位置：ECS宿主机
应用场景：客户需要对云内东西向流量进行检测的场景可以部署agent进行流量采集

功能：对多个检测平台（探针）进行集中运维，包括对探针状态监测、日志集中分析、策略集中管理、规则库集中升级等

应用场景：客户有多个节点需要部署检测探针且需要统一集中运维的分布式部署场景

## 全悉针对HTTP攻击无法检测

1. 检查资产配置是否正确，是否有公网地址私用情况，且没有将这部分业务IP添加为资产。
2. 排查是否为正常HTTP业务报文。从安全视角看，HTTP非规范报文业务层面无法交互，对业务实际无危害，我们的检测逻辑上是需要能正常交互及解析的HTTP报文才会进入检测流程，一定程度上说我们实际还提高了告警的准确性。（判断是否为正常HTTP报文可自行大模型问一下）
3. 以上排查完无果可以提交样本给安全研发师傅研判。

## 全悉基于流量的被动漏洞识别功能逻辑

**相似问题**：全悉漏洞识别、全悉应用识别、全悉应用风险

全悉基于流量的资产漏洞识别逻辑：
1. 首先全悉会基于丰富的应用指纹库对流量中的资产应用以及应用版本进行识别发现
2. 在识别到应用版本后会根据对应的版本与长亭漏洞知识库的漏洞进行匹配，从而发现应用可能存在的漏洞风险。

特殊说明：该方法原理为指纹和漏洞库的被动匹配，仅能发现资产可能存在的漏洞，如果漏洞已经打了补丁的场景仍然会被识别出来。

## 全悉数据存储使用的加密技术和校验技术

- 存储上传的证书数据使用了：AES cbc 256位对称加密算法。
- 返回的告警数据ID字段使用了：RC4加密算法。
- 安装校验文件使用了：MD5 32位算法
- 密码使用bcrypt算法对密码进行哈希加密（Bcrypt是一种用于密码哈希的加密算法，它是基于Blowfish算法的加强版，被广泛应用于存储密码和进行身份验证）

## 用户开了双因子以后，令牌丢失（如换手机了）等问题

**相似问题**：双因子令牌丢失如何解决

如果有客户忘记了双因子认证的令牌需要操作数据库进行重置。
修改方法：进入设备后台，执行以下命令（PS：以下命令按每行顺序复制执行就行）
- docker exec -it db bash
- psql -U hera
- BEGIN;
- UPDATE public."user"
- SET tfa_enabled = false
- WHERE username = 'admin';
- UPDATE public.user_auth
- SET deleted_at = timezone('utc', now())
- WHERE user_id = (
SELECT id FROM public."user" WHERE username = 'admin'
)
- AND type = 'totp'
- AND deleted_at IS NULL;
- COMMIT;

## 全悉白名单配置，关于 域名 和 URL 配置说明

白名单中 URL 配置项说明：
1. 该项分成两个部分，域名 和 Path
2. 域名配置：
  a. 该处填写 HTTP 中的 hostname 字段，该字段在告警的‘原始数据’页面中‘app_proto’的hostname；
  b. 举例：例如 hostname 是  aaa.bbb.ccc:1234
  i. 完全匹配： 则需要填写  aaa.bbb.ccc:1234 ，需要填写后面的端口，不能省略
  ii. 模糊匹配：aaa.bbb.ccc* 、 aaa.*.ccc*、*bbb*
3. Path 配置：
  a. 该处填写 HTTP 中的路径部分，该字段在告警的‘原始数据’页面中‘app_proto’的url；
  b. 举例：例如 url 是 /guest_auth/guestIsUp.php
  i. 完全匹配：填写 /guest_auth/guestIsUp.php 或者  guest_auth/guestIsUp.php，第一个 / 可以省略
  ii. 模糊匹配：支持1个或多个*号，/gu*t_auth/g*tIsUp.php、/gu*tIsUp.php

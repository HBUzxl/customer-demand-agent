## 2. 使用前调优

### 2.1 重要事项：资产配置须重点确认

重要的事情说三遍：资产！资产！还是资产！

原因：目前全悉的检测和资产息息相关，对于不同的方向存在不同的策略。如语义检测仅针对外对内和内对内（流方向）、矿池连接检测仅针对内对外。

#### 2.1.1 如何确定资产是否添加

- 将公网私用的资产，添加到全悉资产页面【这一步非常重要，影响检测效果】

- 在 资产中添加 0.0.0.0 /0，筛选出 direction =
  'other'的情况，和业务方确定源和目的IP哪方是资产，将资产记录（整个 C
  段）。待统计的差不多时，将资产0.0.0.0/0删除，添加记录资产。

### 2.2 XFF 配置（按需配置）

设备可能接入流量为代理或者CDN后，配置合理的XFF配置，可以识别真实的攻击者，在防火墙或者CDN上增加阻断策略。

![](images/全悉实操手册-image1.png)

### 2.3 减少误报

告警加白原则：最小粒度

1.  避免安全设备上报日志的行为产生告警

问题：在有些时候，安全设备产生的日志上报soc的行为会再次触发安全设备的检测，从而生成告警日志、上报告警日志的死循环。

解决方案：当发现如上情况，可以将日志接收端IP+端口加入到白名单中，减少无效日志的干扰。

2.  语义引擎触发的误报

如何判断是语义引擎触发的告警：检测规则以m_开头，告警名称中带语义分析

问题：业务中传输SQL语句或者JavaScript脚本时，可能会触发语义分析的相关告警，这时候需要将这部分告警做加白处理。

解决方案：加白，加白条件：目的IP+端口+URL+对应规则，根据实际情况做相关调整。

3.  规则或模型触发的误报

如何判断是规则或模型触发的告警：检测规则为数字或以k_开头

问题：可能由于规则、模型不严谨，流量比较特殊，导致触发规则或者模型的误报。

解决方案：最小颗粒度进行加白，建议增加条件，加白时间，后续更新后规则继续生效，并可选择将告警的原始数据和PCAP反馈给研发做进一步分析。

4.  威胁情报产生的误报

如何判断是威胁情报产生的告警：检测规则以Ti开头

问题：可能由于第三方情报源质量问题，导致触发威胁情报的误报。

解决方案：加白，加白条件：直接将对应规则进行加白

## 3. 产品实操使用

### 3.1 告警监控

1.  进入‘威胁事件’-‘威胁告警’模块，会按时间序列由近到远展示全悉检测到的告警条目，如果数量比较多，可以点击【事件合并】按钮，会基于威胁名称、攻击IP、受害IP、攻击阶段做自动聚合，大幅降低威胁事件条数。

![](images/全悉实操手册-image2.png)

2.  告警监控的时候可以通过更改自动刷新的频率，来实时刷新最新告警

![](images/全悉实操手册-image3.png)

3.  可以通过“简单筛选”根据时间范围、攻击IP、受害IP、威胁类型、威胁等级、攻击结果、攻击阶段等条件来筛选想要查看的告警范围

![](images/全悉实操手册-image4.png)

4.  除了通过固定条件筛选方式，全悉还支持“高级检索”方式，可以支持多条件组合筛选的方式对威胁事件进行精确筛选。

![](images/全悉实操手册-image5.png)

5.  当警报数量较多时，可以使用“聚合模式”对告警数据进行聚合处理，聚合模式下的告警可以根据攻击IP、受害IP、源IP威胁类型、威胁名称做聚合，在首次聚合完之后对于聚合数据可以根据攻击IP、受害IP、源IP、威胁类型、威胁名称再做二次聚合，进一步提高数据聚焦度。

![](images/全悉实操手册-image6.png)

#### 3.1.1 告警检索模板设定

产品使用期间全悉产品可能产生大量告警，为了从大量告警日志中快速检索到有价值告警事件，可以通过告警条件组合的方式筛选出有价值告警事件

使用方式：在告警检索里提前配置好检索条件并保存，可以根据保存的条件快速进行过滤筛选。![](images/全悉实操手册-image7.png)

##### 3.1.1.1 常用筛选条件

以下列举一些常见的使用场景的筛选条件，以下条件可自由组合。

注：为了使得条件精准生效，拼接各个场景条件时尽量用括号包裹。

###### 3.1.1.1.1 仅关注外网攻击成功事件（流方向：内 \<--\> 外）

(direction = 'in' OR direction = 'out') AND result = 'success'

###### 3.1.1.1.2 所有成功事件或中高超危事件（流方向：any）

(result = 'success' OR (result != 'failed' AND severity \< 4))

###### 3.1.1.1.3 仅关注外网攻击成功事件或中高超危事件（流方向：内 \<--\> 外）

(direction = 'in' OR direction = 'out') AND (result = 'success' OR
(result != 'failed' AND severity \< 4))

###### 3.1.1.1.4 过滤内部扫描器

根据实际情况过滤内部扫描器产生的告警，假设内部扫描器ip为 scanner_ip_i 。

(attacker != "scanner_ip_1" AND attacker != "scanner_ip_2" AND attacker
!= "scanner_ip_3")

###### 3.1.1.1.5 代理工具相关告警

tag = "正向代理" OR tag = "反向代理"

###### 3.1.1.1.6 WebShell 相关告警

tag like "webshell" AND result != 'failed'

###### 3.1.1.1.7 威胁情报相关告警

sid like "Ti\_"

###### 3.1.1.1.8 C2 相关告警

tag = '木马通信'

### 3.2 威胁告警研判

#### 3.2.1 流量告警

1.  对高可疑事件，可以点开告警详情，查看一条告警的具体信息

![](images/全悉实操手册-image8.png)

![](images/全悉实操手册-image9.png)

2.  优先关注攻击结果为"失陷"与"成功"的告警事件

（a）根据“威胁名称”了解当前告警类型，重点关注命令注入、代码注入、WebShell、远控木马等告警类型

（b）根据“攻击描述”字段信息了解威胁详情以及引擎对当前告警的自动判断结果，例如:

-   WebShell连接:连接的WebShell名称，攻击载荷的解码提取结果

-   文件上传:上传的文件名称

-   代码执行:攻击者使用的漏洞、想要执行的命令，命令执行结果

若存在自动提取告警成功结果，则可以直接将该条告警作为攻击成功事件上报。

（c）没有明确判断结果时，根据不同协议进行后续分析判定

- HTTP协议

![](images/全悉实操手册-image10.png)

查看原始报文中请求报文的高亮部分是否为异常数据，若该段数据经过加密或者编码，可以参考载荷封装中解码后的Payload信息，判断是否为恶意操作；查看原始报文的响应报文的高亮部分是否为攻击结果（例如命令执行结果、文件读取结果），若是则将该条告警作为攻击成功事件上报。

- 非HTTP协议

![](images/全悉实操手册-image11.png)

使用数据包解码标签，查看Packet
Bytes中是否存在与告警名称匹配的异常数据与异常结果，若存在则将该条告警作为攻击成功事件上报。

3.  其次关注攻击结果为"企图"的告警事件

（a）根据威胁名称了解当前告警类型以及告警详情，了解告警原因

（b）查看原始报文是否携带载荷，若不存在载荷则忽略该条告警。

（c）没有明确判断结果时，根据不同协议进行后续分析判定

4.  最后关注攻击结果为"失败"的告警事件

（a）根据威胁名称与攻击描述字段信息了解威胁类型以及引擎判断当前告警为失败的原因。

（b）根据失败原因去原始报文中验证，例如攻击描述字段中说明
"当前页面/路由不存在，所以此次攻击结果为失败",
就去原始报文的响应报文中确认响应页面是否为真实的页面不存在页面。

（c）经过验证后确定该条攻击失败，就忽略该条告警。

当多次收到相同地址IP的告警，并且可以判定为误报，可以对当条告警加白处理。

![](images/全悉实操手册-image12.png)

![](images/全悉实操手册-image13.png)

##### 4.2.1.2 使用 HTTP

域前置的Host字段使用的域名一般有两种情况：

1.  使用厂商自身的CDN域名（少见）

2.  利用CDN厂商校验不严的漏洞，使用其他高信誉域名的**未注册的**子域名。（常用）

对于常见的第二种情况，可以用一下步骤排查

1.  查看攻击者IP是否为CDN服务器。

![](images/全悉实操手册-image39.jpg)

*（标记为IDC服务器）*

![](images/全悉实操手册-image40.jpg)

*（有大量域名解析到该IP）*

2.  查看host对应的域名是否有A记录、NS记录。

一般CDN厂商会通过CNAME记录接管域名，而已有域名解析的域名需要先解除之前的绑定记录才能使用CDN服务，否则将造成DNS污染。

**故域前置的域名一般为未注册的子域名。**

![](images/全悉实操手册-image41.jpg)

*（正常的DNS服务器无法解析该域名）*

3.  寻找 CDN 厂商域名服务器

    1. 随便选择一个使用该 CDN 的域名：

![](images/全悉实操手册-image42.jpg)

> *(随便选择一个使用该CDN的域名)*

    2. 通过 dig 命令找到 CDN 厂商的 CNAME 记录：

一般格式为 \<domain\>.cdn.server.com

例子：

www.baidu.com.wsdvs.com.

starself.abcd.cc.a.bdydns.com.

![](images/全悉实操手册-image43.jpg)

> *（通过dig命令找到CDN厂商的CNAME记录）*

4.  将 Host 字段中的域名给到 CDN 厂商的 DNS 服务器解析，若出现 CNAME 记录则为域前置。

![](images/全悉实操手册-image44.png)

*（出现CNAME记录，指向CDN服务器）*

可以输入一个不存在的域名验证，避免CDN厂商将所有的子域名都记录CNAME

![](images/全悉实操手册-image45.png)

*（查询不存在域名，只有SOA记录，无CNAME记录）*

# 软件反代复杂集群版安装手册
**确保已完成[部署前准备](../0.部署前准备/1.部署前准备.md)中的所有操作，否则会导致安装失败**
## 操作流程
### 网络环境要求
1. 管理节点与检测节点网络打通，如果有网络规则限制，则必须满足如下最基础连通性
   - 允许检测节点到管理节点的 TCP 9443 端口访问（上传检测节点信息到管理服务）
   - 允许检测节点到日志节点的 TCP 3334 端口访问（上传日志到日志节点进行聚合操作）
   - 允许日志节点到管理节点的 TCP 5432 端口访问（上传日志到管理节点进行存储）
   - 允许日志节点到管理节点的 TCP 9200 端口访问（上传日志到管理节点进行存储）
   - 允许检测节点到管理节点的 TCP 6379 端口访问（上传检测信息到管理服务）
2. 浏览器所在机器需要能访问所有 WAF 节点的 TCP 6767 端口


### 管理节点
由于一般集群部署模式下，管理节点同时承担着日志处理的功能，在大集群场景下，可能存在管理节点资源不够的情况，此时可以将日志服务部署在单独的计算节点，以提升性能。
1. 初始化管理节点部署模式：`minion setup -p /data/safeline -t S20Management`
   - 如果需要使用国产化数据库(kingbase 东方通，highgo 瀚高)，则命令需要替换为：`minion setup -p /data/safeline -t Software --database-engine highgo`，可选参数包含 `highgo`，`kingbase`。**注意，不允许在选择国产化数据库后，不重置模式进行数据库切换，否则会导致存储数据异常；国产化数据库只在 23.01.009 版本及之后版本支持，请勿在非支持版本执行此命令**
   - 如果需要使用国产化内存 kv 存储（redis），则需要增加 `--redis-engine` 参数，可选项有（`tong_rds`），`minion setup -p /data/safeline -t Software --redis-engine tong_rds`**注意，不允许在选择国产化 KV 存储后，不重置模式进行 KV 存储切换，否则会导致存储数据异常；国产化KV 存储只在 25.03.001 版本及之后版本支持，请勿在非支持版本执行此命令**
   - 如果需要部署多租户模式，则命令需要调整为`minion setup -p /data/safeline -t S20Management --tenant`**注意，多租户模式在 21.03 版本后就不再支持，请不要在 21.03 版本以后执行多租户部署安装**
2. 记录步骤 1 中输出的下列信息，需要在部署「日志节点」「检测节点」时填入
   - Postgres Password（数据库密码）
   - Minion API Token（节点间通信 Token）
   - Bot Js Module Location（Bot 功能相关文件）
   - Minion Cert（节点间通信证书）
![步骤一输出信息示例](../images/快速开始_images/s20management-setup.png)
1. 通过 6767 部署页面进行服务删除
   - 执行 `minion setup -p /data/safeline`
   - 浏览器访问`http://管理节点 IP:6767`
   - 在「方案配置方式」页面选择「编辑本机部署」，并点击「下一步」
   - 删除「流量检测服务」「流量转发服务」「日志采集服务」「日志聚合服务」「日志分析服务」，并点击下一步
   - 点击「点击部署」选项，并点击「完成」
2. 启动基础平台服务：`systemctl start minion`
   - 当 WAF 版本小于 22.09.001 并且大于 22.01.001_preview 版本时，需再多执行一次`systemctl start minion-upgrader`命令
3. 检查 WAF 各服务启动状态，当所有服务的 `status` 值都为 `up`，并且没有`unhealthy`出现时，证明安装成功
4. 浏览器打开 https://当前机器 IP:9443 页面，上传产品证书，登录后打开「系统信息-节点状态」页面，查看节点是否正常


### 日志节点（包含至少 3 ETCD 节点）
**注意，此日志节点类型需要搭配「检测节点（包含至少 3 ETCD 节点）」使用，不适用于其他类型检测节点**
1. 设置节点 hostname（需要保证节点名称在 WAF 集群内保持唯一，否者会导致节点连接失败）
2. 初始化管理节点部署模式：`minion setup -p /data/safeline -t S20Logging`
   - **注意：当需要输入 Management Address with Port and Protocol（管理节点访问地址）时，需要输入的内容为`https://管理节点 IP:9443`**
   - **如果保存的管理节点部署信息不慎丢失，可以通过如下命令在管理节点重新获取**
     - Postgres Password：`minion db get /minion/v1/services/postgres_password`
     - Minion API Token：`minion db get /minion/v1/services/minion_api_token`
     - Bot Js Module Location：`minion db get /minion/v1/bot_js_location`
     - Minion Cert：`cat /data/safeline/resources/management/certs/minion.crt | awk '{printf "%s\\n", $0}';echo`
3. 通过 6767 部署页面进行服务配置
   - 执行 `minion setup -p /data/safeline`
   - 浏览器访问`http://日志节点 IP:6767`
   - 在「方案配置方式」页面选择「编辑本机部署」，并点击「下一步」
   - 编辑 「通用变量中」中的「本机对外 IP 地址」为：`当前节点 IP 地址`
   - 编辑「日志分析服务」中的「ETCD 地址」为：`日志节点 IP:2379`，如果有多个日志节点，则需要以回车作为分隔符，输入多个数据。**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
   - 编辑「日志分析服务」中的「集群模式下对外广播地址」为：`当前节点 IP:3335`**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
   - 编辑「日志分析服务」中的「数据库地址」为：`postgres://safeline:数据库密码@管理节点 IP:5432/safeline?sslmode=disable`
   - 编辑「日志分析服务」中的「es urls」为：`http://管理节点 IP:9200`
   - 编辑「日志汇聚服务」中的「ETCD 地址」为：`日志节点 IP:2379`，如果有多个日志节点，则需要以回车作为分隔符，输入多个数据。**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
   - 编辑「日志汇聚服务」中的「集群模式下对外广播地址」为：`当前节点 IP:3334`**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
   - 选择「新增服务」，增加「Etcd」服务，并修改「Etcd 集群地址列表」为：`日志节点 IP`（注意没有端口号），如果有多个日志节点，则需要以回车作为分隔符。**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
   - 点击「点击部署」选项，并点击「完成」
4. 启动基础平台服务：`systemctl start minion`
5. 浏览器打开 https://管理节点 IP:9443 页面，打开「系统信息-节点状态」页面，查看检测节点是否正常上线，并且状态为「健康」

### 日志节点（包含 1 ETCD 节点）
1. 设置节点 hostname（需要保证节点名称在 WAF 集群内保持唯一，否者会导致节点连接失败）
2. 初始化管理节点部署模式：`minion setup -p /data/safeline -t S20Logging`
   - **注意：当需要输入 Management Address with Port and Protocol（管理节点访问地址）时，需要输入的内容为`https://管理节点 IP:9443`**

3. 通过 6767 部署页面进行服务配置

   - 浏览器访问`http://日志节点 IP:6767`

   - 编辑「日志分析服务」中的「ETCD 地址」为：`ETCD 服务所在节点 IP:2379`。**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**

   - 点击「点击部署」选项，并点击「完成」


### 检测节点（包含至少 3 ETCD 节点）
1. 设置节点 hostname（需要保证节点名称在 WAF 集群内保持唯一，否者会导致节点连接失败）
   - **如果通过 hostnamectl 设置名称，设置完成后需要重启系统，否则名称更新不会生效**
2. 初始化部署模式：`minion setup -p /data/safeline -t S20Agent`，输入保存的管理节点部署信息
   - **注意：当需要输入 Management Address with Port and Protocol（管理节点访问地址）时，需要输入的内容为`https://管理节点 IP:9443`**
   - **如果保存的管理节点部署信息不慎丢失，可以通过如下命令在管理节点重新获取**
     - Postgres Password：`minion db get /minion/v1/services/postgres_password`
     - Minion API Token：`minion db get /minion/v1/services/minion_api_token`
     - Bot Js Module Location：`minion db get /minion/v1/bot_js_location`
     - Minion Cert：`cat /data/safeline/resources/management/certs/minion.crt | awk '{printf "%s\\n", $0}';echo`
![检测节点安装输入示例](../images/快速开始_images/s20agent-setup.png)
3. 通过 6767 部署页面进行服务配置
   - 执行 `minion setup -p /data/safeline`
   - 浏览器访问`http://日志节点 IP:6767`
   - 在「方案配置方式」页面选择「编辑本机部署」，并点击「下一步」
   - 编辑「流量检测服务」中的「ETCD 地址」为：`http://ETCD 所在节点 IP:2379`，如果有多个节点，则需要以回车作为分隔符，输入多个数据。**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
   - 编辑「流量检测服务」中的「集群模式注册本机地址端口」为：`本机对外 IP:8001`（如果不需要更高精度限频可以不填）
   - 编辑「日志采集服务」中的「Aggregator HTTP 地址」为空
   - 编辑「日志采集服务」中的「Etcd 地址」为：`日志节点 IP:2379`，如果有多个日志节点，则需要以回车作为分隔符，输入多个数据。**注意此选项只在日志服务使用 ETCD 做服务发现时才进行配置**
4. 启动基础平台服务：`systemctl start minion`
   - 当 WAF 版本小于 22.09.001 并且大于 22.01.001_preview 版本时，需再多执行一次`systemctl start minion-upgrader`命令
5. 浏览器打开 https://管理节点 IP:9443 页面，打开「系统信息-节点状态」页面，查看检测节点是否正常上线，并且状态为「健康」

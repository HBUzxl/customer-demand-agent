## 1. 产品概述

### 1.1 什么是全悉

长亭全悉（T-Answer）高级威胁分析预警系统是长亭科技基于多年网络攻防实战经验打造的新一代 NDR（网络检测与响应）产品。产品将语义分析及大数据技术与网络攻防技术相结合，聚焦流量全面威胁感知，为用户提供**事前资产风险排查、事中威胁检测及研判、事后溯源及处置**能力。

### 1.2 核心定位

全悉以旁路镜像轻量级部署，实时对网络流量进行检测及采集存储，核心能力包括：

- **多层检测体系**：语义分析引擎 + AI引擎 + IDS规则引擎 + 杀毒引擎 + 沙箱行为分析 + Webshell专项引擎 + 威胁情报
- **全攻击链覆盖**：从侦查→入侵→载荷投递→命令与控制→横向渗透→达成目标→其它，7阶段完整检测
- **自动化响应处置**：旁路阻断 + 自动响应策略 + 联动设备阻断
- **资产自动发现**：基于流量自动识别资产，关联漏洞管理

### 1.3 适用场景

**表1.3-1 场景说明**
| 场景 | 说明 |
|------|------|
| 高级威胁检测 | 检测 APT、0day、未知威胁等传统安全设备无法发现的高级攻击 |
| 安全运营 | 通过告警聚合、自动化处置提升安全运营效率 |
| 护网行动 | 高检测覆盖率支撑攻防实战 |
| 合规监管 | 支撑等保2.0合规要求，提供审计日志和报告能力 |
| 资产管理 | 自动发现网络资产，关联漏洞风险，实现资产风险可视化 |

## 2. 快速上手

### 2.1 登录系统

1. 打开浏览器，输入全悉管理平台的访问地址（如 `https://<设备IP>`）
2. 输入用户名和密码
3. 点击「登录」按钮

![图2.1-1 登录页面整体](./images/图2.1-1_登录页面整体.png)

**注意事项：**
- 默认管理员账号为 `admin`
- 首次登录可能需要修改密码（系统强制要求）
- 如系统启用了 MFA（多因素认证），登录后需要绑定 TOTP 认证器

### 2.2 首次登录密码修改

首次登录或密码过期后，系统会强制跳转到密码修改页面：

1. 输入旧密码
2. 输入新密码（需满足密码策略要求：最小长度、大小写+数字+特殊字符）
3. 确认新密码
4. 点击「提交」

![图2.2-1 密码修改页面](./images/图2.2-1_密码修改页面.png)

### 2.3 MFA 多因素认证配置

如果系统要求启用 MFA，登录后会弹出 MFA 配置引导：

1. 使用 TOTP 认证器应用（如 Google Authenticator、Microsoft Authenticator）扫描二维码
2. 输入认证器显示的6位验证码
3. 点击「确认」完成绑定

> 以后每次登录都需要输入 MFA 验证码。

### 2.4 界面导航说明

登录成功后，进入全悉主界面：

![图2.4-1 主界面整体（含左侧菜单、顶部导航、内容区）](./images/图2.4-1_主界面整体.png)

### 2.5 角色与权限说明

全悉按角色和功能权限控制菜单可见性、按钮可操作性和数据访问范围。不同客户环境的授权范围、部署形态和账号角色不同，实际可见菜单以当前登录账号为准。

**表2.5-1 常见角色与适用场景**
| 角色 | 适用场景 | 常见可操作范围 |
|------|----------|----------------|
| 超级管理员 | 系统初始化、账号权限、系统配置、策略配置 | 可管理用户、系统配置、检测策略、响应策略、资产、报告和审计等全部功能 |
| 全局管理员 | 日常安全运营和平台配置 | 可执行多数运营与配置操作，部分高风险系统设置可能受限 |
| 操作员 | 告警研判、资产查看、报告生成、日常巡检 | 以查看、筛选、导出、处置类操作为主，通常不负责账号和系统级配置 |
| 审计员 | 合规审计、操作追溯 | 主要查看系统审计、报告和运行记录，通常不具备策略修改权限 |

**权限影响说明：**

- 菜单不可见：当前账号未被授予对应功能权限，或当前授权版本不包含该模块。
- 按钮置灰：当前账号可查看页面，但无新增、编辑、删除、导出、启停或下发权限。
- 数据为空：可能是无匹配数据、时间范围不正确、采集链路无流量、探针异常或当前账号无数据范围权限。
- 页面提示无权限：请联系管理员在「系统管理 → 用户管理」中检查角色和权限配置。

> 注意：涉及阻断、自动响应、联动设备、用户管理、系统重启/关机、清除数据等高风险操作，建议仅开放给经过授权的管理员账号。

### 2.6 通用异常处理

**表2.6-1 常见异常与处理建议**
| 异常现象 | 可能原因 | 处理建议 |
|----------|----------|----------|
| 无法登录 | 用户名或密码错误、账号被禁用、MFA 验证码错误、浏览器时间偏差 | 确认账号状态；重新输入验证码；必要时联系管理员重置密码或解除 MFA |
| 登录后要求修改密码 | 首次登录、密码过期或管理员强制重置 | 按密码策略设置新密码，完成后重新登录 |
| 看不到某个菜单 | 当前账号无权限、授权版本不包含、部署形态不支持 | 使用管理员账号确认权限；核对许可证和部署形态 |
| 页面无数据 | 时间范围过窄、筛选条件过多、采集链路无流量、探针离线 | 放宽时间范围；清空筛选条件；检查探针、镜像流量和系统运行状态 |
| 保存配置失败 | 必填项为空、格式不合法、名称重复、连接测试失败 | 按页面提示修正字段；确认 IP、端口、URL、邮箱、Token 等格式 |
| 导出或下载失败 | 数据量过大、浏览器拦截、后台任务失败 | 缩小时间范围；允许浏览器下载；到「任务中心」查看任务状态 |
| 通知未发送 | SMTP/IM/Syslog/Kafka 配置不正确、通知过滤条件未命中 | 先发送测试消息；检查通知范围、过滤条件、网络连通性和第三方服务状态 |

> 建议排查顺序：先清空筛选条件并扩大时间范围，再检查账号权限、系统运行状态、探针状态和外部系统连通性。

| 中危 | 中等威胁，需要排查确认 |
| 低危 | 低风险威胁，可持续观察 |

**攻击结果统计：**

**表3.1-2 攻击结果统计**

|------|------|
| 失陷 | 资产已被攻陷，需要立即处置 |
| 成功 | 攻击成功但尚未失陷 |

| 失败 | 攻击已失败 |

**表3.1-3 可视化模块一览**
| 模块 | 说明 |
|------|------|

| 威胁类型 Top10 | 威胁类型排名前10 |
| 威胁事件 Top10 | 具体威胁名称排名前10 |
| 攻击链路 | 7阶段攻击链（侦查→入侵→载荷投递→命令与控制→横向渗透→达成目标→其它）告警分布 |
| 攻击阶段分布 | 各攻击阶段饼图 |
| 攻击IP Top10 | 攻击最多的10个IP |
| 受害IP Top10 | 被攻击最多的10个IP |
| 攻击协议 Top10 | 攻击协议分布 |
| 黑客工具 Top10 | 使用最多的10种攻击工具 |
| 恶意文件统计 | 文件检测引擎检出类型分布（backdoor/webshell/exploit/virus等） |
| 阻断统计 | 阻断次数、阻断IP数量 |
| 阻断数量变化趋势 | 阻断数据折线图，支持切换「阻断IP数量」/「阻断次数」 |
| 阻断IP Top10 | 被封禁次数最多的10个IP |
| 阻断策略 Top10 | 触发阻断最多的10条策略 |

#### 4.1.2 高级筛选

![图4.1.2-1 威胁告警-高级筛选Tab整体页面（含输入框+搜索按钮+筛选场景按钮）](./images/图4.1.2-1_威胁告警-高级筛选Tab整体页面.png)

高级筛选提供类似SQL语句的自由查询方式，支持输入筛选表达式进行告警检索。

**输入框格式：**

`字段名 运算符 值 逻辑连接符 字段名 运算符 值 ...`

**示例：**

```
result = 'success' AND attacker = '192.168.0.1' AND (victim = '192.168.1.1-192.168.1.255' OR victim = '192.168.0.1/24')
```

**支持的字段（关键字）：**

**表4.1.2-1 支持的字段**
| 字段名 | 类型 | 说明 | 值示例 |
|--------|------|------|--------|
| src_ip | string | 源IP | `'192.168.1.1'` |
| dest_ip | string | 目的IP | `'10.0.0.1'` |
| src_port | int | 源端口 | `80` |
| dest_port | int | 目的端口 | `443` |
| attacker | string | 攻击IP（含CIDR/范围） | `'192.168.0.1/24'` |
| victim | string | 受害IP（含CIDR/范围） | `'192.168.1.1-192.168.1.255'` |
| app_proto | string | 应用层协议 | `'HTTP'` |
| proto | string | 协议 | `'TCP'` |
| sid | int | 规则SID | `12345` |
| tag | string | 威胁类型标签 | `'recon'` |
| phase | string | 攻击阶段 | `'recon'`（侦查）/`'intrustion'`（入侵）/`'delivery'`（载荷投递）/`'control'`（命令与控制）/`'lateral'`（横向渗透）/`'goal'`（达成目标）/`'other'`（其它） |

> 说明：高级查询使用系统内部字段值，`intrustion` 为当前版本保留的内部枚举值，对应界面中的“入侵”阶段。
| type | string | 攻击类型 | `'scanner'`/`'brute_force'`/`'webshell'`等 |
| result | string | 攻击结果 | `'control'`(失陷)/`'success'`(成功)/`'failed'`(失败)/`'unknown'`(企图) |
| severity | int | 威胁等级 | `1`(超危)/`2`(高危)/`3`(中危)/`4`(低危) |
| payload | string | 载荷内容 | `'恶意字符串'` |
| appbrief.req_body | string | HTTP请求体 | `'POST数据'` |
| appbrief.resp_body | string | HTTP响应体 | `'响应内容'` |
| appbrief.req_headers | string | HTTP请求头 | `'Cookie: xxx'` |
| appbrief.resp_headers | string | HTTP响应头 | `'Content-Type: xxx'` |
| appbrief.url | string | URL路径 | `'/admin/login'` |
| appbrief.method | string | HTTP请求方法 | `'GET'`/`'POST'` |
| appbrief.status | string | HTTP状态码 | `'200'`/`'404'` |

**支持的运算符：**

**表4.1.2-2 运算符**
| 运算符 | 说明 | 示例 |
|--------|------|------|
| `=` | 精确匹配 | `severity = 1` |
| `!=` | 不等于 | `result != 'failed'` |
| `>` | 大于（数值类型） | `src_port > 1024` |
| `<` | 小于（数值类型） | `dest_port < 100` |
| `like` | 模糊匹配（字符串需带引号） | `name like 'SQL%'` |
| `not_like` | 不模糊匹配 | `name not_like '扫描%'` |
| `in` | 在列表中 | `severity in (1, 2)` |
| `not_in` | 不在列表中 | `result not_in ('failed', 'unknown')` |
| `is` | 特殊值判断 | `src_pub is null` |

**特殊值：**

**表4.1.2-3 特殊值**
| 值 | 说明 |
|----|------|
| `null` | 字段为空 |
| `not_null` | 字段不为空 |
| `true` / `false` | 布尔字段值 |

**逻辑连接符：**

**表4.1.2-4 逻辑连接符**
| 连接符 | 说明 |
|--------|------|
| `AND` | 条件同时满足（优先级高于OR） |
| `OR` | 条件满足其一 |

**括号：** 支持 `()` 进行条件分组。

**输入规则：**
- 字符串类型的值需要用英文单引号 `'` 或双引号 `"` 包裹
- 数值类型的值直接输入数字
- IP支持CIDR格式（如 `192.168.0.1/24`）和范围格式（如 `192.168.1.1-192.168.1.255`）
- 输入时系统实时校验语法正确性，校验通过后搜索按钮可点击
- 支持通过输入框右侧的筛选场景按钮保存/加载高级筛选条件

离线检测包含三个标签页：**pcap检测**、**流量抓包**、**威胁信息**。

**pcap检测：**

**操作步骤：**

**表4.3-1 pcap检测模式说明**
| 检测模式 | 说明 |
|----------|------|
| 还原时序模式 | 以 pcap 文件的原始流量记录时间为准，告警时间为原始时间，保持原始时序 |
| Real Time 模式（保持时序） | 以第一个报文时刻为基准保持时序，后续报文累加时间差。若 pcap 持续时间较长，可能出现告警时间为未来时刻 |
| Real Time 模式 | 以第一个报文时刻为基准，告警时间为程序处理时间，不保持报文时序，对部分威胁类型（如反弹 Shell）检测结果可能有影响 |

![图4.3-3 离线检测-流量抓包Tab整体页面](./images/图4.3-3_离线检测-流量抓包Tab整体页面.png)

**操作步骤：**

**表4.3-2 流量抓包配置项**
| 配置项 | 说明 |
|--------|------|

| 节点 | 选择需要抓包的采集节点 |

| 抓包时长限制 | 10s / 20s / 30s / 40s / 50s / 60s / 无期限 |

| 过滤方式 | 规则模式（IP+端口）或 BPF 过滤语法 |

| 协议 | TCP / UDP / 其它（规则模式下可选） |
| 是否立即启动 | 开关，开启后创建任务即自动启动 |

> BPF 过滤规则示例：`ip host 172.16.0.1`（监听指定IP）、`port 443`（监听指定端口）、`ip src host 172.16.0.1 and port 443`（监听指定源IP和端口）。

### 6.2 自定义规则

> 安全策略 → 自定义规则标签页


支持使用 Suricata 兼容语法创建自定义检测规则。

**规则创建：**

1. 点击「添加规则」
2. 输入 Suricata 兼容语法的规则内容
3. 系统自动验证规则语法
4. 确认无误后点击「保存」

**语法要素：**
- 规则头：`alert <protocol> <src_ip> <src_port> -> <dst_ip> <dst_port>`
- 规则选项：`msg`, `sid`, `rev`, `content`, `pcre`, `http_uri`, `http_header` 等
- HTTP检测字段：18个HTTP字段

**管理操作：** 启用/禁用、编辑、删除、批量导入。

**表6.2-1 自定义规则字段说明**
| 字段 | 是否必填 | 填写说明 |
|------|----------|----------|
| 规则内容 | 是 | 填写 Suricata 兼容语法规则，保存前需通过语法校验 |
| SID | 是 | 使用系统允许的自定义 SID 范围，避免与内置规则冲突 |
| 规则名称/消息 | 是 | 通过 `msg` 描述规则用途，建议包含业务或威胁名称 |
| 威胁等级 | 建议填写 | 用于告警分级和后续筛选处置 |
| 状态 | 是 | 新规则建议先禁用或在低风险时间窗口启用验证 |

**异常处理：**

- 规则保存失败：检查语法、SID 范围、引号、括号和分号是否正确。
- 规则不生效：确认规则处于启用状态，且测试流量确实经过全悉采集链路。
- 告警量异常升高：立即停用该规则，缩小匹配条件后再启用。

### 7.2 旁路阻断策略

> 响应处置 → 旁路阻断策略


![图7.2-1 旁路阻断策略-整体页面](./images/图7.2-1_旁路阻断策略-整体页面.png)

**旁路阻断 TIPS（注意事项）：**

1. 旁路阻断务必保证旁路阻断网口到访问者网络连通可达，否则阻断功能无法正常使用
2. 旁路阻断为 TCP RESET 技术，仅针对 TCP 报文有效，UDP、ICMP 等协议报文无法阻断
3. 阻断策略上限建议不超过100,000条
4. 当前版本旁路阻断功能与检测流程无直接联系，部分流量可能因阻断而未被解析检测
5. 旁路阻断支持二层阻断、三层阻断，默认为三层阻断

**阻断口配置：** 页面顶部显示当前三层阻断，点击「更改接口配置」可修改。

**策略筛选：** 到期时间、策略ID、自动响应策略ID、名称。

**策略创建：**

![图7.2-5 旁路阻断策略-添加策略Drawer](./images/图7.2-5_旁路阻断策略-添加策略Drawer.png)

1. 点击「添加策略」
2. 配置阻断目标（源IP/目的IP/网段）和阻断时长
3. 点击「保存」

**策略列表字段：** 策略ID、策略名称、阻断对象、自动响应策略、备注、到期时间、创建时间、策略状态、操作。

**顶部操作：** 「导出全部策略」、「添加策略」。

**阻断时长模式：**
- **时长模式**：以秒/分钟/小时/天为单位
- **失效时间模式**：设置绝对的失效时间点

**策略启停：** 启用→命中立即执行阻断；禁用→暂停阻断；删除→永久删除。

**表7.2-2 阻断策略字段说明**
| 字段 | 是否必填 | 填写说明 |
|------|----------|----------|
| 策略名称 | 是 | 建议包含事件编号、攻击源或业务场景，便于追溯 |
| 阻断对象 | 是 | 填写源 IP、目的 IP、网段或页面支持的阻断目标，避免使用过大范围 |
| 阻断时长/失效时间 | 是 | 临时事件建议设置明确失效时间，避免长期误阻断 |
| 备注 | 否 | 记录处置原因、审批人、关联告警或工单编号 |
| 状态 | 是 | 新增后确认状态为启用才会执行阻断；停用后不再生效 |

**异常处理：**

- 阻断未生效：确认阻断口配置正确，旁路阻断网口到访问者网络可达，且被阻断流量为 TCP。
- 误阻断业务：立即停用或删除对应策略，并将关键业务 IP 加入「响应白名单」。
- 策略数量过多：导出策略清单，清理过期策略和重复策略，避免接近策略上限。
- 到期后仍被阻断：检查是否存在其他自动响应策略或联动设备侧独立规则。

### 7.3 自动响应策略

步骤 4：定期复核命中记录，删除过期或命中过宽的策略。

**异常处理：**

- 暂存名单为空：确认触发条件是否过窄，且对应时间段内确实产生告警。
- 直接下发后误封：停用策略，删除阻断策略或联动设备侧规则，并补充响应白名单。
- 重复阻断：检查是否存在多个自动响应策略命中同一对象。

| 模式 | 说明 |
|------|------|

| 从后第N个 | 取XFF字段倒数第N个IP |
| 从前第N个 | 取XFF字段正数第N个IP |

**外部对接异常处理：**

- Syslog 无数据：检查第三方主机、端口、协议、RFC、通知范围和状态是否正确；确认网络 ACL 未拦截。
- Kafka 写入失败：确认 Broker、Topic、认证信息和网络连通性；必要时查看 Kafka 集群是否允许该客户端写入。
- IM 通知未触发：确认机器人 Webhook 可用，通知过滤条件命中，通知时段和频率未限制当前消息。
- Email 测试失败：检查 SMTP 地址、端口、加密方式、账号密码、发件人权限和邮件服务器安全策略。
- SNMP 接收失败：确认 SNMP 版本、团体字或 v3 认证/加密参数与接收端一致。
- XFF 取值异常：根据客户链路中代理层级重新选择取值模式，并用实际告警中的 XFF 字段验证。

## 12. 典型操作流程

### 12.1 流程一：从告警发现到威胁处置

**适用场景：** 安全运营人员日常发现高危告警后，需要完成研判、处置、复核和留痕。

**前置条件：**

- 当前账号具备「威胁仪表」「威胁告警」「响应处置」相关权限。
- 已完成资产配置、检测策略启用和必要的响应白名单配置。
- 如需执行联动设备阻断，需提前在「响应处置 → 联动设备配置」中完成设备连接测试。

**SOP步骤：**

步骤 1：进入「威胁视图 → 威胁仪表」，查看告警总数、等级分布、攻击结果统计和攻击趋势。

步骤 2：优先关注超危、高危、攻击结果为成功或失陷的告警，点击仪表中的详情入口，或进入「威胁事件 → 威胁告警」。

步骤 3：在「威胁告警」中设置筛选条件：时间范围选择最近 24 小时或事件发生时间段，威胁等级选择超危/高危，攻击结果选择成功/失陷。

步骤 4：打开告警详情，核对五元组、攻击路径、攻击阶段、威胁名称、载荷解码、攻击危害和修复建议。

步骤 5：判断告警性质。

**表12.1-1 告警研判判断标准**
| 判断项 | 重点核对内容 | 处理建议 |
|--------|--------------|----------|
| 是否真实攻击 | 攻击源、受害资产、载荷、攻击结果 | 真实攻击进入处置流程 |
| 是否命中重点资产 | 资产等级、业务负责人、资产标签 | 重点资产优先通知业务负责人 |
| 是否存在横向扩散 | 多个受害 IP、相同攻击源、多阶段攻击 | 扩大检索范围并关联告警聚合 |
| 是否疑似误报 | 合法扫描、运维行为、已知业务访问 | 加入检测白名单或标记忽略 |

步骤 6：选择处置方式。

- 需要立即阻断：进入「响应处置 → 旁路阻断策略」或「联动设备配置」下发阻断。
- 需要人工复核：进入「响应处置 → 自动响应策略」暂存名单，确认后再批量下发。
- 属于误报：在「安全策略 → 检测白名单」中按最小范围添加白名单。
- 属于合法但高频行为：记录业务背景，保留告警但调整通知和运营规则。

步骤 7：完成处置后，在「响应处置 → 旁路阻断记录」确认阻断执行时间、阻断对象和关联策略。

步骤 8：回到「威胁告警」复核同一攻击源或受害资产是否继续产生告警。

步骤 9：将处置结论、影响范围、阻断对象、恢复动作和责任人记录到工单或事件报告中。

**验收标准：**

- 告警已完成研判并有明确结论。
- 需要阻断的对象已完成阻断或加入暂存名单。
- 误报或合法流量已按最小范围配置白名单。
- 事件处理结果可在告警详情、阻断记录、审计日志或报告中追溯。

**异常分支：**

- 阻断后业务异常：立即停用或删除对应阻断策略，并补充响应白名单。
- 告警持续出现：扩大时间范围查看同源攻击，进入「告警聚合」确认是否为批量攻击。
- 无法判断是否误报：保留告警，不直接加白，先联系业务负责人确认访问行为。

### 12.2 流程二：新设备上线策略配置

**适用场景：** 新部署或新接入设备后，管理员需要完成基础运营配置，使检测、告警、响应和通知可用。

**前置条件：**

- License 已上传且系统可正常登录。
- 管理口、采集口、镜像流量和时间同步已完成基础配置。
- 当前账号具备系统管理、资产、策略和响应处置配置权限。

**SOP步骤：**

步骤 1：进入「系统管理 → 系统设置 → 运行状态」，确认 CPU、内存、磁盘、网口流量和服务状态正常。

步骤 2：进入「企业资产 → 资产配置」，导入已知资产列表，创建资产分组，设置资产重要性等级和负责人。

步骤 3：进入「安全策略 → 内置规则」，确认核心检测规则处于启用状态；如需新增客户侧规则，进入「自定义规则」创建并验证。

步骤 4：进入「安全策略 → 自定义情报」，导入客户已有威胁 IP、域名、URL 或文件哈希情报。

步骤 5：进入「安全策略 → 检测白名单」，添加已确认的扫描器、监控系统、堡垒机或业务健康检查白名单。

步骤 6：进入「响应处置 → 响应白名单」，添加核心业务网关、运维出口和禁止自动阻断的关键地址。

步骤 7：进入「响应处置 → 自动响应策略」，先创建「暂存处置」策略，不建议新设备上线当天直接使用「直接下发」。

步骤 8：进入「响应处置 → 联动设备配置」，添加防火墙、WAF 或其他联动设备，并完成连接测试。

步骤 9：进入「系统管理 → 数据配置」，配置 Syslog、Kafka、IM、Email 或 SNMP 通知，并发送测试消息。

步骤 10：进入「威胁事件 → 威胁告警」和「流量元数据 → 数据检索」，确认新设备已有检测数据、元数据和告警流转。

**表12.2-1 新设备上线检查清单**
| 检查项 | 验收标准 |
|--------|----------|
| 系统状态 | 运行状态无异常，设备自检无关键失败项 |
| 流量采集 | 流量曲线有数据，元数据可检索 |
| 资产识别 | 重点资产已配置等级、负责人和分组 |
| 检测策略 | 内置规则启用，自定义规则已通过校验 |
| 白名单 | 检测白名单和响应白名单已按最小范围配置 |
| 响应策略 | 自动响应先进入暂存处置，暂不直接下发 |
| 外部通知 | 至少一种通知方式测试成功 |

**异常分支：**

- 无流量数据：检查交换机镜像、采集网口、探针状态和流量元数据保存协议。
- 通知测试失败：按 10.4 节逐项检查外部对接字段。
- 自动响应命中过多：停用策略，缩小触发条件后重新观察。

### 12.3 流程三：安全事件应急响应

**适用场景：** 已确认发生安全事件，需要快速定位影响范围、控制风险、保留证据并输出处置结论。

**前置条件：**

- 已明确事件时间范围、受影响业务或初始告警。
- 当前账号具备告警查看、元数据检索、响应处置和报告生成权限。
- 如需执行阻断，应先确认不会影响核心业务连续性。

**SOP步骤：**

步骤 1：进入「威胁事件 → 告警聚合」，按攻击 IP、受害 IP、威胁名称或攻击阶段聚合，定位事件主线。

步骤 2：下钻到「威胁告警」查看明细，记录攻击源、受害资产、攻击阶段、攻击结果、载荷和时间线。

步骤 3：进入「流量元数据 → 数据检索」，按攻击源、受害资产和时间范围检索关联通信，必要时下载 JSON 或 PCAP。

步骤 4：进入「企业资产 → 资产配置」或「安全场景 → 资产场景」，确认受害资产负责人、业务重要性、开放端口和关联漏洞。

步骤 5：如果攻击仍在持续，进入「响应处置 → 旁路阻断策略」或「联动设备配置」执行紧急阻断。

步骤 6：如果存在误封风险，先进入「响应处置 → 响应白名单」添加关键业务地址，再执行阻断。

步骤 7：处置完成后，回到「威胁告警」和「告警聚合」确认告警数量是否下降，攻击源是否停止访问。

步骤 8：进入「威胁视图 → 威胁报表 → 分析报告」，生成覆盖事件时间范围的报告。

步骤 9：在工单或事件记录中沉淀攻击路径、影响范围、处置动作、恢复动作、责任人和后续加固项。

**表12.3-1 应急响应证据清单**
| 证据类型 | 获取位置 | 用途 |
|----------|----------|------|
| 告警详情 | 威胁事件 → 威胁告警 | 证明检测命中、攻击阶段和攻击结果 |
| 聚合视图 | 威胁事件 → 告警聚合 | 判断是否为批量攻击或同源攻击 |
| 元数据/PCAP | 流量元数据 → 数据检索 | 还原通信内容和攻击载荷 |
| 资产信息 | 企业资产 → 资产配置 | 明确受害资产归属和重要性 |
| 阻断记录 | 响应处置 → 旁路阻断记录 | 证明处置动作已执行 |
| 审计日志 | 系统管理 → 系统审计 | 追溯操作人和操作时间 |
| 分析报告 | 威胁视图 → 威胁报表 | 对外或内部归档材料 |

**异常分支：**

- 攻击源频繁变化：按受害资产、威胁名称和攻击阶段聚合，不只依赖攻击 IP。
- 无法阻断：确认阻断能力、联动设备和网络路径；必要时由网络或边界设备侧手动封禁。
- 证据不足：扩大元数据检索时间范围，结合文件告警、登录场景和资产场景补充证据。

### 12.4 流程四：日常安全巡检

**适用场景：** 安全运营人员按日、周、月执行例行巡检，发现异常趋势并完成运营留痕。

**建议频率：**

- 每日：查看威胁仪表、告警列表、消息中心、任务中心、设备自检。
- 每周：复核高危告警、自动响应策略命中、响应白名单、检测白名单。
- 每月：生成月报，复核资产变化、规则启停、用户权限和系统升级记录。

**SOP步骤：**

步骤 1：进入「威胁视图 → 威胁仪表」，查看告警总数环比、等级分布、攻击结果和攻击阶段变化。

步骤 2：进入「威胁事件 → 威胁告警」，筛选最近 24 小时超危和高危告警，完成研判和标记。

步骤 3：进入「威胁事件 → 告警聚合」，查看 Top 攻击源、受害资产和威胁名称，判断是否存在集中攻击。

步骤 4：进入「安全场景 → 登录场景」和「安全场景 → 资产场景」，查看登录入口、风险事件和漏洞知识库变化。

步骤 5：进入「响应处置 → 旁路阻断记录」和「自动响应策略」，确认自动处置是否符合预期。

步骤 6：进入「系统管理 → 设备自检」和「系统管理 → 系统设置 → 运行状态」，确认资源使用率、磁盘空间和服务状态。

步骤 7：进入「消息中心」处理未读通知，进入「任务中心」处理失败任务。

步骤 8：进入「威胁视图 → 威胁报表」，查看定时报告是否按计划生成；如需临时汇报，创建即时报告。

**表12.4-1 巡检记录建议字段**
| 字段 | 说明 |
|------|------|
| 巡检日期 | 本次巡检执行日期 |
| 巡检人员 | 执行人姓名或账号 |
| 告警概况 | 总量、超危/高危数量、成功/失陷数量 |
| 重点事件 | 需要持续跟踪的告警或安全事件 |
| 处置动作 | 阻断、加白、通知业务、生成报告等动作 |
| 系统状态 | CPU、内存、磁盘、服务、探针和任务状态 |
| 遗留问题 | 需要下一班次或后续版本处理的问题 |

**异常分支：**

- 告警突增：优先查看告警聚合，确认是否为同一攻击源、同一资产或同一规则引起。
- 系统资源接近阈值：检查元数据保存范围、磁盘空间和历史数据策略。
- 定时报告未生成：查看报告任务状态和任务中心失败信息。

# 软件反代集群版安装手册
**确保已完成[部署前准备](../0.部署前准备/1.部署前准备.md)中的所有操作，否则会导致安装失败**
## 操作流程
### 网络环境要求
1. 管理节点与检测节点网络打通，如果有网络规则限制，则必须满足如下最基础连通性
   - 允许检测节点到管理节点的 TCP 9443 端口访问（上传检测节点信息到管理服务）
   - 允许检测节点到管理节点的 TCP 3334 端口访问（上传日志到管理节点进行聚合操作）
   - 允许检测节点到管理节点的 TCP 6379 端口访问（上传检测信息到管理服务）
### 管理节点
**注意，此节描述的操作和「不含检测与转发服务的管理节点部署节点」「复杂集群模式部署」冲突，只能三选一**
1. 初始化部署模式：`minion setup -p /data/safeline -t S20Management`
   - 如果需要使用国产化数据库(kingbase 东方通，highgo 瀚高)，则命令需要替换为：`minion setup -p /data/safeline -t Software --database-engine highgo`，可选参数包含 `highgo`，`kingbase`。**注意，不允许在选择国产化数据库后，不重置模式进行数据库切换，否则会导致存储数据异常；国产化数据库只在 23.01.009 版本及之后版本支持，请勿在非支持版本执行此命令**
   - 如果需要使用国产化内存 kv 存储（redis），则需要增加 `--redis-engine` 参数，可选项有（`tong_rds`），`minion setup -p /data/safeline -t Software --redis-engine tong_rds`**注意，不允许在选择国产化 KV 存储后，不重置模式进行 KV 存储切换，否则会导致存储数据异常；国产化KV 存储只在 25.03.001 版本及之后版本支持，请勿在非支持版本执行此命令**
   - 如果需要部署多租户模式，则命令需要调整为`minion setup -p /data/safeline -t S20Management --tenant`**注意，多租户模式在 21.03 版本后就不再支持，请不要在 21.03 版本以后执行多租户部署安装**
2. 记录步骤 1 中输出的下列信息，需要在部署检测节点时填入
   - Postgres Password（数据库密码）
   - Minion API Token（节点间通信 Token）
   - Bot Js Module Location（Bot 功能相关文件）
   - Minion Cert（节点间通信证书）
![步骤一输出信息示例](../images/快速开始_images/s20management-setup.png)
3. 启动基础平台服务：`systemctl start minion`
   - 当 WAF 版本小于 22.09.001 并且大于 22.01.001_preview 版本时，需再多执行一次`systemctl start minion-upgrader`命令
4. 检查 WAF 各服务启动状态，当所有服务的 `status` 值都为 `up`，并且没有`unhealthy`出现时，证明安装成功
5. 浏览器打开 https://当前机器 IP:9443 页面，上传产品证书，登录后打开「系统信息-节点状态」页面，查看节点是否正常

### 不含检测与转发服务的管理节点部署
当某些场景比如为了性能考虑，节点资源不足等情况，不希望在管理节点部署检测与转发服务，则可以参考本节说明，部署一个不带检测服务，转发服务的管理节点（**注意，此节描述的操作和「管理节点」「复杂集群模式部署」冲突，只能三选一**）。
#### WAF 版本大于等于 21.03 并且小于 22.09
1. 初始化部署模式：
   - `minion setup -p /data/safeline -t S20Management --block-service detector --block-service mario-collector --block-service tengine`
   - 如果需要部署多租户模式，则命令需要调整为`minion setup -p /data/safeline -t S20Management --tenant`**注意，多租户模式在 21.03 版本后就不再支持，请不要在 21.03 版本以后执行多租户部署安装**
2. 记录步骤 1 中输出的下列信息，需要在部署检测节点时填入
   - Postgres Password（数据库密码）
   - Minion API Token（节点间通信 Token）
   - Bot Js Module Location（Bot 功能相关文件）
   - Minion Cert（节点间通信证书）
![步骤一输出信息示例](../images/快速开始_images/s20management-setup.png)
3. 启动基础平台服务：`systemctl start minion`
   - 当 WAF 版本小于 22.09.001 并且大于 22.01.001_preview 版本时，需再多执行一次`systemctl start minion-upgrader`命令
4. 检查 WAF 各服务启动状态，当所有服务的 `status` 值都为 `up`，并且没有`unhealthy`出现时，证明安装成功

#### WAF 版本小于 21.03 或者大于等于 22.09
**此小节描述操作需要通过浏览器访问管理节点的 6767 端口，如果浏览器所在机器和管理服务所在机器有网络策略限制，需提前开放 TCP 6767 端口的访问限制。**
1. 初始化部署模式：`minion setup -p /data/safeline -t S20Management`

2. 记录步骤 1 中输出的下列信息，需要在部署检测节点时填入
   - Postgres Password（数据库密码）
   - Minion API Token（节点间通信 Token）
   - Bot Js Module Location（Bot 功能相关文件）
   - Minion Cert（节点间通信证书）
![步骤一输出信息示例](../images/快速开始_images/s20management-setup.png)
3. 通过 6767 部署页面进行服务删除
   - 执行 `minion setup -p /data/safeline`
   - 浏览器访问`http://管理节点 IP:6767`
   - 在「方案配置方式」页面选择「编辑本机部署」，并点击「下一步」
   - 删除「流量检测服务」「流量转发服务」「日志采集服务」，并点击下一步
   - 点击「点击部署」选项，并点击「完成」
4. 启动基础平台服务：`systemctl start minion`

### 检测节点
1. 设置节点 hostname（需要保证节点名称在 WAF 集群内保持唯一，否者会导致节点连接失败）
   - **如果通过 hostnamectl 设置名称，设置完成后需要重启系统，否则名称更新不会生效**
2. 初始化部署模式：`minion setup -p /data/safeline -t S20Agent`，输入保存的管理节点部署信息
   - **注意：当需要输入 Management Address with Port and Protocol（管理节点访问地址）时，需要输入的内容为`https://管理节点 IP:9443`**
   - **如果保存的管理节点部署信息不慎丢失，可以通过如下命令在管理节点重新获取**
     - Postgres Password：`minion db get /minion/v1/services/postgres_password`
     - Minion API Token：`minion db get /minion/v1/services/minion_api_token`
     - Bot Js Module Location：`minion db get /minion/v1/bot_js_location`
     - Minion Cert：`cat /data/safeline/resources/management/certs/minion.crt | awk '{printf "%s\\n", $0}';echo`
![检测节点安装输入示例](../images/快速开始_images/s20agent-setup.png)
3. 启动基础平台服务：`systemctl start minion`
   - 当 WAF 版本小于 22.09.001 并且大于 22.01.001_preview 版本时，需再多执行一次`systemctl start minion-upgrader`命令
4. 浏览器打开 https://管理节点 IP:9443 页面，打开「系统信息-节点状态」页面，查看检测节点是否正常上线，并且状态为「健康」

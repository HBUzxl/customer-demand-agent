# 软件反代集群版升级手册
**注意：不同版本 WAF 有不同的最低引擎版本要求，所以升级到新版本 WAF 前，需要确定当前使用的引擎版本已经达到最低版本要求，否则需要先升级引擎到目标升级 WAF 版本的最低要求，再执行目标版本 WAF 升级。**  
**注意：检测节点版本升级会导致流量中断，需切走业务流量后再执行升级；单独升级管理节点会导致检测配置发生更新，对稳定性要求较高的情况下，依旧建议切走流量再执行更新**
默认支持所有历史「主线」版本直接升级到当前版本。某些版本存在一些特殊情况，这些版本需要根据「版本升级特别说明」小节的说明，按照具体的版本要求进行升级。  
对于「专版」，默认都不支持升级到后续的主线版本。需要 case by case 评估是否支持升级，比如是否修改数据库结构、专版功能是否已经在主线版本实现等等情况，建议升级前咨询产线。

## 标准操作流程
1. 确保已完成「部署前准备」中的内容
2. 确保待升级 WAF 版本不在「版本升级特别说明」
3. 执行 `minion setup -m` 命令
4. 执行 `systemctl restart minion` 命令
5. 等待 1-2 分钟后，执行 `docker ps -a` 查看所有容器已经启动，并且处于健康状态。

## 版本升级特别说明
### 升级前版本小于 21.07 版本
1. 确保已完成「部署前准备」中的内容
2. 管理节点执行 `minion setup -m -t S20Management` 命令
   - **注意：多租户模式最后一个支持的版本为 21.03版本，所以版本升级时，目标版本不能超过 21.03**
3. 检测节点执行 `minion setup -m -t S20Agent` 命令
4. 执行 `systemctl restart minion` 命令
5. 上传最新版本引擎到安装命令执行目录
6. 执行 `source /etc/minion/minion.env && MINION_CONFIG_PATH=/etc/minion/config.yml minion upgrade -p 引擎文件` 命令
7. 打开管理界面，配置测试规则，规则能正常生效则证明升级成功

### 升级前版本大于等于 21.07 并且小于 22.09 
1. 确保已完成「部署前准备」中的内容
2. 管理节点执行 `minion setup -m -t S20Management` 命令
3. 检测节点执行 `minion setup -m -t S20Agent` 命令
4. 执行 `systemctl restart minion` 命令
5. 执行 `systemctl stop minion-upgrader`(从 22.09 版本开始，已不再使用 minion-upgrader 服务)
6. 执行 `systemctl disable minion-upgrader`(从 22.09 版本开始，已不再使用 minion-upgrader 服务)
7. 等待 1-2 分钟后，执行 `docker ps -a` 查看所有容器已经启动，并且处于健康状态。

### 升级前版本等于 22.09 版本
1. 确保已完成「部署前准备」中的内容
2. 执行 `minion setup -m`
3. 执行 `systemctl restart minion` 命令
4. 检查当前版本是否还有 `minion-upgrader` 运行，预期此服务不应该再运行，如果发现此服务还在运行，则需要执行如下命令
   - `systemctl stop minion-upgrader`
   - `systemctl disable minion-upgrader`
5. 等待 1-2 分钟后，执行 `docker ps -a` 查看所有容器已经启动，并且处于健康状态

# 站点资产相关问题
## 站点匹配优先级问题
1. 当设置了监听 IP 后，如果流量命中了该 IP，仅搜索该 IP 下绑定的站点，搜索不到时也不会去搜索不指定监听 IP 的站点
2. 匹配完 IP 后，优先级从高到低依次为：明细域名(a.com) -> 部分通配域名 (\*.com) -> 全通配域名(\*)
案例：
1. 假设所有站点监听端口都是 80
2. 假设站点1监听 10.0.0.1 ，域名绑定 a.com；
3. 假设站点2不指定 IP，绑定 * 域名。
4. 假设 hosts 表绑定:
	1. a.com ->10.0.0.1
	2. b.com -> 10.0.0.1 
此时访问 https://a.com 命中站点1
访问 b.com 不会命中任何站点，因为 10.0.0.1 这个 IP 下没有匹配任何 b.com 的站点，并且因为命中了 10.0.0.1 这个 IP，不会去未指定 IP 的站点中(即 \* 站点)搜索。

## 创建/编辑站点提示 Redis 失联
该报错是指 mgt-api 执行动作超时，需要结合具体情况分析，通常需要寻求二线技术支持帮助。

简单统计当前站点数，以及记录编辑站点的配置内容。

可以尝试重启 mgt-api，或等 mgt-api 负载较低时再执行动作。

## 创建站点失败
1. 域名无法解析导致的：在转发节点测试对应域名是否可以解析，若发现不能解析，修改 nameserver 或者 host
2. 端口冲突，站点重复等

### 2. 连接设备

#### 2.1 串口连接

使用串口线连接设备，其中 rj45 端连接设备 console 口，usb 端连接 PC usb 口。

1. 线查好后，通过命令查询连接情况：`ls /dev/cu.usbserial-*`
2. 确认存在输出后，通过命令连接设备：`screen -L /dev/具体目录名称 115200`
3. 连接成功后会进入设备 shell

![串口连接进入shell](images/1-067-image2022-1-27_16-10-51.png)

#### 2.2 IPMI连接

对于没有提供 console 功能的设备，可以使用设备 IPMI 来管理设备；当然也可以通过 VGA 接口，VGA 麻烦的是需要外接显示器和键盘。

1. 确保设备提供了 IPMI 功能，一般在设备上留有 IPMI 网口，并标明 IPMI。
2. 当前使用的是【宝德】设备，默认 IPMI 的 IP 是 192.168.255.254/24 或 192.168.3.1/24（当然也可以在 BIOS 中修改 IPMI 的 IP）。
3. 将电脑 IP 也配置成与 IPMI IP 在同一网段，然后使用网线将电脑与设备 IPMI 口相连。
4. 利用电脑浏览器访问 IPMI，`https://192.168.255.254` 或 `https://192.168.3.1`。
5. 进入页面后，选择"远程管理"，再选择"kvm"，即可进入设备控制台。（提示：不支持将字符复制到控制台中）

### 3. 配置RAID

- 设备加电后，在出现一些磁盘相关信息后（大约十几秒后），会提示按 `ctrl + r` 进入RAID设置界面。

> 注：TA-H10-10000 设备 RAID 配置在 BIOS → Advanced → Dynamic UEFI Oprom → AVAGO MegaRAID

- 利用键盘上下键，调整到如下图所示位置，点击回车键。

![RAID配置-调整位置](images/1-008-iShot2022-05-31_14.51.18.jpg)

- 进入到RAID配置界面，首先配置系统盘，按照步骤进行。

![RAID配置-配置系统盘](images/1-009-iShot2022-05-31_14.52.34.png)

- 1）系统盘选择 RAID-0
- 2）利用 `tab` 键将光标移动到 SSD 磁盘上，利用 `空格键` 来选中，选中后会显示 `[X]`
- 3）利用 `tab` 键将光标移动到 OK 按钮上，点击回车键

- 按照上步同样的方法进入磁盘管理（AVAGO MegaRAID SAS 9361-8i），进行配置数据盘，按照下面的步骤进行。(raid是否开启缓存功能应按照实际需求进行，以下是开启raid缓存功能)

![RAID配置-配置数据盘1](images/1-010-iShot2022-05-31_14.55.01.png)

![RAID配置-配置数据盘2](images/1-011-iShot2022-05-31_14.56.31.png)

- 1）数据盘选择 RAID-5
- 2）将剩下的磁盘全选，当前数据盘使用
- 3）点击 Advanced 按钮，进入高级选项
- 4）读策略选择 Ahead，开启预读
- 5）写策略选择 Always Write Back，开启始终回写（即 RAID 卡不存在备用电池的情况下也启用回写功能）
- 6）I/O 策略选择 Cached，开启 I/O 缓存功能
- 7）磁盘缓存策略选择 Enable，开启磁盘缓存功能
- 8）点击 OK，进行保存配置，返回到上一面后，继续点击 OK

- 最后配置完成情况如下图所示，系统盘 RAID 0，446GB；数据盘 RAID 5，14TB。

![RAID配置完成](images/1-012-iShot2022-05-31_14.57.36.jpg)

- 保存退出。按 `ESC` 退出，并选择保存处选择 `OK`，然后按 `ctrl+alt+退格键` 或其他方法进行重启即可。

### 4. 重置BIOS（可选，仅限首次安装系统的设备）

对于第一次安装的设备（若设备之前安装过其他系统，此步骤可忽略），建议重置 BIOS。

1. 加电/重启（串口命令行执行 `reboot`）后按提示按 ESC 键进入 BIOS 界面
2. 如下图，按 Enter 键，跳出提示选择"yes/是"（自动重启）

![重置BIOS](images/1-062-image2022-1-21_18-5-4.png)

### 5. 写入设备序列号（可选，仅限首次安装系统的设备）

对于第一次安装的设备（若设备之前安装过其他系统，此步骤可忽略），需要写入设备序列号，具体步骤如下：

1. 使用 U 盘引导（加电/重启 — 串口命令行执行 `reboot` — 后，根据提示按 ESC 键进入 BIOS 界面）
2. 调整启动顺序，第一启动顺位选择 "UEFI: Build-in EFI Shell"；并保存退出（按 F4 键）

![调整启动顺序](images/1-063-image2022-1-21_18-9-0.png)

3. 重新启动后，在 Mapping Table 中寻找 USB 字样，确定 U 盘对应盘符（如下图中的 fs1:）

![Mapping Table中查找U盘盘符](images/1-052-image2022-1-21_18-10-23.jpg)

4. 在 "Shell>" 提示符号输入 `fs1:`，回车，切换到 U 盘根目录（可以使用 cd 命令切换目录，dir 命令浏览当前目录下的内容）

![Shell切换到U盘](images/1-053-image2022-1-21_18-12-34.png)

5. 执行命令，写入序列号（在 UEFI Shell 中，删除字符需要使用 Ctrl-H 组合键而不是退格键。如何获取序列号？）

| 设备型号 | 操作步骤 |
|---------|---------|
| 宝德 NET-925G/NET-925、研祥 NPC-8208 | 切换到 `EFI\aptio_4` 目录，执行 `DMIEDITEFIx64 /ss <序列号>` |
| 立华 FW-5216 | 切换到 `EFI\aptio_4` 目录，执行 `DMIEDITEFIx64 /bp FW-5216` |
| 宝德 NET-926、研华 FWA-6520、研祥 NPC-8220 | 切换到 `EFI\aptio_5` 目录，执行 `AMIDEEFIx64 /ss <序列号>` |
| 立华 FW-8896 | 切换到 `EFI\aptio_5` 目录，执行 `AMIDEEFIx64 /bp FW-8896` |

![设备型号操作](images/1-034-image2020-10-28_17-15-13.png)

7. 执行 `smbiosview -t 1 -b` 确认序列号是否写入成功
8. 执行 `reset` 重启（注意不是 `restart`）

### 6. 安装

1. 使用 U 盘引导（加电/重启 — 串口命令行执行 `reboot` 后根据提示按 ESC 键进入 BIOS 启动界面）
2. 选择自己制作的 U 盘作为首启动项；保存配置重启（按 F4 键）

![选择U盘作为首启动项](images/1-055-image2022-1-21_18-28-19.png)

3. 选择 "Jupiter Installer"，按 Enter 键进入 U 盘内置的安装系统

![选择Jupiter Installer](images/1-056-image2022-1-21_18-29-18.png)

4. 用户名为 `root`，免密登录进入到安装系统后，执行以下指令：

```bash
cd /media/sdc1          # 有可能是 sdc0 等，视现场情况而定
lsblk                   # 选择较小的盘做系统盘，较大的做数据盘
./install.sh sdb sda    # 具体命令为"/install.sh 系统盘 数据盘"
```

![root免密登录](images/1-057-image2022-1-21_18-32-36.png)

![lsblk选择系统盘](images/1-058-image2022-1-21_18-34-50.png)

5. 安装过程持续约 10 分钟；完成后会有 "Done" 字样，之后执行 `reboot` 重启系统

![安装完成Done](images/1-059-image2022-1-21_18-38-38.png)

6. 按照提示按 ESC 进入 BIOS 界面，调整启动顺序（系统盘放置在首位）（选择：UEFI Hard Disk:UEFI OS），拔掉 U 盘，重启

![调整启动顺序](images/1-071-image2022-6-17_15-16-46.jpg)

### 7. 配置

**注意**：沙箱版全悉，安装完成首次进入系统后会在后台进行沙箱初始化，因此所有 docker 服务启动完成前不应重启设备，需等待沙箱初始化完成。此过程中可以随时通过命令 `journalctl -u jupiter-start.service` 来查看初始化进程。

![沙箱初始化](images/1-018-image-2022-10-28_10-37-39.png)

1. 安装完成，重启进入系统（默认用户名/密码：`admin/admin`），之后进入 Jupiter shell

![重启进入系统](images/1-060-image2022-1-21_18-39-49.png)

2. 配置管理接口 mgmt，默认 IP 是 192.168.1.1/24（其中掩码采用位数表示，"IPv4 Route"直接回车跳过）

![配置管理接口mgmt](images/1-061-image2022-1-21_18-40-30.png)

3. 执行 `network show` 命令查看是否正常。如出现如下错误，请重启设备重试一下。

![network show错误](images/1-070-image2022-6-17_15-16-2.jpg)

4. 具体的所有操作见下图

![配置操作总览](images/1-072-image2022-6-17_15-40-52.png)

5. 配置 DNS 服务器：

```
Jupiter>>> set dns IP  # IP 为 DNS server 地址，例如 8.8.8.8
```

6. （针对雷池设备）进入 Linux shell：

```
Jupiter>>> admin
SN: CT0101201911088644
Admin Passcode:    # 此值需要向产品师傅索取
```

7. （针对全悉新硬件）进入 Linux shell：可以使用用户名和密码

**检查和配置系统时间**：

```bash
# 检查硬件时间
hwclock
```

![检查hwclock](images/1-069-image2022-6-15_11-7-22.png)

```bash
# 如果硬件时间正确，执行
hwclock -s
# 检查时区
date -R    # 正常应为 +0800，不正确则执行
```

![检查时区date -R](images/1-068-image2022-6-15_11-15-27.png)

```bash
timedatectl set-timezone Asia/Shanghai
# 配置日期
date -s YY/MM/DD
# 配置时间
date -s hh:mm:ss
# 配置完成后，将系统时间同步到硬件时间
hwclock -w
```

8. 优雅关机：安装完成后，需要优雅的关机，直接拔掉会触发未知的问题。在 shell 下执行 `poweroff` 命令。

9. （可选）系统时间异常情况下，系统部分程序需要清空数据，具体操作见下图：

![系统时间异常清空数据](images/1-073-image2022-6-17_15-45-1.png)

清理数据指令：

```bash
cd /data/jupiter/
./stop-jupiter.sh
docker-compose -f docker-compose-upgrade.yml stop
rm -rf workdir/prometheus/data/*
rm -rf workdir/pg_data/*
rm -rf workdir/zookeeper_data/*
rm -rf workdir/kafka/data/*
rm -rf workdir/es/data/*
rm -rf workdir/upgraderpg_data/*
rm -rf workdir/clickhouse/*
docker-compose -f docker-compose-upgrade.yml up -d
./start-jupiter.sh
```

## 1.3 部署方式二：软件版安装

### 部署要求

**1. 硬件资源需求**：

| 型号 | 处理流量 | CPU | 内存 | 数据磁盘 | 网卡 |
|------|---------|-----|------|---------|------|
| 最低 | 500Mbps | 6物理核心/12逻辑核心 | ≥ 64G | ≥ 4T | 千兆卡 + 百兆管理卡 |
| 低 | 1Gbps | 10物理核心/20逻辑核心 | ≥ 96G | ≥ 8T（存元数据建议磁盘数≥3块） | 千兆卡 + 千兆管理卡 |
| 中 | 2Gbps | 16物理核心/32逻辑核心 | ≥ 128G | ≥ 12T（存元数据建议磁盘数≥3块） | 万兆卡/双千兆卡 + 千兆管理卡 |
| 次高 | 5Gbps | 28物理核心/56逻辑核心 | ≥ 192G | ≥ 12T（存元数据建议数据盘数量≥5块） | 2口万兆卡 + 千兆管理卡 |
| 高 | 10Gbps | 36物理核心/72逻辑核心 | ≥ 256G | ≥ 16T（存元数据建议数据盘数量≥6块） | 2口万兆卡 + 千兆管理卡 |

> **通用要求**：CPU 必须为 Intel 或海光；网卡尽量 Intel；系统磁盘 ≥ 500G；除 500Mbps 型号外，数据盘做 RAID5

**2. 操作系统** — 🚫 必须满足以下要求，否则安装过程中会报 error 退出安装

- **支持的操作系统**：ubuntu（18.04、20.04、22.04、24.04）、centos（7.6+）、Kylin（V10）
- 推荐使用 ubuntu22.04 server 版（安装时不要选择最小化安装），注意做好时间同步和时区配置（Asia/Shanghai）。如果系统本身 SSH 为弱口令，记得修改为强口令。
- **系统内核要求**：大于 3.10.0 且内核版本不在 [4.15.0-137 ~ 4.15.0-144] 区间内（含 4.15.0-137）
- 操作系统安装时注意不要选择最小化安装（最小化安装后可能缺少必要的运维工具，软件版安装可能会报错）

**3. CPU 要求** — 🚫 必须满足以下要求，否则安装过程中会报 error 退出安装

- CPU 须为 Intel 或海光，且 CPU 指令集要包含 SSE、SSE2、SSE3 或 PNI、SSSE3、SSE4_1、SSE4_2（一般较新的 CPU 都支持以上指令集）
- CPU 需支持 DPDK

**4. 系统最低要求** — ⚠️ 低于以下任意要求，安装过程中会报 warning

- CPU ≥ 8 线程
- 内存 ≥ 32G
- `/data` 目录 ≥ 256G

**5. 必须单独给全悉数据存储创建 `/data` 目录** — 🚫 否则安装过程中会报 error 直接退出安装

**6. 强烈建议 `/data` 目录单独挂载一块磁盘** — ⚠️ 有未格式化或未挂载的磁盘，安装过程会报 warning

- ext4 格式，磁盘大小 > 1T

**7. Docker 要求** — 🚫 Docker 版本小于 1.41 安装过程中会报 error 直接退出安装

- 如果系统内置 Docker 需保证 Server API Version ≥ 1.41，否则需要卸载
- 尽量使用软件版携带的 Docker 环境，安装脚本会自动安装 Docker

**8. 端口检查** — ⚠️ 否则安装过程中会报 warning

- 系统端口 80、443、9092、29092、9200、9090 不能被占用

**9. 必需软件** — ⚠️ 否则安装过程中会报 warning

- 需确保系统安装 curl、iptables、fdisk、ss、tar、ethtool、ip、lsblk、blkid、findmnt，可在线安装或离线安装包方式安装

> ⚠️ **注**：全悉软件安装脚本会检测以上系统各项配置，有 warning 项没有 error 就会让输入 `-y` 继续，有 error 项直接退出安装。

### 安装步骤

1. 在 release 平台下载软件安装包，选择 **Answer-xxx-软件版**（注意：带 Answer-Platform 的是平台安装包）

2. 创建目录并上传安装包：

```bash
mkdir -p /data/jupiter
mv jupiter-software-installer-xx.zip /data/jupiter
cd /data/jupiter
unzip jupiter-software-installer-xx.zip
```

3. 执行安装脚本：

```bash
./install.sh
```

4. 执行检查命令：

```bash
ufw disable                # 关闭 ufw（ubuntu 系统）
fdisk -l                   # 查看磁盘挂载（/data 目录需要挂载到数据盘）
```

5. 重启服务器：

```bash
reboot
```

### 数据盘挂载参考

```bash
# 临时挂载
fdisk -l                   # 数据盘为 /dev/sd*
mkfs -t ext4 /dev/sd*
mkdir /data
mount /dev/sd* /data

# 持久化
blkid /dev/sd*             # 查询 UUID
# 编辑并追加到 /etc/fstab：
UUID=1d4e1d9d-d15c-1273-8442-2303b05b96ad /data ext4 defaults 0 1
```

## 1.4 部署方式四：国产化硬件安装

国产化硬件（如 TA-H10-5000）的安装与硬件灌装基本一致，参考 [1.2 部署方式一：硬件版安装](#12-部署方式一硬件版安装)，本节仅描述不同之处。

### 制作灌装 U 盘

选择海光设备的沙箱部署物料，在 release 平台下载最新版本的"T-ANSWER 国产化设备（海光-x86）Sandbox 部署物料"。

### 配置BMC

设备默认未配置BMC，首次运行时需要外接显示器开启BMC，方便后续运维。

开机进入BIOS，进入高级→BMC配置→BMC网络配置，建议将专用网络（设备MGMT口）配置为192.168.255.254。

![BMC网络配置](images/1-019-image-2023-1-31_14-39-6.png)

默认BMC用户名密码为admin/admin

开机进入BIOS，进入高级→LSI MegaRAID→Configuration Management→Create Virtual Drive

注意：选择硬盘时，可以通过Select Media Type筛选SSD或HDD（默认时HDD，不展示SDD）

![RAID配置-Select Media Type](images/1-020-image-2023-1-31_14-46-21.jpg)

### 后台检测列表

**检查系统时间是否正常**：

```bash
date -R
```

**检查 Docker 是否正常启动**：

版本是否符合预期，升级列表参考 `/data/jupiter/jupiter.version`：

| 组件类别 | Docker 容器名 |
|---------|-------------|
| 检测引擎 | ganymede、kaleidoscope、chaitin_detector |
| 前端 | frontend |
| 后端/管理端 | hera、herabee、migrate（启动时执行一次立即退出）、gateway |
| 消息通道 | kafka、zookeeper |
| 存储 | es、db、redis、clickhouse |
| 升级 | upgrader、upgraderdb、upgraderfrontend |

**检查各个 Docker 是否运行正常**：

```bash
# 是否有持续性异常重启
docker ps
# 是否有异常启动日志（xxx 为前置罗列的 docker 容器名）
docker logs xxx -f
# 检查是否包含关键字（retry、error、restart 等）
```

**对外服务端口**：

| 服务 | 端口 | 检查命令 |
|------|------|---------|
| gateway | 80/443/tcp | `docker ps` |
| 宿主机 | 22/ssh | `netstat -ntl; netstat -nul; lsof -i:65530` |

**检查 docker-compose 配置是否准确**：

文件名：`/data/jupiter/docker-compose-*.yml`

- CPU 核心配置：ganymede 和其他 docker 不共享核心（cpuset 字段无交集）
- ganymede/es/kafka/kaleidoscope/chaitin_detector/herabee 是否设置了内存限制（mem_limit 字段）

**检查系统级别服务是否正常**：

```bash
systemctl status jupiter-upgrade-answer    # 升级服务/全悉界面
systemctl status minion                     # minion 管理服务
# Active: active(running) 为正常状态
```

![系统级别服务](images/1-checklist-系统服务1.png)

![系统级别服务](images/1-checklist-系统服务2.png)

**数据采集口是否正常启动**：

- 是否存在数据采集口（`ifconfig eth1.1`，硬件版默认接管 eth1.1）
- 判断千兆/万兆卡（`ethtool eth1.1`，查看 "Supported link modes"，取其最大值）

**万兆口**：

```bash
ethtool -l eth1.1        # 硬件 Current Combined 是否为 8
ethtool -x eth1.1        # 是否开启 RSS 对称哈希
ethtool -g eth1.1        # 接收 ring 队列大小是否为 4096
ethtool -k eth1.1 | grep rx-checksumming  # 是否关闭校验和
cat /proc/interrupts | grep eth1.1        # 网卡中断是否绑定到共享 CPU（ganymede cpuset 配置外的 CPU）
```

**千兆口**：

```bash
ethtool -l eth1.1        # 硬件 Current Combined 是否为 1
```

**引擎是否正常运行**：

```bash
# 检查是否产生 HTTP 元数据（两次命令之间应有变化）
docker exec -i kafka /opt/bitnami/kafka/bin/kafka-run-class.sh kafka.tools.GetOffsetShell \
  --broker-list localhost:9092 --topic origdata_log_http --time -1
```

**检查完毕使用 `poweroff` 关机，切勿直接拔电。**

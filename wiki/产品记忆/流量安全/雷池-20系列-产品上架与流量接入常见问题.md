# 产品上架与流量接入常见问题

## 流量不通

### 所有流量均无法导通/超时
1. 确认当前的网络拓扑，确认流量正确的到达 WAF，可以利用 tcpdump 命令在 WAF 上确认，若确定流量未到达 WAF，需要在客户下游的转发负载设备上排查
假设抓包的端口是 `8080`，执行命令：`tcpdump -i any port 8080`
2. 流量到达 WAF ，但没有转发出去发生超时
一些软件版的运行环境可能存在非预期的 iptables 规则
通过以下命令检查环境中是否存在人为配置的 iptables 特殊规则：

- `iptables-save`
- `iptables -t filter -nvL`
- `iptables -t nat -nvL`
### 部分流量未导通/超时
#### 协议问题
1. 若使用的是 exchange 协议，WAF 不支持该协议的反向代理或转发
2. 若使用了 HTTP chunk 特性，确认业务服务器响应包是否规范
	1. HTTP 报文中若包含 Chunk-Encoding: chunked，但报文的结尾没有 0 和 CLRF 结束符，tengine 会一直等待后续报文直到超时
#### WAF 站点配置问题
转至 3.站点资产相关问题排查
#### TLS/SSL 证书问题
响应有认证错误时/握手失败时，检查证书是否正确
1. 绕过 WAF 直接访问绑定了证书的 Server，确认 TLS 握手是否成功
2. 通过 md5sum 等手段检查是否上传错误的 SSL 证书
#### QAT 硬件问题
若存在证书认证相关问题，且当前环境存在硬件 QAT 加速卡时，检查 QAT 设备的运行状态。
按以下方式检查 QAT 设备、qatengine 配置和内存状态：

- 查询宿主机 QAT 设备，如果没有则会显示 0 个可用设备：`adf_ctl status`
- 查询 qatengine 的配置：`docker exec -it tengine /opt/ssl/bin/openssl engine -t -c -vvvv qatengine`
- 检查内存是否足够：`free -h`
- 查看内存详情：`cat /proc/meminfo`

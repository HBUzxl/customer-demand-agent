## 工作模式

谛听支持多种蜜罐部署方式。不同模式的入口形态不同，但最终都会把攻击数据送入 Supermario 处理，由 Supermario 分类聚合后发送给 Server 持久化。

### 软件部署模式

```
① 攻击者访问蜜罐
② Agent 采集事件 ──RPC──► Supermario（分类/去重/聚合）
③ Supermario ──HTTP──► Server（业务逻辑/持久化）
④ Server ──► PostgreSQL + Redis
⑤ Server ──► Supermario ──► 告警通道（邮件/Syslog/Webhook/弹窗）
```

- 最常见的部署方式，通过安装包在 Linux 服务器上部署。
- Docker Compose 编排所有服务，Nginx 反代前端与 API。
- Agent 部署于同一网络内的其他主机，通过 RPC 长连接上报事件。

### 硬件设备模式

```
① 攻击者访问蜜罐（硬件探针网口接入）
② Agent 采集事件 ──RPC──► Supermario
③ 后续链路同软件模式
```

- 软硬件一体交付，支持多网口硬件探针。
- `VmEnable = true`，支持 Windows 蜜罐虚拟机（KVM）。
- 部署脚本使用 `deploy_hw.sh` / `deploy_arm.sh`。

### 集中管理模式（Captain）

```
① 多个谛听节点注册到 Captain
② Captain ──► 统一管理策略/配置/日志
```

- 适用于多节点统一管控场景。
- Captain 模式下不使用 SeaweedFS，文件存储走本地。

## 关键链路

### 攻击检测全链路

```
① 攻击者 ──► 蜜罐（Agent 部署）
② Agent 采集 ──RPC──► Supermario（事件分类、去重、聚合）
③ Supermario ──HTTP──► Server（业务逻辑、持久化）
④ Server ──► PostgreSQL（存储） + Redis（缓存/告警状态）
⑤ Server ──► Supermario ──► 告警通道（邮件/Syslog/Webhook/弹窗）
⑥ Frontend ──► Server API ──► 展示/操作
```

### Agent 通信

| RPC 方法 | 方向 | 用途 |
|----------|------|------|
| `RPCNewIdentifyEntry` | Agent→SM | 探针注册（IPs, OS, hostname） |
| `RPCFetchConfigEntry` | Agent→SM | 拉取端口映射配置 |
| `RPCScannerEventEntryV2` | Agent→SM | 上报端口扫描事件 |
| `RPCPingEventEntry` | Agent→SM | 上报 ICMP Ping 事件 |
| `RPCArpEventEntryV2` | Agent→SM | 上报 ARP 事件 |
| `RPCForwardPortEntry` | Agent→SM | 端口转发/连接中继 |

- Agent 通过自定义 RPC 协议与 Supermario 保持 TCP 长连接。
- Supermario 的 `conn_cache` 模块管理 Agent 连接池。

### 配置下发

```
修改蜜罐/探针/告警配置
    │
    ▼
Server (Django) ──► Supermario ──► Agent 拉取并应用
    │                                       │
    ▼                                       ▼
PostgreSQL                          端口映射/蜜罐策略更新
Redis 缓存同步
```

- Server 通过 `utils/supermario.py` 的 `call(method, urlpath, data)` 与 Supermario 同步配置。
- Agent 周期性通过 `RPCFetchConfigEntry` 拉取最新端口映射与蜜罐策略。

## 蜜罐管理

谛听支持 78 种蜜罐类型，按分类如下：

| 分类 | 代表类型 | 说明 |
|------|---------|------|
| 系统服务 | FTP、Telnet、VPN、Samba、DNS | 模拟基础网络服务 |
| 数据库 | MySQL、Redis、MongoDB、PostgreSQL、Oracle、MSSQL | 模拟数据库服务，部分支持反制 |
| Web 应用 | Jenkins、WordPress、Jboss、RabbitMQ、Grafana | 模拟常见 Web 管理平台 |
| 特殊缺陷 | EternalBlue、fastjson、Shiro、Struts2、WebLogic | 模拟已知漏洞环境 |
| 高级 | 智能学习 Web 站点、自定义 Web (PHP/Python/Lua)、拟态防护 | 可定制化蜜罐 |
| 操作系统 | CentOS/Ubuntu (SSH)、Windows 7/10/2016 (RDP) | 高交互操作系统蜜罐 |
| 工控 | IEC104、Modbus、OPCUA、S7 | 工控协议蜜罐 |

### 蜜罐生命周期

```
创建 → 启动 → 运行中 → 停止 → 重置 → 删除
                    │
                    ▼
              攻击事件上报
```

- **创建**：选择蜜罐类型，配置名称、网络、资源限制等参数
- **启停**：通过 Supermario 的 `hen` 引擎管理 Docker/VM 容器
- **重置**：清除蜜罐内攻击痕迹，恢复初始状态
- **预设**：支持上传自定义蜜罐预设模板

### 蜜罐资源限制

在 `supermario.toml` 中配置：

```toml
[pkg.hen]
  DefaultMemLimit = 2000      # 默认蜜罐内存限制（MB）
  WebMemLimit = 2500          # Web 蜜罐内存限制
  DefaultCPULimit = 1.0       # CPU 限制（核数）
  WebCPULimit = 2.0
```

## 蜜网管理

蜜网是蜜罐的逻辑分组，用于统一管理一组相关的蜜罐。

- 支持创建、编辑、删除蜜网
- 蜜网内蜜罐共享网络配置
- 支持白名单配置，避免误报
- 蜜网 ID 追踪，方便溯源分析

## 探针管理

探针（Agent）部署于监控主机，负责采集网络攻击事件。

### 探针功能

| 功能 | 说明 |
|------|------|
| 端口扫描检测 | 检测对蜜罐端口的 TCP/UDP 扫描 |
| ICMP Ping 检测 | 检测对蜜罐的 Ping 探测 |
| ARP 欺骗检测 | 检测网络中的 ARP 欺骗行为 |
| 端口转发 | 将流量转发到蜜罐，实现诱捕 |
| 远程运维 | 通过 WebShell 管理探针 |

### 探针通信协议

探针通过自定义 RPC 协议与 Supermario 保持 TCP 长连接，主要 RPC 方法：

| RPC 方法 | 用途 |
|----------|------|
| `RPCNewIdentifyEntry` | 探针注册 |
| `RPCFetchConfigEntry` | 拉取端口映射配置 |
| `RPCScannerEventEntryV2` | 上报端口扫描事件 |
| `RPCPingEventEntry` | 上报 Ping 事件 |
| `RPCArpEventEntryV2` | 上报 ARP 事件 |

### 业务分组

支持树形业务分组（cur/level 字段），按组织结构管理探针。

## 事件中心

事件中心展示所有检测到的攻击事件，包括连接日志、蜜罐事件、扫描事件等。

### 事件类型

| 事件类型 | 来源 | 说明 |
|---------|------|------|
| 蜜罐入侵事件 | Agent→SM→Server | 蜜罐内攻击行为（登录/命令/文件等） |
| 连接事件 | Agent→SM→Server | 攻击者与蜜罐的连接记录 |
| 端口扫描事件 | Agent→SM | 对蜜罐端口的扫描探测 |
| Ping 事件 | Agent→SM | ICMP Ping 探测 |
| ARP 事件 | Agent→SM | ARP 欺骗检测 |
| Docker 逃逸事件 | Supermario | 蜜罐容器逃逸检测 |

### 风险等级

| 等级 | 值 | 说明 |
|------|---|------|
| 高危 | 4 | 需立即处置的攻击行为 |
| 中危 | 3 | 需关注的攻击行为 |
| 低危 | 2 | 一般性探测行为 |
| 无威胁 | 1 | 无需处置 |

## 告警中心

告警中心管理告警规则和告警通知。

### 告警通道

| 通道 | 说明 |
|------|------|
| 邮件告警 | 通过 SMTP 发送告警邮件 |
| Syslog 告警 | TCP/UDP，支持 RFC3164/RFC5424 |
| Kafka 告警 | 发送到 Kafka Topic |
| Webhook 告警 | HTTP POST 回调 |
| 短信告警 | 短信通知 |
| 弹窗告警 | 前端实时弹窗（600 秒间隔） |
| 防火墙联动 | 雷池/牧云/长亭防火墙自动封禁 |

### 告警流程

```
事件触发 → 告警规则匹配 → 告警分发（Supermario dispatcher）
                              │
                              ├── 邮件通道
                              ├── Syslog 通道
                              ├── Kafka 通道
                              ├── Webhook 通道
                              └── 防火墙联动
```

## 攻击者画像

通过浏览器指纹、社交账号、设备信息等技术溯源攻击者身份。

画像数据包含：

| 维度 | 字段 | 说明 |
|------|------|------|
| 设备 | cpuConcurrency, fonts, timezone, screenResolution, os | 设备指纹 |
| 网络 | externalIP, realIP, internalIP | 网络身份 |
| 浏览器 | name, version, fp2, webgl_fp, canvas_fp | 浏览器指纹 |
| 社交 | uid, username, home（按网站动态变化） | 社交账号 |

## 统计报表

- 支持生成统计报告与溯源报告
- 报告可导出为 PDF
- 支持定时报告任务

## Syslog 外发

系统支持将事件通过 Syslog 外发，可配置的事件类型：

- 蜜罐入侵事件
- 端口探测事件
- Ping 扫描事件
- ARP 欺骗事件
- 攻击者画像
- 探针连接/断开状态
- Docker 逃逸事件

> Syslog 为保证时效性逐条发送，与界面下载的聚合日志不同。

详细字段说明参考 [openapi.yaml](openapi.yaml) 中对应 Syslog 相关接口的请求体定义。

## MCP 接口

谛听提供 MCP Server，将 REST API 封装为 MCP（Model Context Protocol）工具，使 AI 助手能够通过自然语言调用谛听的全部管理功能。

### 工具概览

MCP Server 当前提供 **77 个工具**，按功能域分类如下：

| 分类 | 工具数 | 覆盖范围 |
|------|--------|----------|
| 蜜罐管理 | 23 | 蜜罐/蜜网生命周期、模板、蜜饵、证书、蜜网剧本 |
| 探针管理 | 22 | 探针查询、端口映射、业务组、网络配置、VLAN |
| 攻击事件 | 10 | 入侵日志、端口探测、攻击源分析 |
| 攻击者画像 | 9 | 画像查询/删除、下载、溯源报告 |
| 许可证 | 1 | 许可证状态查询 |
| 系统工具 | 2 | 测试回显、时间查询 |

### 协议与部署

- **协议**：MCP over SSE（Server-Sent Events）
- **框架**：FastMCP + Starlette + Uvicorn
- **部署方式**：Docker 容器或命令行启动，默认监听端口 19991
- **认证**：通过 API Token 认证，所有请求携带 `role` 和 `api-token` 请求头

### 使用方式

在 AI 助手（如 Claude Code、Cursor）中配置 MCP Server 地址后，即可通过自然语言操作谛听：

- "列出所有蜜罐" → 调用 `honeypot_list`
- "启动测试蜜罐" → 先 `honeypot_list` 获取 CID，再 `honeypot_start`
- "查看最近的攻击事件" → 调用 `list_connection`
- "查看攻击者画像" → 调用 `list_portrait`

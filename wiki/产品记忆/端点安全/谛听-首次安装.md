# 快速部署（自动化脚本）

如需快速部署，可使用自动化部署脚本完成环境检查和安装。

### 方式一：使用自动化脚本（推荐）

```bash
# 1. 上传部署脚本和安装包到服务器
scp dsensor_deploy.sh check_dsensor_env.sh user@server:/home/user/
scp honeypots-xxx.zip DS-S40-xxx.zip user@server:/home/user/

# 2. SSH 登录服务器
ssh user@server

# 3. 运行环境检查（脚本会自动申请 root 权限）
chmod +x check_dsensor_env.sh
./check_dsensor_env.sh

# 4. 运行部署脚本（脚本会自动申请 root 权限）
chmod +x dsensor_deploy.sh
./dsensor_deploy.sh /home/user/honeypots-xxx.zip /home/user/DS-S40-xxx.zip diew4sohTh

# 5. 部署完成后访问管理界面
# http://服务器IP
```

> **提示**：脚本兼容 24.06、25.07（需额外执行 ./installer）和 25.12（.bin 自身完成安装）三个版本。25.07 版本会自动检测并执行 ./installer。

## 检查与准备环境

目前有两种检查环境的方式：使用环境检查脚本自动检查（支持 Ubuntu、CentOS）、手动检查，两种检查方式任选其一即可。

### 使用环境检查脚本自动检查环境（支持 Ubuntu、CentOS）

环境检查脚本在管理节点软件压缩包中，先解压第一层压缩包，即可看到环境检查脚本（checkEnv）。

可输入以下命令解压压缩包（注意替换实际文件名）：

```bash
unzip DS-S40-software-installer-xxx.zip
```

解压后可得到3个文件：

```text
- d-sensor-4-software-installer_xxx.bin
- checkEnv
- README.md
```

运行其中的checkEnv，即可开始自动检查环境：

```bash
./checkEnv
```

环境检查输出的检查项状态包含4种：

```text
- 通过（Pass）：表示通过
- 未知（Unkown）：表示未知，需要用户自己或联系技术人员进一步确认
- 警告（Warning）：表示未通过，但建议符合，可联系技术人员进一步确认
- 错误（Error）：表示未通过，需必须符合，存在此状态时不能安装产品
```

修正配置项后，可重新执行环境检查脚本再次检查。

### 手动检查环境

#### 检查内核版本与时间

安装产品要求管理节点的操作系统为内核高于 3.10.0-514、构建时间晚于或等于 2017 年的版本。如果内核版本比较低，Docker 的部分功能 (如 overlay2 存储层驱动) 无法使用，并且可能影响功能的稳定性。如果构建时间过早，可能存在逃逸漏洞，对谛听的安全运行有严重影响。

输入以下命令检查：

```bash
uname -r

uname -a
```

要求内核版本大于 3.10，构建时间晚于或等于 2017 年。

#### 检查 umask 值

输入以下命令检查 umask 配置，确保值为 022：

```bash
umask

022
```

若 umask 非022，则需要修改 umask 配置：

```bash
umask 022
```

> **常见问题**：Ubuntu 默认 umask 是 0002，需要修改。修改方法：
>
> ```bash
> echo 'umask 022' >> ~/.profile
> source ~/.profile
> umask  # 确认输出为 0022
> ```

#### 检查文件系统

输入以下命令检查磁盘分区的文件系统类型，谛听安装分区的文件系统类型要求为 ext4。

```bash
blkid

# 或者

df -Th
```

若没有 ext4 分区，需要新建分区并使用 mkfs.ext4 进行格式化。

PS. 谛听安装好后，可以将系统数据目录 /data/d-sensor/ 挂载在其他文件系统类型的分区上，不会影响系统运行，但 docker 相关目录 /var/lib/docker/ 必须保持在 ext4 类型的分区上。

#### 检查系统时间

输入以下命令检查系统时间，要求系统的 UTC 时间为正确的 UTC 时间。

```bash
date -u

# Thu Sep  7 03:04:43 UTC 2017

# 或者

timedatectl
```

输出示例：

```text
      Local time: Wed 2014-09-24 21:19:26 CST
  Universal time: Wed 2014-09-24 13:19:26 UTC
        RTC time: Wed 2014-09-24 13:19:26
        Timezone: Asia/Shanghai (CST, +0800)
     NTP enabled: yes
NTP synchronized: yes
 RTC in local TZ: no
      DST active: n/a
```

若显示的UTC时间和实际UTC时间不符，可通过 date 或 timedatectl 设置时间。

> **常见问题**：若系统时间显示 Unknown，可设置时区：
>
> ```bash
> sudo timedatectl set-timezone Asia/Shanghai
> date
> ```

#### 检查 SELinux、Firewalld 设置（Ubuntu系统可跳过）

在 CentOS 系统中进行部署时，需要关闭 SELinux 、Firewalld。Ubuntu 系统中 SELinux 、 Firewalld 默认关闭，可跳过此步骤。

1. 关闭 SeLinux 并确认关闭成功

```bash
setenforce 0
getenforce
# Permissive
```

getenforce 结果不是 Enforcing 则表明 SELinux 已经成功关闭。

2. 设置开机默认关闭 SELinux：

```bash
sed -i 's/enforcing/disabled/g' /etc/selinux/config
cat /etc/selinux/config
# disabled
```

/etc/selinux/config 为 disabled 则表明开机默认关闭 SELinux。

3. 关闭 Firewalld 并设置为开机默认关闭

```bash
systemctl stop firewalld
systemctl disable firewalld
systemctl status firewalld
```

输出示例：

```text
● firewalld.service - firewalld - dynamic firewall daemon
     Loaded: loaded (/usr/lib/systemd/system/firewalld.service; disabled; vendor preset: enabled)
     Active: inactive (dead)
        Docs: man:firewalld(1)
```

若看到 Active: inactive (dead) 字样，表明 Firewalld 关闭成功。

### 卸载旧版本和错误配置的 Docker（未安装 Docker 可跳过）

部署要求 Docker 版本为 20.10.17 或以上的稳定版。

另外，要求 Docker 的 Storage Driver 为 overlay 或 overlay2，否则会导致谛听安装后占用空间过大，无法正常运行。

下面给出在 Ubuntu 16.04 LTS Server 和 CentOS 7.4 的 64 位系统版本的卸载过程，其他系统可以以此为参照。

1. 检查 docker 版本和 Storage Driver 配置：

```bash
docker –version
docker info
```

要求安装的 Docker 版本为 20.10.17 或以上的稳定版。Storage Driver 为 overlay 或 overlay2。如果只是 Storage Driver 不对，可以修改，参考：<https://docs.docker.com/storage/storagedriver/overlayfs-driver/> 。也可以直接卸载，后面重新安装。

2. 卸载旧版本或错误配置的 Docker

Ubuntu：

```bash
sudo apt-get remove docker docker-engine docker.io
```

CentOS：

```bash
sudo yum remove docker docker-common docker-selinux docker-engine
```

如果 apt-get、yum 报告没有安装这些软件包，也是正常的，可以继续下一步。

## 安装软件

安装前，请先确认设备是否已安装 unzip、system命令：

```bash
sudo apt-get install unzip
sudo apt-get install systemd
```

### 版本安装流程差异说明

> **重要**：不同版本的谛听安装流程有差异，请先确认待安装的版本类型再进行操作。

| 版本 | .bin 安装程序的作用 | 是否需要额外运行 ./installer |
|------|-------------------|---------------------------|
| **25.07（本版本）** | 仅解压文件 | **是，必须执行** |
| 25.12 等新版本 | 完成全部安装 | 否（installer 文件不存在） |

**本版本（25.07）安装流程**：执行 .bin 解压 → **运行 ./installer** → 安装完成

**25.12 等新版本安装流程**：执行 .bin → 安装完成（.bin 自身完成全部安装，不会生成 installer 文件）

installer 的关键参数：
- `-i=false`：非交互模式
- `-d sw`：软件版安装
- `-d sw+vm`：软件+虚拟机蜜罐版

### 绕过目录检查（关键步骤）

由于安装脚本会检查目录是否为空，当目录中已有蜜罐文件时会报错退出。需绕过此检查：

```bash
cd /data/d-sensor

# 备份原脚本
sudo mv check_environment.sh check_environment.sh.bak

# 创建返回成功的脚本
echo '#!/bin/bash' | sudo tee check_environment.sh
echo 'exit 0' | sudo tee -a check_environment.sh
sudo chmod +x check_environment.sh
```

1. 创建部署目录并切换到部署路径

```bash
mkdir –p /data/d-sensor
cd /data/d-sensor
```

2. 上传安装包到虚拟机或硬件设备中的 /data/d-sensor 路径下

3. 将蜜罐安装包解压到部署目录（注意替换为实际的文件名）

```bash
unzip -o honeypots-2-software-installer_xx.zip –d /data/d-sensor
```

4. 安装蜜罐

若系统没有 Docker、Docker-compose，则会在此时自动安装

```bash
sudo ./install.sh
```

> **提示**：安装蜜罐后，建议将当前用户加入 docker 组：
>
> ```bash
> sudo usermod -aG docker $USER
> ```
>
> 需重新登录使 docker 组生效。

5. 将软件压缩包解压到部署目录（注意替换为实际的文件名）：

```bash
unzip DS-S40-software-installer-xxx.zip
sudo ./d-sensor-4-software-installer_xxx.bin -C /data/d-sensor
```

> **提示**：管理平台安装包为加密压缩包，解压需使用 `-P` 参数指定密码：
>
> ```bash
> unzip -P 'diew4sohTh' -o DS-S40-xxx.zip
> ```

> **提示**：解压前已执行绕过目录检查步骤，安装程序不会再检查目录是否为空。

6. 安装软件系统

**本版本（25.07）必须额外运行 ./installer**：

```bash
sudo ./installer
```

执行 installer 时，如果该型号设备需要安装虚拟机蜜罐，安装过程中选择 "软件+虚拟机蜜罐拓展（sw+vm）"。否则选择"软件（sw）"，若出现"will you enable vm manager(y/n)"选择n即可。

> **注意**：25.07 版本的 .bin 安装程序仅负责解压文件，**不会自动安装服务**，必须手动运行 ./installer。如使用自动化部署脚本，脚本会自动检测并执行此步骤。

7. 确认服务正常启动

```bash
sudo docker ps -a
```

确保所有容器状态都为up，如下图所示：

![docker容器状态](images/upload_559bf8abdb813e0e5230fc5a5cf58b91.png)

8. 在 /data 目录下加载预置模版

```bash
cd /data
sudo ./generate_preset.sh
```

若安装目录不是默认目录，执行时需要指定对应目录：

```bash
sudo ./generate_preset.sh /data/d-sensor
```

9. 访问管理地址，上传 license 并登陆。若能正常访问管理界面，而且 蜜罐管理-模版管理 中能添加若干蜜罐的模版，其中部分蜜罐还有预置的模版（例如 自定义 Web(Python) 蜜罐），则说明安装成功：

![安装成功](images/upload_f51fc83762bc6a7a1dcd8083fc706982.png)

10. 安装蜜罐拓展包

    a. 虚拟机蜜罐：

    > i. 确保安装时已开启虚拟机蜜罐模块：执行"docker ps"查看有没有"vm_domain"容器。若没有，则进入 docker-compose 所在文件夹，执行 docker-compose down，然后重新执行安装脚本 ./installer，并选择 "软件+虚拟机蜜罐拓展（sw+vm）"
    >
    > ii. 将拓展包文件解压到 /data/libvirt/images
    >
    > iii. 执行 "docker restart vm_domain"，再执行 "docker restart dsensor_redis"即可

    b. .zip 后缀名蜜罐：

    > 解压到安装目录，然后在解压文件夹内运行 ./install.sh

# 安装探针节点

## 检查环境系统配置

1. 当在 CentOS 系统环境下部署探针时，需要关闭 SELinux 、Firewalld。Ubuntu 系统下的 SELinux 、 Firewalld 默认关闭，可跳过此步。具体步骤见本章 [检查 SELinux、Firewalld 设置（Ubuntu系统可跳过）](#检查-selinuxfirewalld-设置ubuntu系统可跳过)
2. 确保探针机器能访问管理节点的 1337 端口
3. 探针服务器最低配置需求：CPU 1核、内存 2GB、硬盘 20GB。

推荐 **在线安装**，在线安装要求探针机器能访问管理节点的 443、1338 中的任意一个端口。若不能访问，需要进行离线安装。

## 附1：在线快速安装探针

在线安装的情况下，如果确定探针安装的配置，可以将下载、安装、执行的步骤合并，在探针设备上执行一行命令直接完成安装。

Linux 系统：

```bash
wget --no-check-certificate \
https://{管理节点地址}/ag/install_agent_{操作系统架构} -O /tmp/install_agent && \
chmod +x /tmp/install_agent && \
sudo /tmp/install_agent --host {管理节点地址} --token {您的Token}
```

Windows 系统：

```powershell
[System.Net.ServicePointManager]::ServerCertificateValidationCallback = { $True }; `
(New-Object System.Net.WebClient).DownloadFile(`
"https://{管理节点的地址}/ag/install_agent.exe", `
"$env:TEMP/install_agent.exe"); `
Start-Process -Wait -NoNewWindow -FilePath "$env:TEMP/install_agent.exe" `
-ArgumentList "--host {管理节点地址} --token {您的Token}"
```

注1：`{操作系统架构}` 的允许值为 i386、amd64。这里指程序的架构，例如可以在 64 位的系统上装 32 位的程序。

注2：`{管理节点地址}` 的允许值为主机名和 IP。

注3：`{您的Token}` 是系统用户在管理界面的"个人中心"生成的 API Token。

注4：`--token {您的Token}` 后面可以再添加 `--display_name {探针名}`。

## 附2：指定探针连接管理节点的 IP

探针安装后，用户可以重新指定探针连接管理节点的 IP，还可以绑定多个管理节点的 IP。如果绑定多个，管理节点 IP 迁移时，探针就可以自动重连新的管理节点 IP。

若需要指定，请登录已安装探针的机器，执行命令：

- linux 系统指定单个地址使用

```bash
./chaitin-bootstrap --server-addr <ip1>:1337 install
```

- linux 系统指定多个地址使用

```bash
./chaitin-bootstrap --server-addr "<ip1>:1337;<ip2>:1337" install
```

- Windows 系统用管理员身份打开 cmd，指定单个地址使用

```cmd
chaitin-bootstrap.exe --server-addr <ip1>:1337 install
```

- Windows 指定多个地址使用

```cmd
chaitin-bootstrap.exe --server-addr "<ip1>:1337;<ip2>:1337" install
```

# 安装多网口探针

多网口探针是指系统配合官方 A2000H、A3000H、A4000H 等标准型号的多网口硬件探针设备，提供的单探针管理大量 IP 的功能。

## 部署要求

| 部署环境和资源要求 |  |
| -------- | -------- |
| __管理IP__ | **用于「多网口探针」设备接入管理网络**（注：能访问管理节点的443 或 1338 端口用于安装，1337 端口用于运行） |
| __交换机Trunk口__ | 在交换机上提供Trunk模式的网口用于与「多网口探针」设备的数据口进行连接，连接后可监听不同VLAN上的大量IP |
| __VLAN信息__ | **确认需要部署伪装服务的VLAN。**（注：监听IP的网段和设备管理IP所在网段不能相同） |
| __IP信息__ | **确认需要部署伪装服务的IP。**（注：探针监听和绑定蜜罐的IP应选择空闲IP，避免和真实业务冲突。） |

## 网口管理界面操作说明

"网口管理"位于多网口探针的探针详情中，其界面如下：

![网口管理界面](images/upload_144ecf6ea08e6db47f3fef5964585dda.png)

以下为网口说明：

| -------- | -------- | -------- |-------- |

| __网口名称__ | 和硬件设备对应 | 和硬件设备对应 | [父接口].[VLAN ID] |

|  __网口状态__ | __管理口__ MGT |  __数据口__<br>初始 | __数据口__<br>已添加子接口 | __数据口__<br>已配置IP或网关 |__VLAN 口__ |
| -------- | -------- | -------- |-------- |-------- |-------- |
| __添加子接口__ | X  | O    | O   | X | X |
| __配置默认网关__ | X（产品界面不可配置）  | O    | X    | O    | O   |

## 设备部署

1. 配置管理IP：根据客户侧给设备规划的管理ip，通过CONSOLE口或直连设备进行配置。（出厂默认IP：192.168.1.1，默认SSH密码：联系产品经理 马天龙 或研发 赵凡 获取）
2. 接入管理网络：确保多网口探针设备和管理平台之间网络可达（能访问管理节点的443 或 1338 端口用于安装，1337 端口用于运行）
3. 安装探针节点：进入设备操作系统，参考3.2节安装探针节点
4. 连接交换机：通过数据口（ETH）连接交换机，与交换机之间是trunk连接

## 网口管理

部署多网口探针后，列表将额外展示探针的"IP 数/IP数上限"信息，方便管理多网口硬件探针上的空闲 IP。如下图：

![多网口探针列表](images/upload_340c8fc55047e176ca84c43da36c79b0.png)

在多网口探针的探针详情处，"可监听IP"相关配置将会替换为 "网口管理"，如图：

![网口管理详情](images/upload_def58b54e319cbbdb514926d6139f6bf.png)

此处将显示当前探针的管理口、数据口、VLAN 口，以及接口上的 IP 信息。

1. 操作说明

   - 点击列表右上角 "添加 VLAN接口"，可以基于数据口添加 VLAN 口
   - 点击接口右侧的 "编辑网关"，可以设置该接口的下一跳网关地址。配置正确的网关地址，可以借由网络中已有的网关设备，模拟跨 VLAN 通信等复杂的网络场景
   - 点击接口右侧的"配置 IP"，可以配置接口的 IP
   - 点击列表上方 "导入配置"，可以以 Excel 表格的形式，批量导入探针的 IP 配置信息

2. 其他注意事项

   - 管理口不能通过界面编辑 IP、网关，以防操作失误、导致探针连接断开
   - IP 总数不能超过当前探针型号的监听 IP 数上限
   - 数据口添加 VLAN 子接口后，需要接到交换机的 trunk 口使用。此时该数据口不允许配置 IP、网关；反之，数据口配置了 IP、网关后，需要接到交换机的 access 口使用。此时该数据口不允许添加 VLAN 子接口

所有配置好的虚拟 IP 以及管理口的 IP 都可以在添加服务时被监听。

# 常见问题解决

### 问题1：umask 检查不通过

**现象**：环境检查提示 "要求 umask 值为 022"

**原因**：Ubuntu 默认 umask 是 0002

**解决**：

```bash
echo 'umask 022' >> ~/.profile
source ~/.profile
```

### 问题2：Docker 权限不足

**现象**：运行 `docker ps` 提示 "permission denied"

**原因**：用户不在 docker 组

**解决**：

```bash
sudo usermod -aG docker $USER
# 重新登录生效
```

### 问题3：管理平台安装包解压失败

**现象**：unzip 提示 "unable to get password"

**原因**：管理平台安装包是加密压缩包

**解决**：使用 `-P` 参数指定密码

```bash
unzip -P 'diew4sohTh' -o DS-S40-xxx.zip
```

### 问题4：安装提示"目录存在不能执行安装步骤"

**现象**：运行管理平台安装程序时报错退出

**原因**：安装脚本检测目录不为空就退出

**解决**：参见 [绕过目录检查（关键步骤）](#绕过目录检查关键步骤)

### 问题5：磁盘空间不足

**现象**：安装过程中提示磁盘空间不足

**原因**：安装包 + Docker 镜像需要较大空间

**解决**：

```bash
# 检查磁盘空间
df -h /

# 如果空间不足，考虑：
# 1. 清理不必要的文件
# 2. 扩展虚拟机磁盘
# 3. 挂载新磁盘到 /var/lib/docker
```

### 问题6：Docker Storage Driver 不正确

**现象**：安装后 Docker 无法正常运行或占用空间过大

**原因**：Docker Storage Driver 不是 overlay 或 overlay2

**解决**：修改 `/etc/docker/daemon.json`，添加或修改 storage-driver 配置：

```json
{
  "storage-driver": "overlay2"
}
```

然后重启 Docker：

```bash
sudo systemctl restart docker
```

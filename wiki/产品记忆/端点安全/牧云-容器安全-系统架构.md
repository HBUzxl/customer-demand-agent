# 设计原则

在产品的构设计过程中，我们遵循以下原则，以确保系统的高效性、可扩展性和安全性。

## 模块化设计

系统采用模块化架构，将不同功能划分为独立模块，以提高系统的可维护性和可扩展性。每个模块可以独立开发、测试和部署，减少系统间的耦合度。

## 高可用性

架构设计确保系统具备高可用性，通过冗余和负载均衡等机制，确保在部分组件故障的情况下，系统仍能正常运行，提供可持续服务。

## 可扩展性

系统支持水平和垂直扩展，能够根据业务需求的增长快速增加资源。无论是增加计算能力还是存储容量，均可轻松实现，以适应不断变化的需求。

## 性能优化

通过合理的设计模式和技术选择，优化系统性能，确保在处理大量数据和高并发请求时，系统依然能够高效响应，提供良好的用户体验。

## 兼容性与可集成性

系统设计时考虑与现有系统的兼容性，确保能够与其他应用和服务无缝集成，支持多种数据源和数据格式，满足业务需求。

## 简洁性

在设计中力求简洁性，采用清晰的接口和协议，降低系统学习和使用的难度，提高开发和维护的效率。



# 系统架构图

下面以 K8S 为例阐述云原生环境下的架构，诸如 Docker 等环境下系统架构类似，只是安装流程可能不一样。

## 服务端

服务端是整个架构的中枢，其中 Gateway 作用用户视角的统一入口，ConfigCenter 作为统一的配置中枢为产品所有的配置提供集中的管理，Grpc Server 则是与集群接入和探针管理的统一入口。

![](../images/system-architecture-server.png)


## 集群接入

下图展示了服务端与集群的接入细节。集群的每个节点中（如有需要）都会安装 Agent，并且其中一个 Master 节点会额外安装一个与集群 Api Server 通信的 Connector 组件。

![](../images/system-architecture-cluster-access.png)






## 探针

下图展示了 Agent 的架构图。探针在安装时会通过集群的 Job 下发到符合条件的所有 Node（即 Server），然后从集群内迁移到集群外，通过 Node 所在的 Systemd 管理（不同系统有不同的实现）。Agent 实际上是一组进程的统称。在工作时， Manager 会负责管统一的生命周期和资源管控，Agent 负责对操作系统环境进行抽象，提供统一的接口给 Plugin-Runner，而 Plugin-Runner 则提供了一个受控且易于扩展的安全能力运行时。

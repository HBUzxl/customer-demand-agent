## 攻击源分析

攻击源分析以源 IP 的形式统计系统中所有蜜罐入侵日志的信息。用户可以在此处查询到网络中最具威胁的源 IP，以及其详细分析。

### 攻击源分析列表

![图4.1-2 攻击源分析列表](images/upload_0ed3a5572b67c42e7f051dea0b45405d.png)

<center>
图4.1-2 攻击源分析列表
</center>




攻击源分析列表默认显示 30 天内系统感知的蜜罐入侵日志源 IP 分析，并以入侵日志数量排序。

1. 内容详解
   - 入侵日志数：表示源 IP 关联的蜜罐入侵日志数量
   - 最后攻击目标/最后攻击内容/最后攻击时间：表示源 IP 关联的最新一条蜜罐入侵日志信息
2. 相关操作
   - 筛选源 IP
     - 点击 “筛选”，输入希望筛选的 IP 即可
   - 筛选数据时间范围、风险级别和处置状态
     - 点击 “30 天内” 下拉菜单，选择数据时间范围，即可筛选统计的数据时间范围
     - 勾选或取消勾选“不显示风险级别为‘无’的事件”，即可切换统计的数据的风险状态
     - 勾选或取消勾选“不显示状态为‘已处置’的事件，即可切换统计的数据的处置状态

## 攻击者画像

攻击者溯源功能是谛听通过特殊的智能溯源蜜罐实现的，能够实现对攻击者更深一步的信息挖掘的功能。可获得的信息包含攻击设备指纹、攻击者社交账号、攻击者位置等关键信息。

![图4.1-4 攻击者画像列表](images/upload_925aad436468419662d1729cc40c64a4.png)

<center>
图4.1-4 攻击者画像列表
</center>





“攻击者画像列表”页面记录对入侵者的溯源信息，以浏览器指纹和真实外网 IP 溯源到攻击者的真实自然人。

- 点击“筛选”，可以根据 IP、社交信息、位置等信息筛选画像
- 选择画像，可以在“更多操作”中下载、删除所选日志
- 点击画像右侧“查看详情”可以进入画像详情

攻击者画像详情信息包含基础信息、设备指纹、社交信息、位置信息、补充信息。

1. 基础信息

   ![攻击者画像 - 1. 基础信息](images/upload_612bc153a83c4a8d731da0ac46347d1f.png) 

   <center>
    图4.1-5  基础信息
    </center> 


   - “查看关联入侵日志”可以查看所有该攻击者相关的蜜罐入侵日志

2. 设备指纹

   设备指纹展示该攻击者攻击时的源设备信息。包含攻击时使用的主机信息、浏览器指纹等。

   - 是否是触控屏：例如平板电脑、触屏手机
   - 是否是移动端：笔记本电脑、台式电脑均不属于移动端
   - 浏览器指纹：由内置算法生成的浏览器指纹，可标记唯一的攻击源浏览器

3. 社交信息

   社交信息是攻击者攻击时同时可能登录的一些社交账号信息。如 163 账号信息、qq 账号信息等。

   社交信息不一定每次溯源都能获取到，依赖于攻击者攻击时，社交账号的使用情况。例如若攻击者未在浏览器登录上述社交账号，或社交账号未绑定过邮箱、手机号等信息，则无法获取，属正常现象。

4. 位置信息

   位置信息是溯源攻击者网络 IP 的位置信息来获取的。

   - 真实外网 IP 位置信息，是攻击者攻击时真实的外网 IP。
   - 真实内网 IP，是攻击者攻击时，主机所处局域网的 IP。
   - 代理 IP，是攻击者访问外网时使用的最外层 IP。一般是攻击者使用的代理 IP，也可能是攻击者的真实外网 IP
   - 直接攻击 IP，是攻击者攻击探针时，和探针直接通信的 IP。和蜜罐入侵日志中获取的 IP 相同

5. 补充信息

   补充信息中包含 MySQL 反制、Git 反制、Burp IP 溯源等特殊的溯源反制获取的信息，可能包含主机名、邮箱、用户名、真实 IP 等信息。

   补充信息和蜜罐配置、攻击者客户端环境有关，若未使用包含相应功能的蜜罐，或攻击者本机无相应配置信息，则无法获取，属于正常现象。

## 实时大屏

![图4.1-8 配置实时大屏](images/upload_f036e8f36e76e8a65fc1f515b9b20f59.png)

<center>
图4.1-8 配置实时大屏

实时大屏能够更方便地监控系统运行情况和入侵告警情况。
系统支持两种大屏，鼠标悬浮到大屏略缩图上，点击“启动大屏”可以开启实时大屏；点击“调整配置”，可以自定义大屏的细节配置，例如大屏标题、统计时间等。

1. 威胁监控大屏

   ![实时大屏 - 1. 威胁监控大屏](images/upload_7d5ee6de8b3a99b36c91482b1ced9be4.png)

   <center>
    图4.1-9  威胁监控大屏
   </center>


   “威胁监控大屏”主要用于展示实时告警信息。可以在略缩图的“编辑配置”处指定顶部标题和统计时间范围。

   - 被攻击最多的探针、业务组和最具威胁源 IP，按照日志威胁等级智能分析威胁情况并进行排序。数字表示日志总数，不一定与排序完全对应。
   - “最新告警信息”仅显示 未处置 与 处置中 的告警信息。方便排查
   - 中部“实时威胁状态”中，关系图表示业务组拓扑，橙色的业务组表示存在告警信息。

2. 实时大屏

   ![实时大屏 - 2. 实时大屏](images/upload_a717b94c41c9b60fdcdae685ebbb8465.png)

   <center>
    图4.1-10  实时大屏
   </center>


   “实时大屏”用于实时呈现系统捕获到的入侵数据。

   - 界面上方显示当前系统状态，如时间、负载、探针状态等
     - 左上角显示大屏名称和当前时间，大屏名称可以在系统“实时大屏”页面自定义
   - 中部的左侧和右侧为入侵事件占比、被入侵服务占比，饼图为历史总览统计
   - 最中间是最近告警信息，以表格的形式呈现最新 10 条日志信息
   - 下方左右两侧分别为 被入侵探针 TOP5、源 IP TOP5，柱状图为历史总览统计
   - 下方中央为入侵事件时间分布，以柱状图的形式呈现最近入侵日志的时间，其中横轴表示时间，纵轴表示入侵次数

### 蜜罐入侵日志列表

<center>
图4.2-1 蜜罐入侵日志

“蜜罐入侵日志列表”页用于记录系统捕获到的入侵事件。单条日志代表一次入侵从开始到结束的全部入侵事件的集合，用户可以从这里查找到关于此次入侵最详细的记录。

1. 相关操作

   - 下载日志
     - 勾选需要下载的日志，在“更多操作”中点击‌“下载所选日志‌”即可
     - 持下载 csv、json和 xls 格式，csv、xls 适合阅读，json 适合大日志量或自动化解析
   - 删除日志
     - 勾选需要删除的日志，在“更多操作”中点击‌“删除所选日志‌”即可
   - 筛选日志
     - 点击 “筛选”，配置筛选项并 “确定”即可

2. 相关定义

   - 风险级别：用于对整个入侵的行为进行定义。

     - 高危：由智能算法识别出，会严重影响内网安全的行为

     - 中危：由智能算法识别出，会影响内网安全的行为

     - 低危：由智能算法识别出，会轻度影响内网安全的行为

     - 无：入侵者只进行了 tcp 连接，无其他操作

     > **注意：** 这里的风险程度只表示入侵者未进行高危操作。但是侵入内网本身也代表着内网被攻破，建议立即进行危险排查

     - 攻击中发生的事件：此次入侵中包含的所有事件的类型

<center>
图4.2-7 ARP欺骗日志

ARP 欺骗日志记录探针感知到的 ARP 欺骗攻击

1. 含义

   - 探针：受到 ARP 欺骗攻击的探针

   - 目的 IP：探针上受到攻击的 IP

   - 伪装 IP：ARP 欺骗报文中，被替换了 MAC 地址的 IP

   - 筛选：点击右上角筛选，可以根据伪装 IP、目的 IP、探针、时间对日志进行筛选

   - 删除日志：勾选需要删除的日志，在“更多操作”中点击‌“删除所选日志‌” ，再点击确认即可

## 诱饵设置

诱饵是指在黑客的攻击路径上，尤其是信息收集的过程中，有意地设置一些“敏感数据”，以将其攻击转移至蜜罐中，最终达到保护真实资产、溯源取证的目的。

诱饵设置前，建议先配置好合适的 蜜网-蜜罐-探针 伪装欺骗系统，设置诱饵后才能达到最大的效果。

### GitHub 互联网诱饵



![图4.3-8 诱饵设置 - Github互联网诱饵](images/upload_6c0810fa01ae59fa0edaf97184eb691e.png)

<center>
图4.3-8 诱饵设置 - Github互联网诱饵
</center>

GitHub 互联网诱饵是在公开的代码存放网站 Github 中设置一个虚假的代码仓库，并将探针诱捕地址暗藏其中。由于 GitHub 上有大量的信息泄漏代码，黑客在外网信息收集时常常会在网站上检索企业相关信息，此时就可能被诱饵误导，进入探针蜜罐系统中。

Github 诱饵设置前，注意需要先将特定的探针部署到 DMZ 区，探针地址输入对应的公网地址。这样诱饵将黑客引到探针时，才能继续诱捕。

GitHub 诱饵设置时，建议使用不含敏感信息的新账户上传。为了最大程度提升诱导效应，建议输入包含企业信息的项目说明、项目名称、项目描述，以尽可能被黑客检索到。

### 主机诱饵



![图4.3-9 诱饵设置 - 主机诱饵](images/upload_b473b221b407963f34d2ac3d8dabe779.png)

<center>
图4.3-9 诱饵设置 - 主机诱饵
</center>

主机诱饵是在内网的主机中设置一些虚假信息，以误导攻陷该主机的黑客。由于黑客进入内网、攻陷主机后，会首先在主机上进行网络、文件、缓存等特殊数据的收集，以准备下一步的渗透。此时若主机上包含一些信息诱饵，就能将其引诱到蜜罐，进而进行诱捕。

主机诱饵按主机类型可分为 Linux、Windows 两种，各自包含若干不同类型的诱饵，单独或组合使用皆可。使用前，注意先将探针部署到该主机可访问到的网段，这样黑客被误导才能进入探针蜜罐系统中。



### 文件诱饵



![图4.3-10 诱饵设置 - 文件诱饵](images/upload_7bf2ac4cf9d59559c486b943e2186f97.png)

<center>
图4.3-10 诱饵设置 - 文件诱饵
</center>

文件诱饵是设置在内网主机中的虚假文件，若黑客进入内网、攻陷主机并打开该虚假文件，文件将向系统发送告警，方便管理员及时处置入侵行为。 每个诱饵都含有唯一的指纹，建议分别设置到不同的主机中，方便管理员定位失陷主机。

文件诱饵包含 Word、Excel、PowerPoint 三类格式，可使用系统内置的文件，也可上传自定义文件，可按需配置。

文件诱饵使用时，必须配置相应的 “文件诱饵“蜜罐，且绑定到探针上（建议探针部署到公网）。然后在生成文件诱饵时，输入部署了文件诱饵蜜罐的探针地址（必须是攻击者可以访问到的地址，协议、域名或 IP、端口都要写准确，例如 https://example.com:8888），然后将生成的文件诱饵散布到存在失陷风险的主机、区域，即可完成诱饵部署。

## 多网口探针说明（仅使用了多网口硬件探针的系统）

多网口探针是指系统配合官方 A1500S/H、A2000H、A4000H 等标准型号的多网口探针设备，提供的单探针管理大量 IP 的功能。

当硬件探针设备上架后，探针列表将显示对应的多网口探针，多网口探针的使用方法和普通探针有较大区别，本章节将进行具体说明。

部署多网口探针后，列表将额外展示探针的” IP 数/IP数上限”信息，方便管理多网口硬件探针上的空闲 IP。如下图：

</center>

在多网口探针的探针详情处，“可监听IP”相关配置将会替换为 “网口管理”，如图：



![图4.4-8 探针详情-网口管理（多网口探针）](images/upload_f99e30995b14de33e5570c8533165d04.png)

此处将显示当前探针的管理口、数据口、VLAN 口，以及接口上的 IP 信息。

1. 操作说明

   - 点击列表右上角 “添加 VLAN接口”，可以基于数据口添加 VLAN 口（仅多网口硬件探针支持）

   - 点击接口右侧的 “编辑网关”，可以设置该接口的下一跳网关地址。配置正确的网关地址，可以借由网络中已有的网关设备，模拟跨 VLAN 通信等复杂的网络场景

   - 点击接口右侧的“配置 IP”，可以配置接口的 IP

   - 点击列表上方 “导入配置”，可以以 Excel 表格的形式，批量导入探针的 IP 配置信息（仅多网口硬件探针支持）

2. 其他注意事项

   - 管理口不能通过界面编辑 IP、网关，以防操作失误、导致探针连接断开

   - IP 总数不能超过当前探针型号的监听 IP 数上限

   - 数据口添加 VLAN 子接口后，需要接到交换机的 trunk 口使用。此时该数据口不允许配置 IP、网关；反之，数据口配置了 IP、网关后，需要接到交换机的 access 口使用。此时该数据口不允许添加 VLAN 子接口

   所有配置好的虚拟 IP 以及管理口的 IP 都可以在添加服务时被监听。
   
   对于多网口硬件探针，可在“配置探针”弹窗中选择开启“自动 Ping 网关”，用于支持探针保活。

用户可通过“告警配置”页面对告警阈值、邮箱告警、Webhook 告警的配置进行管理，实现入侵发生时的及时通知。

2. 告警阈值

   告警阈值即达到设定条件触发告警，告警阈值类型包括两类：

   - 威胁感知告警

     - 可以选择开启 蜜罐入侵、端口探测、ping 扫描、arp 欺骗、溯源日志 五种告警

     - 蜜罐入侵告警阈值：配置蜜罐入侵告警的最低阈值。例如选择“低危”时只会在感知到低危、中危或高危入侵事件才会发出告警

       - 注：系统关于威胁日志的汇总告警，若设置开启，则需设置汇总间隔。在收到告警范围内的日志后立即触发告警汇总，汇总间隔内不进行任何告警，直到汇总间隔结束，系统发出汇总邮件，内容包含这段时间内触发日志的数量、触发日志的最高风险级别、当前未处置的告警数量 等信息

     - 威胁告警业务组：触发邮件告警的业务组范围。探针感知到威胁事件时，若探针所属业务组不在邮件告警业务组中，则不会发送通知邮件

     - 可以选择开启 CPU、内存、磁盘、探针连接断开、探针连接恢复、探针服务异常 六种告警

### 攻击引流

攻击引流可以让 HIDS、IDS、 负载均衡等设备将识别到的恶意流量代理转发到探针上的蜜罐服务， 扩大伪装欺骗系统的覆盖范围。

要使用此功能，需要设定具体接收引流流量的探针，并且在联动设备上配置探针地址、蜜罐服务端口，并通过代理协议 (Proxy protocol) 转发恶意流量。详细方案可咨询产品技术支持。

配置好后，可以实现联动设备 IP 透传的效果，如图：



![图4.8-10 攻击引流 IP 透传效果](images/upload_941ce6ab5b5bf7bc2dc11f72924c64a2.png)

<center>

</center>

如果想开启验证，请在产品上将验证开启，然后将生成的验证密钥配置到联动设备上。此时如果攻击者按照联动流量的形式，发送了不符合验证的流量的话，蜜罐就会拒绝。

 

注1：攻击引流仅对蜜罐入侵日志生效，端口探测日志、Ping日志 无法进行源 IP 透传。

注2：攻击者经过联动设备引流，访问谛听的 探针:蜜罐服务 时，如果探针未启用联动，那么会无法正常访问服务。反之攻击者如果直接访问已经启用了联动功能的探针的话，会无法正常访问Mysql 反制、MariaDB、FTP 、telnet 四种蜜罐，其他蜜罐正常

添加白名单后，系统将不会记录/上报/告警符合白名单内容的威胁事件。点击右上角 “添加白名单” 即可添加新的白名单。如下图：



![图4.8-22 逐条输入白名单](images/upload_e5395a48de98731baf02ec4df2fc508f.png)

<center>
图4.8-22 逐条输入白名单

1. 逐条输入白名单

   - 可选择TCP、UDP、ICMP 和全部协议

   - 源 IP、源端口、目标 IP、目标端口不能全为空。IP支持 ipv6格式，支持输入网段，例如 192.168.23.0/24。端口支持输入端口范围，例如 23-600

   - 勾选生效范围时，若全部勾选，则表示符合白名单的威胁事件不会记录日志、告警和发送Syslog。若不勾选日志记录，但勾选告警通知、Syslog，则表示符合白名单的威胁事件会记录日志，但不会告警、发送 Syslog。以此类推

   - 勾选访问限制时，若勾选“不允许访问蜜罐”，则加白后无法访问蜜罐

   - 注，若攻击者在极短时间内，同时探测了白名单中的端口和非白名单中的端口，那么单条日志仍然会完整记录，不会加白

   

   ![白名单 - - 注，若攻击者在极短时间内，同时探测了白名单中的端口和非白名单中的端口，那么单条日志仍然会完整记录，不会加白](images/upload_32e9c3f55efee52716bcd7f60189569e.png)

   <center>
    图4.8-23  批量输入白名单
    </center>

2. 批量输入白名单

   批量输入白名单时，原理与逐条输入基本一致。点击确定后，会一次性保存多条白名单信息。

   - 每行一条白名单。每条内可以直接指定源 IP，也可以用分隔符的方式分别指定全部四要素：

     - 例子：192.168.10.2:77;192.168.10.3:80;udp

     - 第一个英文分号前表示源 IP 与端口, 第一个英文分号到第二个分号之间表示目的 IP 与端口。IP与端口之间以英文冒号分隔

     - 第二个英文分号后表示协议，可以输入 tcp、udp、icmp，不指定时表示全部。但注意协议为 全部 和icmp的时候，只能指定源 IP，无法指定源端口、目的 IP 和 目的端口

     - 不需要输入端口时，英文冒号可以省略。不需要指定目的信息、协议时，可以省略一行最末尾的英文分号

     - IP 为 ipv6 格式时，若需要输入端口，则将 IP 以英文符号 [] 扩住来输入

   - 示例：

     - 192.168.10.12——协议为“全部”，直接指定源IP

     - 192.168.10.12;192.168.10.13;tcp——协议为TCP，指定源IP、目的IP

     - ;192.168.10.12;udp——协议为UDP，指定目的IP

     - 192.168.10.13;;icmp——协议为ICMP，指定源IP

     - 192.168.10.1/16:80-88;192.168.11.1/16:80-88;tcp——协议为TCP，指定四要素

     - fe80::52cf——协议为“全部”，指定IPv6的源IP
     - \[fe80::52cf]:80;\[fe80::52cf]:88;tcp——协议为TCP，指定IPv6的四要素

还原备份时，系统中的大部分配置将在覆盖还原前清空，替换为备份中的配置。注意：

- 备份存在适用版本，仅能在适用的系统版本上进行还原

- 还原探针时，将跳过已创建但不在备份中的探针配置

  - 例如，如果系统目前存在某个探针，而备份中没有，那么这个探针不会在还原的时候被删除。如果备份中有，那么该探针的基础信息、服务配置、IP配置、网口配置等会在还原时被还原成备份中的配置

  - 注，若远程设备本身未安装探针，还原配置无法自动创建远程的探针

- 还原时会自动创建蜜网蜜罐，但将跳过已创建的蜜网、蜜罐

  - 例如，如果系统存在某个蜜网蜜罐，如果备份中无，蜜罐也不会被删除。如果备份中有，蜜罐也不会被更新配置或重新创建

  - 当系统中不存在某个蜜网蜜罐，而备份中有，那么还原时会自动创建蜜罐。蜜罐创建完成后不会自动启动，需要手动到蜜罐列表启动

- 还原时将跳过当前用户。即当前用户不会被删除、更新配置

 

还原配置会耗费一段时间，还原期间请勿操作系统，防止数据还原异常。

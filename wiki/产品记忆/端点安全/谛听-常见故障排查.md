## 蜜罐受到入侵或探测后，没有生成日志？

先检查下攻击源 IP 或者目的 IP 是否被加入到白名单中，加入白名单后入侵或者探测都不会生成日志

## Windows sever 2008 R2 蜜罐入侵日志中，日志下载不成功。安装探针时，探针下载不成功

这个应该和服务器的安全限制有关，在 win7 下是可用的。建议更换浏览器

## SMTP 配置好后，日常使用时未正常发送告警邮件

* 测试 SMTP 配置，确定服务配置正常
* 查看告警阈值，确定事件在告警范围内，且当前未进入告警间隔
* 确定该事件没有被添加白名单

如果以上三条都正常，可能是因为邮件队列卡住。需要重启 dsensor_server 容器：
```
sudo docker restart dsensor_server
```

## Redis 等数据库蜜罐、自定义 Web (PHP) 蜜罐在自定义配置后，无法正常启动，一直关闭

如果自定义的数据库文件（ .rdb 和 .sql）是 dump 下来的，可能是版本不兼容：

* redis 蜜罐的 redis 版本是 3.2.6 ，不支持 4.0 以后版本的 .rdb 文件
* php 蜜罐是 php7.0，sql 版本是 10.1.41-MariaDB-0+deb9u1

## 谛听所在系统磁盘空间不足，如何优化清理无用文件

从根目录开始对占用磁盘较高的目录依次执行 du -sh ./*，查看目录占用情况，对一些文件进行删除

1. 确认日志数据占用情况
/data/d-sensor/data 数据库文目录件，这里体现实际数据占用情况

2. 确认镜像文件占用情况
/var/lib/docker
当用户交付定制蜜罐较多或部署了较多扩展蜜罐（Oracle、Windows）情况下，该目录可能占用较大
可以尝试迁移docker镜像目录，参考问题

3. 删除无用文件
/data 历史安装包可删除
/data/bak 备份文件可以删除
/data/d-sensor 历史版本安装文件（bin、zip)可以删除
/data/d-sensor/logs/server中 queue.log.数字的、app.log

# 升级管理节点

因DS-S40-25.07.0系列版本安装包较大且更新了系统升级组件，所以暂不支持旧版本在管理节点界面升级到DS-S40-25.07.0系列版本，只支持在后台升级到该版本。

DS-S40-25.07.0系列版本升级到后续新版本时将继续支持界面升级。

## 检查当前版本和待升级版本

本文档仅适用于从 DS-S40-19.01.001 及之后的版本开始升级，不适用于 DS-S40-19.01.001 之前的版本升级。若需要从 19.01.001 之前的版本升级，请先升级到 19.04.003 版本，再从 19.04.003 的版本开始升级。

另外，若需从 DS-S40-20.07.102 以及之前版本升级到 **DS-S40-20.09.001** 以及以后的版本，需要额外进行数据迁移操作。**请不要直接升级**，而是参考 "谛听 20.09.001 数据库升级与数据迁移说明"文档进行操作。

另外，由于各版本的安装命令可能有细微区别，本章节中**升级失败回滚到旧版本这一步骤，请尽量按旧版本对应的部署文档操作**。

## 工具准备

1. 新版本产品安装包
   - 软件系统安装包
   - 蜜罐安装包
   - （可选）蜜罐拓展包
2. 旧版本产品安装包（用于升级失败时的回滚）
   - 软件系统安装包
   - 蜜罐安装包
   - （可选）蜜罐拓展包
3. 安装包解压密码

注：产品安装包、安装包解压密码由长亭技术人员通过 [产品发布平台](https://release.chaitin.net/product/version/184c4097-c070-4188-a0e4-5f4abbd027a0/list?title=%E8%B0%9B%E5%90%AC) 进行选择、下载和提供。产品安装包体积较大，若需发送建议通过邮箱、U 盘的方式。

## 停止服务并备份数据

1. 确认系统版本合适后，登录 manager 节点，进入谛听部署目录

```bash
cd /data/d-sensor
```

2. 进入 docker-compose.yml 文件所在目录，停止所有服务

```bash
docker-compose down
systemctl stop docker_escape_detector
systemctl stop upgrader_executor
systemctl stop minion_linux
```

3. 备份已有的数据

```bash
mkdir -p /data/d-sensor-backups
cp -r /data/d-sensor/data /data/d-sensor-backups/data
cp -r /data/d-sensor/data1 /data/d-sensor-backups/data1
cp -r /data/d-sensor/config /data/d-sensor-backups/config
```

## 升级软件

1. 检查docker版本，确保docker版本为20.10.17或以上的稳定版。

```bash
docker –version
```

2. 上传新版本的软件升级安装包"DS-S40_xxxx.zip"到原部署目录下，进入部署目录，将软件升级包覆盖解压到原部署目录

```bash
unzip DS-S40-software-installer-xxx.zip
./d-sensor-4-software-installer_xxx.bin -C /data/d-sensor
unzip -o honeypots-2-software-installer_xxx（新版本）.zip -d /data/d-sensor
```

当解压要求输入 password 时，需使用新版本安装包的解压密码进行操作。

3. 进行软件系统和蜜罐类型的升级

   执行 installer 时，如果该型号设备需要安装虚拟机蜜罐，安装过程中选择 "软件+虚拟机蜜罐拓展（sw+vm）"。否则选择"软件（sw）"，若出现"will you enable vm manager(y/n)"选择n即可。

```bash
./install.sh
./installer
```

> **版本差异说明**：25.07（本版本）升级时需要运行 ./installer。25.12 等新版本执行 .bin 后安装已自动完成，不需要额外运行 ./installer。

4. 确认服务正常启动

```bash
docker ps -a
```

确保容器状态都为"up"，如下图所示：

![docker容器状态](images/upload_82a4fedf60d9dde0b229059c8e68f905.png)

5. 在 /data 目录下加载预置模版

```bash
cd /data
./generate_preset.sh
```

若安装目录不是默认目录，执行时需要指定对应目录：

```bash
./generate_preset.sh /data/d-sensor
```

6. 访问管理地址并登陆。若能正常访问管理界面，而且页面最下方显示的产品版本更新到了新的版本，则说明安装成功：

![版本升级成功](images/upload_8ed8eee8c8afb4ee2bf7f9abe99bd9b8.png)

7. 安装新版本蜜罐拓展包（如果拓展包没有更新，此步骤可跳过）

   - 虚拟机蜜罐：
     - 确保安装时已开启虚拟机蜜罐模块：执行"docker ps"查看有没有"vm_domain"容器。若没有，则进入 docker-compose 所在文件夹，执行 docker-compose down，然后重新执行安装脚本 ./installer，并选择 "软件+虚拟机蜜罐拓展（sw+vm）"
     - 将拓展包文件解压到 /data/libvirt/images
     - 执行 "docker restart vm_domain"，再执行 "docker restart dsensor_redis"即可
   - .zip 后缀名蜜罐：解压到安装目录，然后在解压文件夹内运行 ./install.sh

## 虚拟机蜜罐迁移

针对22.04版本以前部署的虚拟机蜜罐，需要重新创建。

针对23.12版本以前部署的虚拟机蜜罐，需要迁移虚拟机蜜罐镜像路径并重置，迁移操作如下：

1. 迁移路径

```bash
cp -r /var/lib/libvirt/images/* /data/libvirt/images/
```

2. 读入镜像信息

```bash
docker restart vm_domain
docker restart dsensor_redis
```

3. 在管理平台「蜜罐管理」界面重置虚拟机蜜罐

## （升级失败时）数据回滚

注意：由于各版本的安装步骤可能有细微区别，**升级失败回滚到旧版本的具体操作，请尽量按旧版本对应的部署文档操作**。

1. 进入原部署目录，在有"docker-compose.yml"文件的目录下停止所有服务：

```bash
cd /data/d-sensor
docker-compose down
```

2. 删除升级失败数据，将备份数据还原到部署目录

```bash
rm -rf /data/d-sensor/data
cp -r /data/d-sensor-backups/data /data/d-sensor/data
cp -r /data/d-sensor-backups/data1 /data/d-sensor/data1
cp -r /data/d-sensor-backups/config /data/d-sensor/config
```

3. 将旧版本安装包上传到部署目录下，解压旧版本安装包，重新部署

   - 若旧版本管理节点安装包是zip包（即23.12.001版本之前）：

```bash
unzip -o d-sensor-4-software-installer_xxx(旧版本).zip -d /data/d-sensor
unzip -o honeypots-2-software-installer_xxx(旧版本).zip -d /data/d-sensor
./install.sh
./installer
```

   - 若旧版本管理节点安装包是bin包（即23.12.001版本及以后）：

```bash
unzip -o honeypots-2-software-installer_xxx(旧版本).zip -d /data/d-sensor
./install.sh
unzip DS-S40-software-installer-xxx(旧版本).zip
./d-sensor-4-software-installer_xxx(旧版本).bin -C /data/d-sensor
./installer
```

4. 在安装目录下加载预置模版

```bash
cd /data
./generate_preset.sh
```

若安装目录不是默认目录，执行时需要指定对应目录：

```bash
./generate_preset.sh /data/d-sensor
```

5. 确认服务正常启动

```bash
docker ps -a
```

确保容器状态都为 up。

6. 安装旧版本蜜罐拓展包

   - 虚拟机蜜罐：
     - 确保安装时已开启虚拟机蜜罐模块：执行"docker ps"查看有没有"vm_domain"容器。若没有，则进入 docker-compose 所在文件夹，执行 docker-compose down，然后重新执行安装脚本 ./installer，并选择 "软件+虚拟机蜜罐拓展（sw+vm）"
     - 将拓展包文件解压到 /data/libvirt/images
     - 执行 "docker restart vm_domain"，再执行 "docker restart dsensor_redis"即可
   - .zip 后缀名蜜罐：解压到安装目录，然后在解压文件夹内运行 ./install.sh

7. 访问管理地址并登陆。若能用老密码正常登陆，页面最下方显示的产品版本为老版本，日志等数据仍保留，则说明回滚成功。

# 升级探针节点

## 检查待升级版本

探针不一定每个版本都会更新，如果新版本的探针有更新内容，系统会在 Web 管理界面 -> 探针列表 进行提示。

升级时，请先选择少量探针备份后升级，确认没有影响后，再在界面上进行全量升级。

## 备份

1. 登录探针节点，进入探针安装目录

```bash
cd /data/agent
```

2. 停止探针服务

```bash
sudo ./chaitin-bootstrap stop
```

3. 备份探针安装包与数据

```bash
mkdir -p /data/agent-backups
cp -p /data/agent/chaitin-agent.zip /data/agent-backups
```

## 升级服务端探针

升级管理节点时，如果探针版本有更新，会自动升级服务端探针。

如果需要在未升级管理节点的情况，直接升级服务端探针，进入 系统配置 -> 升级与更新 -> 更新版本，上传新版本的探针升级包即可。

注意：直接升级服务端探针前，请确保新版本探针兼容当前系统，否则可能出现无法绑定服务、无法正常告警的问题。

![升级服务端探针](images/upload_f5b3857a368d40851d9a3ac32ebf5921.png)

## 升级远程探针

1. 进入 探针管理-探针管理 页面，若本次更新了探针版本，可以看到探针升级提示标志。选中需要升级的探针，点击 "升级探针"，如下图：

![升级远程探针](images/upload_d4e74a46b5731fd7115cce2e63bc864d.png)

2. 在弹窗中确认探针升级的信息后，点击 "确定"，系统将提示 "探针升级请求发送成功"，如下图：

![探针升级确认](images/upload_8efb485712a625b554ba4fd973e2834f5.png)

3. 升级请求发送成功后，探针暂时 "离线"，片刻后重连，变为 "正常"，则探针升级成功。

## （升级失败时）数据回滚

### Linux 系统

1. 登录探针部署机器，进入探针部署目录，停止并删除失败探针：

```bash
cd /data/agent
sudo ./chaitin-bootstrap stop
sudo ./chaitin-bootstrap remove
```

2. 进入备份探针安装包目录，将备份探针安装包解压到部署目录下

```bash
cd /data/agent-backups
unzip -o chaitin-agentbackups.zip -d /data/agent
```

3. 重新部署备份探针

```bash
sudo chmod +x ./chaitin-bootstrap
./versions/v{备份探针版本}/chaitin-agent
sudo ./chaitin-bootstrap install
# Install detection agent for dsensor service:    [  OK  ]
sudo ./chaitin-bootstrap start
# Starting detection agent for dsensor service:   [  OK  ]
```

4. 确认服务正常启动

```bash
ps -axu | grep chaitin_agent
```

确保能看到两个 chaitin_agent 进程。

### Windows 系统

1. 登录探针部署机器，进入部署探针的 chaitin-agent 文件夹

2. 停止原探针服务。双击"uninstall.bat"可执行文件进行卸载

3. 解压备份的"chaitin-agentbackups.zip"，覆盖原 chaitin-agent 文件夹

4. 再次进入 chaitin-agent 文件夹，重新安装。双击"install.bat"可执行文件进行安装

5. 确认服务正常启动。登录谛听管理界面，确保探针状态为 "正常工作"

# 升级蜜罐

1. 加载了新的蜜罐安装包后，进入 蜜罐管理-蜜罐管理 页面，可以确认系统是否有可升级的蜜罐

2. 确认某蜜罐需升级后，点击蜜罐右侧的 "升级蜜罐" 按钮

3. 等待蜜罐服务升级完毕

注：升级蜜罐可能花费数十秒，升级时会提高管理节点的 CPU 占用。为了避免机器性能压力过大影响使用，不建议短时间内升级太多蜜罐，可分批进行。

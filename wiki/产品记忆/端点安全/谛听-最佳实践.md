## 蜜网部署最佳实践

### 部署原则

1. **贴近真实资产**：蜜罐 IP、端口、服务应与真实资产相似，提高诱骗效果
2. **隔离部署**：蜜网与真实网络隔离，防止攻击者以蜜罐为跳板
3. **分层部署**：核心区域、DMZ、办公网各部署不同类型蜜罐
4. **合理配比**：高交互蜜罐（SSH/RDP）少量部署，低交互蜜罐（Web/数据库）批量部署

### 典型部署架构

```
互联网 ──► DMZ 区域
             ├── Web 蜜罐（WordPress/Jenkins/Nexus3）
             ├── 数据库蜜罐（MySQL/Redis/MongoDB）
             └── 特殊缺陷蜜罐（fastjson/Shiro/Struts2）

内网 ──► 核心区域
           ├── SSH 蜜罐（CentOS/Ubuntu）
           ├── RDP 蜜罐（Windows 7/10/2016）
           └── 数据库蜜罐（Oracle/MSSQL/PostgreSQL）

工控网络 ──► 工控区域
               ├── IEC104 蜜罐
               ├── Modbus 蜜罐
               └── S7 蜜罐
```

### 资源规划

| 场景 | 推荐配置 | 参考蜜罐数量* |
|------|---------|------------|
| 易捷版 | 2核 / 8GB / 500GB | ~10 个 |
| 标准版 | 4核 / 16GB / 1TB | ~30 个 |
| 尊享版 | 16核 / 64GB / 1TB+ | ~100 个 |

> *蜜罐数量为估算值，实际取决于蜜罐类型与资源消耗。高交互蜜罐（SSH/RDP）资源开销较大，Web/数据库蜜罐开销较小。

## 日志与排错

### 各服务日志位置

| 服务 | 容器内路径 | 宿主映射 |
|------|-----------|---------|
| Server (Django) | `/web/logs/app.log` | `./logs/server/` |
| Supermario | `/app/logs/` | `./logs/supermario/` |
| Nginx | `/var/log/nginx/` | `./logs/nginx/` |
| Upgrader | `/app/logs/` | `./logs/controller/` |

### 常见排错路径

| 问题 | 检查位置 |
|------|---------|
| API 返回 401 | `logs/server/app.log` → 搜索 `sso_token_invalid` / `login_required` |
| 蜜罐启动失败 | `logs/supermario/` → 搜索 `hen` / `docker` 相关错误 |
| Agent 离线 | `logs/supermario/` → 搜索 `rpc` / `agent` 连接错误 |
| 事件未上报 | `logs/supermario/` → 搜索 `consumer` / `batch` |
| 告警未触发 | `logs/supermario/` → 搜索 `dispatcher` / `alarm` |
| 数据库慢查询 | `logs/server/app.log` → Django `db.backends` logger |
| 缓存不一致 | 检查 Redis `cmodel` hash + `{table}_m` set → 执行 `robjects.flush()` |
| 升级失败 | `logs/controller/` → Upgrader 日志 |

### 日志级别调整

**Server**：修改 `server/src/logging.conf`

**Supermario**：修改 `config/supermario.toml`

```toml
[pkg.logger]
  Level = "debug"   # 改为 debug / warn / error
```

修改后需重启对应容器。

## 性能调优

### PostgreSQL

调整 `config/postgresql.conf`，关注以下参数：

- `shared_buffers`：建议设为系统内存的 25%
- `work_mem`：排序和哈希操作的内存
- `effective_cache_size`：建议设为系统内存的 75%

### Supermario

调整 `config/supermario.toml` 中的批处理参数：

```toml
[server.batch]
  potTimerD   = 30    # 蜜罐事件批处理间隔（秒）
  scanTimerD  = 30    # 扫描事件
  connTimerD  = 60    # 连接事件
  alarmTimerD = 30    # 告警检查
```

事件量大时可适当缩短间隔，但会增加 CPU 和数据库负载。

### Redis

- 启用 `CacheModel = true` 减少 PostgreSQL 查询
- 监控 Redis 内存使用，必要时调整 `maxmemory` 策略
- Django 缓存同步：通过 `CachedManager.flush()` 定期回写

## 安全加固

- **API 认证**：所有 API 请求需携带 `SSO_TOKEN` / `API_TOKEN` / `DATAV_TOKEN`
- **CSRF 保护**：前端请求携带 CSRF Token
- **IP 策略**：配置 IP 黑白名单（`CheckIpMiddleware`）
- **会话超时**：支持相对超时 + 绝对超时双重控制
- **Supermario api-key**：SHA-256 哈希 + 常量时间比较，防时序攻击
- **容器安全**：所有服务统一 `cap_drop: [NET_RAW]`

## 升级与维护

### 升级流程

1. 通过 Web 界面上传升级包或在线获取
2. Upgrader（端口 8899/8797）解压并执行 `config.yaml` 中定义的步骤
3. 支持蜜罐镜像热更新（不重启平台）

### 数据备份

- 支持手动备份：系统设置 → 数据备份
- PostgreSQL 数据目录：`./data/`
- 备份保留在 `/data/d-sensor-backups/`

### Docker 清理

```bash
# 清理无用镜像
docker image prune -f

# 清理非 latest 的 honeypot 镜像
docker images | grep honeypot | grep -v latest | awk '{print $3}' | xargs docker rmi -f
```

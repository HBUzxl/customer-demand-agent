## 排查过程建议

1. 首先检查宿主机是否真的启动了executor程序（可以通过 ps aux | grep executor 查看），如果不存在该程序则重新执行下./installer 会自动安装executor

2. 查看logs/upgrader/executor.log查看执行过程（执行过程能够清楚的知道执行到哪一步失败）
![executor日志执行过程](images/upload_224c0831c8aba03257b95e4730d6c273.png)

3.如果发现是执行自己写的脚本失败，则可以解压后执行其中的run.sh自己本地复现下

排查思路顺序从上至下，最有可能是两个问题，一个是executor程序没执行，一个是自己写的升级包脚本有问题。

## 问题列表

### 上传升级包一直显示0%

一般是浏览器的问题，查看下是不是浏览器的版本低于90，如果是的话可以换下高于版本90的浏览器

### 为什么升级以后找不到executor程序

这种情况很有可能是从比较老的版本升级到最新版本，其中executor中使用了旧的配置文件(upgrader.yml，正常应该是executor.yml)，导致executor无法正常解析从而无法正常启动
![executor配置文件状态](images/upload_727a730c5ee58fdb732893e173d6b917.png)

操作步骤如下：

1.systemctl status upgrader_executor查看状态是否是异常

2.如果发现命令中使用了upgrader.yml而不是executor.yml，执行以下命令
```
systemctl disable upgrader_executor && rm -rf /etc/systemd/system/upgrader_executor.service
```
3.再次执行./installer，最后检查下systemctl status upgrader_executor状态是否正常

### 上传文件以后为什么没有在待应用列表中显示？

打开console查看接口 /api/meta/package/upload 的返回值，会有具体的错误信息显示出来

### 点击应用后升级包进度一直显示加载中

这种问题一般有两种可能，分别是

1.没有启动executor程序，通过 ps -aux | grep executor 查询是否启动了该程序，如果没有启动的话则让客户再次执行 ./installer 程序会自动启动 executor

2.本地网络策略导致executor无法连接上8787和8899的端口，这个可以通过executor.log日志来排查，后续直接让客户重新评估下该机器的网络策略即可

如果以上都做完了后，发现executor的日志已经正常无报错，则可以等待一段时间，此时executor会自动拉取之前已经提交的升级包进行安装

### 点击升级按钮后谛听管理节点的界面一直无法访问

由于可能存在迁移数据的问题服务还没正常启动，短时间内的无法访问是正常的，但是如果超过10分钟还是无法访问，可以找开发介入并且提供下logs/server/app.log

### 蜜罐升级加载镜像失败

空间问题，检查下机器的磁盘空间是否足够，联系下开发询问需要删除的内容

### 升级失败后怎么查看升级过程中哪一步出了问题

23.05.001中已经支持在界面上展示升级进度，如果是之前的版本则可以查看升级日志 logs/upgrader/executor.log

### 如何重置升级包状态（由已完成应用状态重置为未应用状态，方便再次执行）

* 如果是包括2023.03.001及之前的版本

    1. 查看升级包id，可以通过/api/meta/package/info中的wait字段查看，参考如下：
    ![升级包信息wait字段](images/upload_042583904bc75da7568c62e58db47f68.png)

    2. 进入谛听后台
    ```
    docker exec -it dsensor_server python manage.py shell_plus
    ```

    3. 更新升级包状态
    ```
    UpgraderPackageInfo.objects.filter(package_id="xxxxx").update(operation_id=0,upgrader_pkg_id=0,apply_time=None,process=0)
    ```

* 如果是包括2023.05.001及之后的版本
    1. 获取升级包id，同上
    2. 更新升级包状态
    ```
    docker exec -it dsensor_server python manage.py reset_package --id=xxxxx
    ```

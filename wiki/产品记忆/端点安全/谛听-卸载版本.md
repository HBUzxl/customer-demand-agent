# 卸载管理节点

如果需要彻底卸载管理节点 (软件版)，清除所有相关数据，可使用自动化脚本或按以下步骤手动操作。

## 快速卸载（自动化脚本）

### 方式一：使用自动化脚本（推荐）

```bash
# 上传卸载脚本到服务器
scp dsensor_uninstall.sh user@server:/home/user/

# SSH 登录服务器
ssh user@server

# 运行卸载脚本（保留 Docker）
# 脚本会自动申请 root 权限
chmod +x dsensor_uninstall.sh
./dsensor_uninstall.sh

# 如果需要同时卸载 Docker
./dsensor_uninstall.sh --remove-docker
```

> **提示**：默认保留 Docker，卸载后会自动恢复 Docker 配置（重建 systemd 单元文件、daemon.json 等），确保下次安装时 Docker 可正常使用。如需同时卸载 Docker，使用 `--remove-docker` 参数。

### 方式二：手动卸载

见下方详细步骤。

## 手动卸载步骤

1. 登陆管理节点，进入谛听部署目录

```bash
cd /data/d-sensor
```

2. 进入 docker-compose.yml 文件所在目录，停止所有服务

```bash
sudo docker-compose down
sudo ./minion/minion_linux stop
sudo ./minion/minion_linux remove
sudo ./docker_escape_detector/docker_escape_detector stop
sudo ./docker_escape_detector/docker_escape_detector remove
sudo ./upgrader/executor stop
sudo ./upgrader/executor remove
```

3. 删除所有 Docker 镜像、Docker 容器

```bash
sudo docker system prune -a -f
```

> **注意**：原手册中使用 `docker stop $(docker ps -a -q)` 命令，当没有容器时该命令参数为空会报错。建议直接使用 `docker system prune -a -f`。

4. 删除部署目录下所有系统数据、安装包、工具

```bash
sudo rm -rf /data/d-sensor
```

## 清理残留文件

卸载管理节点后，`/data` 目录下可能残留 generate_preset.sh 生成的文件，需要手动清理：

```bash
# 清理 generate_preset.sh 生成的残留文件
sudo rm -rf /data/default_presets
sudo rm -f /data/*.log
sudo rm -f /data/*.sh
sudo rm -f /data/*.json
```

> **注意**：如需保留部署脚本（dsensor_deploy.sh、dsensor_uninstall.sh、check_dsensor_env.sh），请在删除前备份或使用自动化卸载脚本（脚本会自动保留这些文件）。

## 可选：卸载 Docker

如果需要彻底清理，可以卸载 Docker：

```bash
# 停止 Docker 服务
sudo systemctl stop docker
sudo systemctl disable docker

# 删除 Docker 数据
sudo rm -rf /var/lib/docker
sudo rm -rf /var/lib/containerd
sudo rm -rf /etc/docker

# 删除 Docker systemd 单元文件
sudo rm -f /etc/systemd/system/docker.service
sudo rm -f /etc/systemd/system/docker.socket
sudo systemctl daemon-reload

# 卸载 Docker 包（Ubuntu）
sudo apt remove -y docker-ce docker-ce-cli containerd.io

# 卸载 Docker 包（CentOS）
sudo yum remove -y docker-ce docker-ce-cli containerd.io
```

> **注意**：如果保留 Docker 不卸载，卸载谛听后需要确保 Docker 配置完整（systemd 单元文件、daemon.json、数据目录等），否则下次安装时 Docker 可能无法正常启动。自动化卸载脚本会自动处理此问题。

## 验证卸载

### 1. 检查目录

```bash
# 应该不存在
ls /data/d-sensor

# 应该为空或只有空目录
ls /data/
```

### 2. 检查 Docker

```bash
# 应该为空
sudo docker images
sudo docker ps -a
```

### 3. 检查端口

```bash
# 应该没有输出
sudo netstat -tlnp | grep -E '80|443|1337|1338'
```

### 4. 检查磁盘空间

```bash
df -h /
# 可用空间应该恢复到安装前的状态
```

# 卸载探针

在管理界面上删除探针后，探针设备上的探针程序并不会被删除。如果需要重装探针，需要彻底卸载原有探针。操作如下：

1. 找到探针安装目录。如果已经忘了，可以执行以下命令搜索

```bash
ps aux | grep 'chaitin-bootstrap'
```

例如下图，则这台设备的探针安装在 /agent/ 目录下：

![查找探针安装目录](images/upload_446112fccaaffc859c7847929eb8cc9c.png)

2. 在探针安装目录下运行命令，移除探针系统服务

```bash
./chaitin-bootstrap stop
./chaitin-bootstrap remove
```

3. 删除文件夹下的所有探针相关文件。包含一个 .tls 文件夹，以及下图中的文件：

![探针相关文件](images/upload_c3be267676fc0cea827cdf9cdacdbcc3.png)

参考命令：

```bash
rm -rf .tls
rm -rf chaitin-bootstrap
rm -rf ......
```

当然，如果这个文件夹只用于安装探针，也可以直接删除整个文件夹，以安装在 /agent 下为例：

```bash
rm -rf /agent
```

删除完成后，即可正常安装新探针。

# 常见问题

### 问题1：docker stop 命令报错

**现象**：执行 `docker stop $(docker ps -a -q)` 报错

**原因**：没有容器时命令参数为空

**解决**：直接使用 `docker system prune -a -f`

### 问题2：残留文件未清理

**现象**：卸载后 /data 目录下仍有文件

**原因**：原卸载手册未包含清理 generate_preset.sh 生成的文件

**解决**：参见 [清理残留文件](#清理残留文件)

### 问题3：权限不足

**现象**：执行命令提示 "permission denied"

**原因**：需要 sudo 权限

**解决**：所有命令都需要加 `sudo`

### 问题4：卸载后 Docker 无法启动

**现象**：卸载谛听后，重新安装时 Docker 无法启动

**原因**：卸载过程中 Docker 的 systemd 单元文件（/etc/systemd/system/docker.service）或配置文件（/etc/docker/daemon.json）被删除

**解决**：重新创建 Docker 配置文件

```bash
# 创建 systemd 单元文件
sudo tee /etc/systemd/system/docker.service << 'EOF'
[Unit]
Description=Docker Application Container Engine
Documentation=https://docs.docker.com
After=network-online.target docker.socket firewalld.service containerd.service
Wants=network-online.target
Requires=docker.socket

[Service]
Type=notify
ExecStart=/usr/local/bin/dockerd
ExecReload=/bin/kill -s HUP $MAINPID
TimeoutStartSec=0
RestartSec=2
Restart=always
StartLimitBurst=3
StartLimitInterval=60s
LimitNOFILE=infinity
LimitNPROC=infinity
LimitCORE=infinity
TasksMax=infinity
Delegate=yes
KillMode=process
OOMScoreAdjust=-500

[Install]
WantedBy=multi-user.target
EOF

# 创建 daemon.json
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json << 'EOF'
{
  "live-restore": true,
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "200m"
  },
  "storage-driver": "overlay2"
}
EOF

# 重新加载并启动
sudo systemctl daemon-reload
sudo systemctl enable docker
sudo systemctl start docker
```

```bash
sudo docker-compose down && \
sudo ./minion/minion_linux stop && \
sudo ./minion/minion_linux remove && \
sudo ./docker_escape_detector/docker_escape_detector stop && \
sudo ./docker_escape_detector/docker_escape_detector remove && \
sudo ./upgrader/executor stop && \

echo "卸载完成！"
```

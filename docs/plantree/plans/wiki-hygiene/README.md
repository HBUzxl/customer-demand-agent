# Wiki 卫生与客户记忆治理

> 知识库健康问题与客户记忆的写入质量缺陷。状态：**Ready**（2026-08-15
> 从真实使用会话 sess_cfdc2e91beb0 挖出；三类问题+一个产品缺陷）。

## 背景

一期收尾后首个真实使用会话（用户让 Agent 自测工具、问审核机制）暴露：
Agent 自测残留未清理、冒烟测试污染客户库、一条类型错误的威胁条目被批成
verified、同一测试客户被重复创建 7 个条目。

## 问题清单（2026-08-15 盘点）

### ① Agent 自测残留（4 条，活跃 2 条）

| 条目 | 状态 | 问题 |
|---|---|---|
| 用户记忆/客户/工具功能自测洞察 | **verified 活跃** | 自测数据在检索索引里 |
| 用户记忆/客户/工具自测-观察注记 | **verified 活跃** | 同上 |
| 用户记忆/客户/工具测试-临时条目 | archived | 测了删除（只归档未物理删） |
| 用户记忆/客户/工具自测-临时客户 | archived | 同上 |

根因：Agent 测 delete 只删了自己起名「临时条目」的；memory_observe 写的
两条洞察忘了删。且 observe 写 customer 类型不触发 needs_review（ADR 语义
如此——customer 不审核），直接 verified 进活跃库。

### ② 冒烟测试污染客户库（11 条活跃 + 14 归档残留文件）

同一测试场景被写成 **7+ 个不同 title**：冒烟测试电商 / 冒烟测试电商-大促CC…
/ 冒烟测试电商：… / 冒烟F0客户-…；另有 医院客户：挂号… / 官网挂马需过等保
三级客户 / 客户网站扫描攻击+数据爬取诉求 等真实冒烟残留。另 某跨境电商平台
（content 是标题复读，信息量为零）。历史 .superseded-*.md 14 个。

### ③ 类型错误条目（1 条）

威胁库「连锁超市 POS 恶意软件（刷卡数据窃取）」：type=threat 但正文只有
一段客户观察（连锁超市、POS 被植入、需确认 PCI DSS）——这是**客户线索**，
威胁知识本体「POS恶意软件」已存在。用户批量审核时批成 verified，无人发现
类型错。暴露：**审核 UI 不显示条目类型与现有库的重合提示**。

### ④ 产品缺陷：同一客户重复创建条目（无合并/复用机制）

「冒烟测试电商」7 个变体的根因：Agent 每轮 memory_ensure 时自拟 title，
系统没有任何「同客户已有条目→复用/合并」的引导。真实使用中一个客户聊
三轮就会产生 3 个条目，客户画像越读越散。

## 方案

### F1. 数据清理（一次性，人工过目清单后执行）

- 物理删除 4 条自测残留（含 2 条 archived）+ 11 条冒烟污染 + 清 14 个
  .superseded 残留文件。
- 「连锁超市 POS…」从威胁库移到客户库（内容是客户线索）或直接删除
  （线索价值低——真实客户另有条目）。
- 执行方式：直接删 wiki 文件 + 重启服务重载（或走 DELETE API + archive=false）。

### F2. 客户记忆复用机制（产品缺陷修复，④）

- memory_ensure 前置检索：Agent 调 ensure(customer) 时，若同客户名已有
  活跃条目，result 里返回 existing 提示 + 现有条目 title（prompt 已有
  「先查后写」指引，补上工具层的硬提示）。
- systemPrompt 客户画像注入段（L2）强化：已有客户条目时提示「续写该条目
  而非新建」。
- 不做自动合并（语义合并需人审，走 F4 观察注记→固化管线的既有通道）。

### F3. 审核 UI 增强（防类型错误漏审，③）

- /review 列表与 F4 ReviewCard 显示条目 type 徽章。
- 待审条目与现有库同关键词命中 ≥2 时显示「疑似与 X/Y 重叠」提示
  （确定性检查，复用 RunLint 的 overlap 逻辑）。

### F4. 自测行为约束（防 ① 复发）

- systemPrompt 增加一行：测试性写入（自测工具/演示数据）必须用前缀
  「工具测试-」命名且测试完必须 delete（archive=false 物理删）。
- 或者更简单：memory_observe/ensure 的 result 对 title 含「测试/自测/
  临时」的给 warning 提示（软约束，靠 prompt 即可）。

## 非目标

- 不做客户条目自动合并/去重的后台任务（先靠 F2 前置检索+prompt 约束）。
- 不做审核流程改造（F3 只是信息增强，审批动作不变）。

## 验证

- F1：清理后 memory_list customer 应只剩真实客户条目；检索「冒烟/测试/
  工具自测」零命中（活跃索引）。
- F2：集成测试——同一客户名两次 ensure 不同 title，第二次 result 含
  existing 提示；prompt 注入含「续写而非新建」。
- F3：/review 页 type 徽章渲染；构造重叠条目时提示出现。
- F4：prompt 文本断言（测试性写入约束在 systemPrompt 里）。

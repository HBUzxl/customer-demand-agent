# 自主 Agent 设计

> 顶层是自主 Agent，不是 workflow。LLM 自主决定下一步，所有能力通过工具调用。

## 核心区别

| | Workflow（不采用） | 自主 Agent（采用） |
|---|---|---|
| 顶层结构 | 固定步骤序列：需求理解→产品匹配→可行性→追问 | 循环：LLM 自主决策下一步 |
| 决策者 | 框架硬编码顺序 | LLM 根据输入自主判断 |
| 灵活性 | 所有客户走同一路径 | 不同客户走不同路径 |
| 业务功能 | 代码里的 pipeline | system prompt 里的目标 + 工具 |

## 为什么不用 workflow

客户需求分析**没有固定顺序**：

- 客户说得清楚 → Agent 可能直接查产品 → 给结论，跳过"追问"
- 客户说得模糊 → Agent 先追问，再查产品
- 老客户 → Agent 先查客户画像，再针对性地查产品
- 全新威胁 → Agent 查行业记忆 → 发现没记录 → 记录新洞察

固定 workflow 会把 LLM 锁死成"无论什么输入都走同一套步骤"，丢掉自主判断力。

## 自主循环

```
用户输入 → 加入 messages
    │
    ▼
调用 LLM（system prompt + 工具定义 + messages）
    │
    ├── 返回 tool_calls？
    │     │
    │     ├── 是 → 逐个执行工具 → 结果回填 messages → 回到"调用 LLM"
    │     │
    │     └── 否 → 最终答案，结束
    │
    └── 出错 → 重试 / 回退（模型管理管）
```

**框架不预设"先查产品再匹配"的顺序**。Agent 自己决定：
- 要不要查产品？→ `memory_search(type=product)`
- 要不要查客户？→ `memory_search(type=customer)`
- 要不要记录画像？→ `memory_ensure(type=customer)`
- 直接给结论？→ 输出分析结果

## Workflow 的定位：包装成工具

不是"不要 workflow"，而是"不处处都是 workflow"。

**什么时候需要 workflow**：确定性的多步流程，每步必须执行、顺序固定。例如"生成方案建议书"——收集分析结果 → 套模板 → 填产品参数 → 输出文档。

**怎么处理**：包装成一个工具 `generate_proposal(...)`，对 AI 来说就是一次工具调用。工具内部可以跑固定流程，但 AI 看不到、也不需要关心内部步骤。

```
AI 视角：                   工具内部（workflow）：
"生成方案建议书"      →      generate_proposal
  （一次调用）                 ├── 步骤1：读分析结果
                              ├── 步骤2：套方案模板
                              ├── 步骤3：填产品参数
                              └── 步骤4：输出文档
```

## System Prompt 的职责

自主 Agent 的"自主"来自 system prompt 里的目标 + 约束，不是代码：

```
你是长亭科技的客户需求分析助手。

你的目标：
- 理解客户的业务语言，翻译成具体安全需求
- 匹配长亭产品，标注置信度
- 判断可行性（直接覆盖/定制/外部/不建议接）
- 标出客户没说清、需要追问的信息

约束：
- 必须给出可行性判断（每个分析都要有）
- 只推荐已知产品，禁止编造
- 不确定时标注"需进一步确认"
- 发现新客户/新威胁 → 调用工具记录

可用工具：
- memory_search / memory_recall / memory_ensure / ...
```

目标告诉你"要做什么"，约束告诉你"必须怎样"，工具给你"用什么做"。至于"先做哪个、做不做"，是 LLM 的自由。

## 与"上层功能"的关系

之前把"需求理解/产品匹配/可行性/追问"当成 workflow 步骤，是错的。它们是 Agent 的**目标**（写在 system prompt），不是**步骤**（代码 pipeline）。

真正的"上层功能"不是四个步骤，而是：**一个自主 Agent + 一套工具 + 一个目标**。

# memory-v2 决策记录

## ADR-016：System Prompt 分层——内容不注入，索引与会话状态注入（v2）

**状态**：已裁决（用户 2026-08-14 首裁 + 同日修订 v2）

**v1 → v2 演变**：v1「绝对不注入任何知识」系用户口误后自行修正——
用户画像必须注入（分级输出需要知道用户水平），产品/行业类知识"理论上
也该注入"交由分析定夺。v2 定稿分层模型。

**分层**：

| 层 | 内容 | 注入 | 理由 |
|---|---|---|---|
| L0 静态模板 | Agent 身份/自主性指引/目标/约束 | ✅ 永不变 | 预设是什么就是什么 |
| L1 使用者画像 | 名字+等级+styleForLevel 输出风格（~50 token） | ✅ | 行为配置非知识；每轮都影响输出风格；config.default_user 选定 |
| L2 会话状态 | 【最近分析结果】【对话状态】【已答追问】+ 客户身份一行（会话已关联时） | ✅ | checkpoint 链是 ADR-003 短期记忆本体，非知识库；客户"身份"是会话事实 |
| L3a 产品目录索引 | 产品名+一句话定位+别名（紧凑，~200 token） | ✅ 索引 | 模型必须知道有什么产品才能形成检索假设、执行"只推荐存在产品"约束（Karpathy index.md 思想） |
| L3b 其余知识 | 产品细节（能力/场景/竞品）、威胁、合规、行业、**客户画像本体** | ❌ 全走工具 | 内容会膨胀；威胁/合规/行业按症状可检索且 AI 可写（pending 风险）；客户画像会变大变过时 |

**客户身份获取**（配合 L2 的一行事实）：

- 前端会话头加客户名输入框（销售手填最准，经 /api/message customer
  字段 → EnsureSession 持久化；现状字段存在但无 UI，恒为空）
- F3 ask_user 落地后兜底：Agent 分析时发现会话未关联客户可主动问
- 画像细节一律 memory_search type=customer 按名取

**废除**（v1 时的现状改造）：

- AllKnowledge 全量注入（renderKnowledge 段 → 改为仅产品目录索引）
- 客户画像内容注入（上午 SetCustomerResolver 方案 → 改为身份一行 +
  工具取画像；SetCustomerResolver 链路保留用于取身份）

**保留不变的 P8 结论**：无内容注入后 pending 污染面消解；产品目录索引
来源 AllProducts 只含 product 类型（AI 只读，无 pending）。

**代价与对策**：同 v1——每轮至少一次工具调用的延迟；对策为 prompt
强化"推荐/断言前必须检索证实，未检索就推荐视为违规"，回放表格让
工具轨迹违规可见。

**影响面**：assembler（renderKnowledge → 紧凑目录；客户画像段 → 身份
一行）、会话头客户名 UI、prompt 措辞、集成测试更新、AGENTS.md。

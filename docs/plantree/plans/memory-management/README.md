# 记忆管理增强

> 记忆库 UI 的计数正确性、详情可见性与批量管理能力。状态：**Done**（2026-08-15 二期 goal 落地）
> （2026-08-15 用户实际使用反馈；三个问题已核实根因）。

## 用户反馈（2026-08-15 原话）

> 「每个都说自己有一篇文章是吧，但是其实它里头啥也没有。万象说有一篇
> 文章，这一篇文章是哪来的？这个技术是怎么做的？这个数量是怎么计算的？
> 感觉有点不对劲儿啊。」
>
> 「所有跟管理相关的东西……记忆呀，都应该是有多选的，就是删除、添加，
> 怎么怎么样，都是应该可以有多选的选项。但是现在你所有东西都没有多选。
> 每一个记忆都需要有一个多选。」

## 现状核实（2026-08-15，代码证据）

### ① 产品计数误导

`MemoryList.tsx:44`：`docCount = 子文档数 + 1`——**「+1」把主文档自己
算进去**。万象没有任何子文档时显示「1 篇」，用户以为底下挂着 1 篇别的
文档，点进去主产品页只有文档卡片网格（`MemoryDetail.tsx:203` 主产品
**不渲染正文**，`!isMainProduct` 才显示）——「说有一篇但其实啥也没有」
的感受来源。雷池 3 篇=主文档+FAQ+部署指南，数字恰好合理掩盖了口径问题。

### ② 主产品详情无正文

主产品页 = 产品画像字段（能力/场景/边界）+ 子文档卡片，**主文档自身的
markdown 正文（如万象.md 的介绍文字）不显示**。文档详情页才有正文。

### ③ 记忆条目无多选批量操作

MemoryList 六个类型 tab 全部单行删除（无复选框）。wiki-hygiene plan 里
盘点出的 13 条污染条目目前只能逐条删。

## 方案

### F1. 产品计数修正

- 口径改为「子文档 N 篇」：无子文档显示主产品自己的摘要或干脆不显示
  篇数（推荐：`N 篇文档` 仅当 N>0；主文档不计入——它就是产品本身）。
- 雷池显示「2 篇文档」；万象/云图/洞鉴/牧云/谛听不显示篇数徽章。

### F2. 主产品页显示正文

- 主产品页在画像字段下方增加主文档正文渲染（与文档详情同 MarkdownView
  路径）；子文档卡片列表保持在后。

### F3. 记忆条目多选 + 批量操作（六类型通用）

- 列表行加复选框（所有类型 tab：产品子文档/威胁/合规/行业/客户/使用者；
  产品 tab 主产品行不带框——产品级联删除风险高，只允许子文档多选）。
- 表头全选/全不选；选中浮出批量条「已选 N ｜ 批量删除 ｜ 取消」。
- 批量删除走应用内 ConfirmDialog（session-management F1 的共享组件，
  危险色+不可恢复提示；产品子文档删除提示将影响关联主产品）。
- 批量删除 = `Promise.allSettled` 循环单删 + 成败汇总（成功 X/失败 Y+
  首错）——与 session-management 的会话批量删除同一套交互模式。
- 审核状态筛选联动：批量操作对 pending/verified/archived 均可用
  （archived 行在列表中弱化显示）。
- **新建也走多选形态**：新建页支持批量粘贴多篇（YAML frontmatter 分隔）
  ——低频，可后置二期。

## 非目标

- 不做批量修改状态（approved/pending 批量翻转——审核走 review-gating
  plan 的门禁流程，不在这里混做）。
- 不做跨类型混合多选（tab 内多选即可）。
- 主产品级联删除（删雷池连子文档）不做——保持单文档粒度。

## 验证

- F1：万象无子文档 → 无篇数徽章；雷池 → 「2 篇文档」。
- F2：万象主产品页显示「万象是长亭安全运营中心平台…」正文。
- F3：tsc/lint/build 绿；手动冒烟——威胁 tab 全选 → 批量删除 →
  确认弹窗 → 列表清空+检索 miss；构造 1 条失败（断网）→ 汇总提示。

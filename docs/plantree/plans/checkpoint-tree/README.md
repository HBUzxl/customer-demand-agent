# Checkpoint 语义重构：对话版本树

> checkpoint 从「分析快照链」重构为「与 Agent 对话的版本树（git 式分支）」。
> 状态：**Done**（2026-08-15 二期 goal 落地）（2026-08-15 用户裁决方向；含概念统一/分支模型/UI 三层）。

## 用户裁决（2026-08-15 原话）

> 「现在已经没有什么"纯聊天"之类的说法了，只有一种活动，就是与 Agent 的
> 对话。我们现在所有的行为，都叫作与 Agent 的沟通……只要是与 Agent 的
> 对话，就需要有 checkpoint。」

（概念统一：不再区分 寒暄/纯聊天/追问/分析 轮——每轮对话都有 checkpoint，
每轮都是对话历史的一环。旧设计里「纯聊天建轻量 followup」的说法废弃，
followup 不再是「轻量/次要」的，它就是对话轮本身。）

> 「这个 checkpoint 你好好确定一下它到底是个什么东西。」

（checkpoint 的本质 = **对话版本的 git**：每轮提交一个快照，链是主线，
编辑重发/回溯再问产生分支。）

> 「有时候我可能编辑重放，那这里其实有点像 git 的概念，它是一个树状结构。
> 比如我 1、2、3、4、5、6，到第六轮时，我觉得第二轮不好，就从第二轮
> 重新问。这个时候，它相当于建立了一个新的分支，我能够回到这个分支上。
> 所以，你得在一个对话里找个地方，去存放这个分支相关的东西……让用户
> 能够随时地回去。」

## 现状 vs 目标

| 维度 | 现状 | 目标 |
|---|---|---|
| 概念 | initial/followup/reanalysis 三类，followup 被视为「轻量纯聊天」 | 统一「对话轮」概念：每轮一个 checkpoint，类型仅作内容标注（含分析/仅对话） |
| 结构 | 线性链（PrevID 串成单链，编辑重发=截断后重建，旧分支丢失） | **树**：根=首轮，每次编辑重发/回溯产生子节点，多分支并存 |
| 回溯 | F1 编辑重发=截断重写（TruncateAfter 物理删） | 分支保留：从第 2 轮重问=第 2 轮节点下长新分支，1-6 主线仍在，可切换 |
| UI | Replay 线性时间线（checkpoint 作为行插入） | 对话页内**版本树视图**：分支可视化（时间线+分叉标记），点击任意节点「回到这里继续问」 |

## 方案

### F1. 数据模型：链 → 树

- Checkpoint 增 `ParentID`（已有 PrevID 语义改造）+ `BranchID`（分支标识，
  主线=main，重问产生的分支用序号 b2-1/b2-2…按分叉点命名）。
- 编辑重发不再 TruncateAfter 物理删：旧轮保留，新轮挂到分叉点的
  ParentID 下，成为兄弟分支。
- messages 表增 `branch_id` 列（消息归属分支）；回放按分支过滤。
- 迁移：现有线性链 → 主线 main（无数据丢失）。

### F2. 概念统一：每轮必有 checkpoint

- 术语：checkpoint = 对话轮快照（不再有「纯聊天轻量」的说法）。
- checkpoint 内容标注保留：本轮含 analysis_submit（initial/reanalysis
  语义收窄为分支上的标注）/ 本轮仅对话（followup）。
- 前端 Replay/时间线文案统一「对话轮」；「追问」字样仅在确有 missing_info
  问答时显示。
- P3 软上限按分支计算（每分支 50，不再全局挤兑）。

### F3. UI：对话内版本树 + 一键回到

- Conversation 页侧边/顶部「版本」入口（badge 显示分支数>1 时出现）。
- 版本树视图：纵向时间线 + 分叉缩进（git graph 式简化——主线一条竖线，
  分支右侧展开，每节点=一轮，hover 显示该轮首句）。
- 任意节点「从这里继续」：加载该分支上下文为新当前分支（不删其它分支），
  对话区切到该分支的消息流。
- Replay 页同样按分支过滤展示 + 分支切换。

### F4. 与既有功能的关系

- F1 编辑重发（TruncateAfter）：改为「创建分支」而非截断（API 保留但
  语义变化——前端编辑重发自动走分支创建）。
- 断点续传（Restore）：按当前分支的链恢复。
- LastAnalysis 回溯：按当前分支内回溯。

## 设计决策（2026-08-15 实现时明确）

- **消息维度分支**：branch 作用于 messages（用户可见的对话路径）；checkpoint 链保持会话级主线（短期记忆跟随最新对话状态，不按分支分叉）——分支切换后 Agent 记忆是全会话的，与「与 Agent 的对话」统一概念一致。
- **分叉=复制共享前缀**：BranchAfter 复制 seq<after 的消息副本到新分支（b{seq}-{ts}），main 原路径完整不动；续写走 POST /api/message 带 branch 参数（AppendMessageBranch）。
- 版本树完整可视化（git graph 式）与「任意 checkpoint 节点回到」为后续迭代（分支数据模型+过滤视图+Conversation/Replay 切换已落地）。

## 非目标

- 不做分支合并（对话场景无合并语义；想要另一分支的结论就切过去问）。
- 不做分支改名/备注（先用分叉点+轮次自动命名）。
- 不做跨会话分支。

## 验证

- F1：迁移测试——老库线性链 → main 分支完整保留；新写分支数据
  ParentID/BranchID 正确；TruncateAfter 兼容路径不删旧分支。
- F2：术语扫描（前端文案无「纯聊天/轻量」残留）；每轮 checkpoint 创建
  的集成测试不变（已覆盖）。
- F3：前端 tsc/lint/build；手动冒烟：三轮对话 → 第二轮编辑重发 →
  版本树出现两分支 → 各自继续对话互不干扰 → 切回主线。

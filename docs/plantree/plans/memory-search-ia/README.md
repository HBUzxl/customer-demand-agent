# 记忆库搜索与信息架构修复

> 记忆库搜索语义（全量/卡片分类）与产品页「入口 vs 文章」的区分。
> 状态：**Done**（2026-08-15 二期 goal 落地）（2026-08-15 用户提出；数据层已核实为全量搜索，
> 问题在 UI 展示形态与卡片概念混淆）。

## 用户反馈（2026-08-15 原话）

> 「搜索它只搜索当前页面的东西，还是全量搜索？比如我在产品这里只有
> 6 个产品卡片，我还没点进去，在这个页面里搜索，它到底是只在这 6 个
> 卡片（比如万象这种高层面的档）里去搜，还是它们下面的东西也会搜？」
>
> 「搜索东西到底是什么东西？它应该搜索的是文章才对呀。你可能没有对
> 这个卡片做分类，或者没有做一些设置。有些卡片点击之后，它其实是
> 文章，有些它其实是入口。」

## 现状核实（2026-08-15，实测证据）

**数据层没问题——是全量搜索**：

- `SearchEntry` 走全库倒排索引：title(权重3)/aliases(2.5)/tags(2)/
  keywords(2)/related_products+scenarios(1.5)/summary(0.5)，CJK bigram。
- 实测：产品 tab 搜「FAQ」→ 命中子文档「雷池-FAQ」（主卡片之外）；
  搜正文词「内存抓取」→ 命中 POS恶意软件（正文级搜索）。

**UI 层两个真问题**：

1. **搜索范围不透明**：用户不知道搜的是「6 张卡片的名字」还是
   「底下所有文章」。搜索后产品 tab 从卡片网格切换成平铺列表
   （MemoryList.tsx:48 `flat = searching ? items : ...`），主文档和子文档
   混在一起、无类型标注——形态突变+无解释，用户无法判断搜了什么。

2. **卡片「入口 vs 文章」无区分**：产品主卡片是**入口**（点进去看画像
   +子文档列表），其他五个 tab 的条目和产品的子文档是**文章**（点进去
   看正文）。但 UI 长得一模一样，没有任何分类标识——用户点产品卡片
   期待看文章，看到的却是另一层目录，产生「这卡片是啥」的困惑。

## 方案

### F1. 搜索语义显性化

- 搜索框 placeholder 明确：「搜索全部内容（含产品子文档正文）」。
- 搜索结果页头部显示：「全库搜索「XX」· N 条结果（含子文档）」+
  当前 tab 过滤器（全部/产品/威胁/…）——默认当前 tab，可切全部。
- 搜索结果行显示命中类型徽章：产品入口 / 产品文档 / 威胁 / 合规 /
  行业 / 客户 / 使用者——一眼看清搜到的是什么。
- 命中字段提示（可选增强）：title 命中/标签命中/正文命中小标记。

### F2. 卡片分类：入口 vs 文章

- **产品主卡片 = 入口**：卡片视觉与文章行区分（入口卡片带目录图标 /
  右侧箭头 / 显示「N 篇文档」计数——与 memory-management F1 计数修正
  联动）；hover 提示「进入产品知识」。
- **文章条目（文档/威胁/合规/行业/客户/使用者）= 文章行**：行首文档
  图标；点击直达正文详情。
- 产品页内：主文档正文区（memory-management F2）+ 子文档卡片列表下方，
  子文档卡明确「文章」形态（点击看正文，不再像入口）。
- 图标语义表：入口（箭头/文件夹）/ 文章（文档线框）——全库统一。

### F3. 搜索结果直达分类页

- 点搜索结果的子文档 → 文档详情页（现状已通）。
- 点搜索结果的产品主条目 → 产品入口页。
- 无结果时：「无匹配——检查关键词或新建该条目」（+新建按钮预填
  title=query）。

## 非目标

- 不做跨类型聚合排序（按 tab 过滤即可）。
- 不做语义/向量搜索（ADR-002 确定性检索不动）。

## 验证

- F1：搜索后头部文案+类型徽章渲染；跨 tab 过滤切换正确。
- F2：产品卡片与文章行视觉可区分；图标语义一致。
- F3：无结果 CTA 可用（预填 title 的新建）。
- 数据层回归：FAQ/正文词搜索用例不变（已核实全量）。

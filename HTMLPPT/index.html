PART 01

理念与规划

为什么做 · 核心判断 · 架构决策 · 规划方法

第一大部分，讲清楚这个项目的出发点。核心是一句话：这是自主 Agent，不是固定流程的工具。

what

一句话定位

销售拿到客户的一段话（"网站老被扫""要过等保二级"），交给这个 Agent——它自己判断该查什么、怎么匹配产品、能不能接、还缺什么信息。

输入

客户的原始沟通文本

可能是微信里的一段话、邮件、会议纪要。不要求结构化，Agent 自己理解。

输出

结构化的需求分析

需求理解（业务语言→安全需求）· 匹配产品（+置信度）· 可行性判断 · 待追问信息。

区别于传统工具：不是「固定四步模板」——发一句"你好"它就正常聊天，发真实需求它才调分析工具。判断权在 Agent，不在流程。
强调"自主"这个词。传统做法是固定 workflow：需求理解→产品匹配→可行性，四步走死。我们推翻了这个。

core idea

自主 Agent，不是 workflow

❌ 固定 workflow 的问题

把 LLM 锁死成固定步骤，客户描述不同，分析路径本应不同，却被强制走同一模板。

发一句"你好"也给你吐出四步分析模板——用户原话："我发你好，应该正常聊天才对啊"。

✅ 自主循环的样子

调 LLM→ 有 tool_calls?→ 执行工具→ 回填结果↻ 再调
所有能力都是工具调用。LLM 自己挑用什么、什么时候用。强制约束（如"必须给可行性判断"）写在 system prompt，不靠流程。
这是整个项目最重要的一条决策（ADR-009）。后面所有功能都建立在这个判断上：业务能力工具化，而不是固定输出格式。

decisions 2/2

ADR-013 ~ 016：自主化重构

ADR-013

业务能力工具化

分析结果是 analysis_submit 工具，不是固定输出格式。Agent 自主判断意图，schema 即契约。否掉「纯 prompt 自主」「意图分类前置」。

ADR-014

统一对话入口

/api/analyze + /api/chat 合并为 POST /api/message，旧入口薄 shim。不做老数据兼容（用户裁决）。

ADR-015

前台/后台域划分

前台（与 Agent 对话）记忆成套全程在线——聊天轮次也要查证/记录；后台（独立任务）无记忆依赖，一次性 LLM 调用。

ADR-016

System Prompt 分层 v2

L0 静态模板 / L1 使用者画像 / L2 会话状态 / L3a 产品目录索引 注入；L3b 其余知识全走工具检索（全量注入已废）。

意义：这四条把「自主 Agent」从口号变成机制——工具化、单入口、域划分、分层注入，共同构成 Agent 的行为契约。
ADR-013~016 是二期（agent 自主化重构）落地的四条，比 001~012 更贴近运行时行为。013 工具化、014 单入口、015 前后台划分、016 prompt 分层。

memory

三层记忆系统

长期记忆

Wiki（文件型）

确定性关键词检索：CJK bigram 分词 + 加权倒排索引（标题权重 3、别名 2.5、标签 2、正文摘要 0.5）。

产品 / 行业 / 用户三层分类，AI 可写但分权限。

短期记忆

Checkpoint 链

结构化状态快照：initial / followup / reanalysis 三种。每轮对话一个 checkpoint。

保留「最近有效分析」回溯——纯聊天轮不会挤掉分析上下文。

历史记录

SQLite 完整轨迹

每条消息、每次工具调用、每个 checkpoint 全持久化。可回放审计。

与短期记忆区分：checkpoint 是工作记忆（内存），history 是持久记录（磁盘）。

三层各司其职：Wiki 是"懂的知识"，checkpoint 是"当前在想什么"，SQLite 是"聊过什么"。Agent 查证走 Wiki，回溯走 checkpoint，翻旧账走 history。

PART 02

已实现功能

现在能干什么 —— 每项功能的意义

第二大部分，10 类已实现功能。每项都讲「是什么 + 为什么有意义」。

feature 01

自主 Agent 循环

核心：analysis_submit 业务工具

寒暄 → 自然语言回复（"你好"就正常聊）

产品概念 → memory_search 查证 + 聊

真实需求 → 调 analysis_submit 提交结构化分析

追问 → 答，或判断需求变化后重分析（is_reanalysis=true）

analysis_submit schema
{
  "demand_analysis": "...",   // 需求理解
  "matched_products": [...],  // 匹配产品+置信度
  "feasibility": "direct",    // 可行性
  "is_reanalysis": false      // 是否重分析
}
意义：摆脱固定四步模板——「你好」不再吐出需求分析 JSON，判断「这是不是真实需求」的权在 Agent。
这是 ADR-009 的落地。分析不再是固定输出格式，而是一个工具——Agent 判断需要时才调。

feature 02

统一对话入口 + Run 任务模型

一个入口

POST /api/message
{ "text": "客户网站被扫...", "session_id": "..." }
// 返回 202 + run_id，立即响应

/api/analyze 和 /api/chat 是废弃 shim，统一走 /api/message。

Run 任务模型

202 立即返回，后台 Run 执行——前端不等结果

SSE 订阅流：id: 游标 + x-run: 归属，增量续传

断连运行继续 / cancel / 编辑重发 / 多轮隔离

意义：前端即时响应 + 流式体验；刷新页面不丢任务（断点续传），多轮对话各自隔离不串台。
F0 Run 任务模型经过了 12 轮审计打磨——事件归属、游标、断连、取消，都是踩过坑的。

feature 03

记忆系统：6 工具 + 权限矩阵

工具作用产品威胁/合规/行业客户使用者
memory_search关键词检索（跨类型）✅ 读✅ 读✅ 读✅ 读
memory_recall语义模糊召回✅✅✅✅
memory_list列出某类型✅✅✅✅
memory_ensure创建/更新条目❌ 人工✅ 待审核✅❌
memory_observe追加观察注记❌✅ 待审核✅❌
memory_delete删除条目❌❌✅❌
意义：Agent 能查证事实、记录线索、维护记忆——不是裸 LLM。权限矩阵保证「产品知识只人工维护」这条红线不被 AI 突破。
权限矩阵是 ADR-005 的核心：产品记忆是人工维护的确定性最高知识，AI 绝对不能写不能删。

feature 04

检索精度 + 事实时效

CJK bigram 分词

中文检索不再整句匹配

「网站经常被扫描攻击」切成「网站 / 站经 / 经常 / 常被…」滑动二元组，命中关键词而非连续子串。

加权倒排索引：标题 3 > 别名 2.5 > 标签 2 > 正文摘要 0.5，标题命中排前。

时效归档

事实会过期，旧版本留痕

每条记忆带 valid_at / invalid_at / superseded_by。

覆盖更新时，旧版本归档为 .superseded-*.md——「这客户上月要什么」可回溯，不静默丢。

意义：检索命中率是记忆系统的命根子——中文不分词会漏检，事实不归档会错用过期结论。
这两块是二期打磨的重点：分词解决了"搜不到"，时效解决了"搜到错的"。历史查询接口 /api/memory/{type}/{title}/history 能看版本链。

feature 05

审核门禁：写入即审批

写入门禁

Agent 写威胁/合规/行业→ pending_review→ 对 Agent 不可见

审批前：检索、列表、prompt 注入全部排除这条 pending 内容。

对话内审批

输入框上方 · sticky 弹条
Agent 请求写入 [行业]「金融AI合规」  [批准] [拒绝]

批准即对 Agent 生效，拒绝即删。/review 独立页面已删除——对话内是唯一入口。

意义：「我通过之后内容才进记忆库」——审核是门禁不是事后标记。AI 写知识，人拍板生效。
这块是用户明确要求的：之前 pending 内容「边等审核边被检索」，等于没审。改成门禁后，AI 写的东西人不批准就进不了库。

feature 06

客户绑定 Agent 自主化 + ask_user

session_bind_customer

客户身份 = Agent 自己问出来

对话涉及具体客户但没绑定时，Agent 先 memory_list 看已有客户 → ask_user「这是谁家客户？」（选项=已有+新客户）→ 你答 → 它调工具绑定会话。

手动「+关联客户」入口已删——绑定是 Agent 行为，不是用户填表。

ask_user + missing_answer

结构化提问 + 答案闭环

关键信息缺失且能枚举选项（部署环境/预算区间）→ ask_user 给按钮点选，比开放追问省事。

答案回来用 missing_answer 记录进 checkpoint，不重复问同一件事。

意义：客户身份、信息追问都在对话流内闭环——不跳页、不填表，Agent 自己问、自己绑。
这两个都是「对话流内闭环」的体现：客户绑定、信息追问，全在对话里完成，不跳到别的页面。

feature 07

后台任务域（TaskBackground）

taskbg 包

Runner 串行执行

单 worker 队列，任务列表 + panic 防护 + 5min 超时。前后台域划分：前台记忆成套，后台无记忆依赖一次性调用。

固化管线

observe → 抽结构 → 人审

Agent 零散观察注记 → LLM 抽成结构化要点 → 生成 pending 草案 → 人审落地。

Wiki Lint + 标题

确定性体检

Lint 五检查（孤儿/残缺/别名冲突/重叠/该建未建），不调 LLM 快且稳。会话标题首轮完成后自动 LLM 概括。

意义：观察沉淀成知识（固化）、知识体检（Lint）、会话命名（标题）——这些后台活不占前台记忆，各司其职。
ADR-015 划的界：前台（与 Agent 对话）记忆成套全程在线；后台（独立任务）无记忆依赖。固化就是把观察沉淀成知识，走人审。

feature 08

配置中心 + 观测台

配置中心三态化

前端即控制台

可配：全局超时 / Agent 迭代上限 / 回退链 / 使用者（热生效）。

隐藏：prompt 分层、工具提示词等内部项（用户不该看到）。

只读：数据位置（迁移需停服）。

观测台 /observe

运行不再黑盒

后台任务列表 · 日志 tail（SSE 直播）· LLM 调用审计（模型/回退/耗时/成败）· 健康检查。

prompt 模板外置 prompts/system.md，编辑重启生效 + 版本快照。

意义：后端配置与运行不再黑盒——能配的在前端配，能看的在前端看，改完热生效。
用户原话「后端是前端的控制台，不是黑盒」。配置中心从"只读展示"改成"三态"——该开放的开放、该藏的藏。

feature 09

会话管理

应用内确认弹窗

替换原生 confirm/alert——删除、归档、拒绝全部走自研 ConfirmDialog。

批量删除

复选框 + 全选 + Promise.allSettled 成败汇总，想「从头来」一键清空。

内容搜索

搜标题 + 消息正文（snippet 高亮）——找「聊过刷号防护的那个会话」。

编辑重发 = 开分支

从第 N 轮重问 = 新分支（main 完整保留），可切回任意分支继续。

意义：管理类界面全支持多选；删除有确认、有回退感；找历史会话能搜到内容。
会话管理是用户真实使用中提的需求：想批量删、想搜内容、想编辑重发开分支——都落地了。

工程规范

深模块纪律

别把单文件扩成大杂烩；按 memory/agent/channel/llm/model/history 领域边界组织。

错误处理

TransportError / APIError 分类；重试只在「可重试+幂等」；%w 包裹保留 cause chain。

安全基线

api_key 绝不进日志/回显；SSRF 三重防御；SQL 全参数化；rehype 先 raw 后 sanitize。

日志

stdlib log.Printf，[ok]/[warn] 前缀，请求日志含耗时。

配置约定

业务配置走 config.json（不用环境变量），api_key 绝不提交。

多租户

已废止（单租户），X-Tenant-ID 接受但忽略。

工程规范是 AGENTS.md 里沉淀的硬约束，新代码沿用。
